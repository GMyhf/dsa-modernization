# 第9章 文件管理和外排序

**数据放不进内存的时候，怎么排序。**

前八章所有算法都有一个隐含前提：**任意元素的访问代价相同**。
一旦数据在磁盘上，这个前提就没了。

- 9.1 内存与外存的代价差在哪
- 9.3 置换选择、二路外排序、多路归并

---

# 9.1 一次磁盘访问有多贵

| | 典型量级 |
| --- | --- |
| 主存访问 | 几十**纳秒** |
| 磁盘寻道 + 旋转 | 几**毫秒** |
| 差距 | **约 10 万倍** |

**所以外排序的代价不数比较次数，数「读写了多少次外存」。**

一个直接推论：**顺序读写远比随机读写划算**——
寻道一次之后连续读一大块，摊到每个字节上几乎免费。

<!-- 备注
这就是为什么外排序全靠**归并**而不是快排：归并只需要顺序读写，
快排的分割要来回跳。第 8 章说「归并需要 O(n) 额外空间所以不如快排流行」，
到了外存这个结论完全反过来。
-->

# 页 I/O 成本模型

设文件有 $N$ 条记录，一页装 $B$ 条：

- 顺序扫描一遍：$\lceil N/B\rceil$ 次读页
- 读一遍并写回：约 $2\lceil N/B\rceil$ 次页 I/O
- 一趟归并：完整读写文件一次，约 $2N/B$

例：3000 条记录、每页 100 条，一趟至少读 30 页、写 30 页。

**多一趟归并的代价是多读写整个文件**，
远比内存里多做几次比较昂贵。

---

# 9.2 记录怎样装进页

| 记录类型 | 页内组织 | 更新代价 |
| --- | --- | --- |
| 定长 | 直接按槽排列 | 位置容易计算 |
| 变长 | 页尾槽目录记偏移与长度 | 记录可移动，槽号不变 |

删除也有两种选择：

- 立即压紧：扫描紧凑，但要搬动后续记录
- 留墓碑：写入便宜，但查询要跳过空洞，最终仍需重组

索引保存“关键码 → 页号/槽号”，把逻辑顺序与物理位置分开。

# 外排序的基本套路

```text
第一阶段: 分段读进内存, 排好, 写回磁盘   ->  若干个「顺串」(run)
第二阶段: 把这些顺串归并成一个有序文件
```

两个阶段各有优化空间：

- 第一阶段：顺串**越长越好**（顺串少，归并的轮数就少）
- 第二阶段：一次归并**越多路越好**（路数多，轮数少）

---

# 9.3.1 置换选择：让顺串更长

朴素做法：内存能装 M 个，就每次读 M 个排好写出去，顺串长度恰好 M。

**置换选择能让顺串平均长到 2M。**

# 置换选择：怎么做到的

```text
内存里维持一个最小堆, 装满 M 个
反复:
    取出堆顶, 写进当前顺串
    读入下一个记录:
        它 >= 刚写出的那个吗?
            是 -> 放进堆, 还能进当前顺串
            否 -> 冻结它, 等下一个顺串再用
    堆空了 -> 当前顺串结束, 解冻全部冻结的记录
```

**关键在「冻结」**：比刚写出的值小的记录进不了当前顺串，
但它仍然占着内存，参与下一轮。

<!-- 备注
为什么平均是 2M：可以用「扫雪机模型」直观解释——
雪均匀落下，扫雪机绕圈扫，稳态下每圈扫掉的雪量是圈内存量的两倍。
输入随机时顺串平均长度就是 2M。
输入本来就近乎有序时，能长得更多，极端情况一个顺串装下全部。
-->

# 置换选择：原书序列逐步走

工作区 $M=7$，输入：`50 49 35 45 30 25 15 60 16 27 1`

| 步 | 输出 | 新输入 | 去向 | 冻结 |
| ---: | ---: | ---: | --- | --- |
| 1 | 15 | 60 | 活跃 | 空 |
| 2 | 25 | 16 | 冻结 | 16 |
| 3 | 30 | 27 | 冻结 | 16,27 |
| 4 | 35 | 1 | 冻结 | 16,27,1 |
| 5–8 | 45,49,50,60 | 耗尽 | 排空活跃堆 | 16,27,1 |

顺串 1：`15 25 30 35 45 49 50 60`，长度 8，已经超过 $M$；
顺串 2：`1 16 27`。

# 9.3.2 二路外排序

![图 9.3 二路归并过程](../assets/7486004c6161789b.jpg)

每轮把顺串两两归并，顺串数减半。m 个顺串要 $\lceil\log_2 m\rceil$ 轮。

**每一轮都要把整个文件读一遍写一遍**——
所以总的外存访问量是 $2N\lceil\log_2 m\rceil$。

**要减少轮数，就得提高归并路数。**

---

# 3000 条记录：二路归并要几趟

若初始顺串每条 200 条：$3000/200=15$ 条顺串。

```text
第 0 层: 15 条 × 200
第 1 趟:  8 条，长度约 400
第 2 趟:  4 条，长度约 800
第 3 趟:  2 条，长度约 1600
第 4 趟:  1 条，长度 3000
```

需要 $\lceil\log_2 15\rceil=4$ 趟。
每趟读写 3000 条，总传输约 $2\times3000\times4=24000$ 条记录。

若置换选择把平均顺串延长到 400，初始只有约 8 条，可省一趟。

---

# 9.3.3 多路归并：瓶颈在哪

k 路归并时，每输出一个记录都要在 k 个候选里挑最小的。

- 线性扫：$k-1$ 次比较
- 总代价：$N(k-1)$ 次比较

**路数 k 增大，轮数降了，但每步的比较次数升了**——两者对冲。

要真正受益，就得让「挑最小」变便宜：**选择树**。

赢者树和败者树是**经典教材中的选择树表示**，统称 **tournament tree（选择树）**，主要服务外部排序的多路归并；一般内存内取最小通常直接使用二叉堆或优先队列。

---

# 赢者树

![图9.4 含有5 个选手的赢者树](../assets/dffb7316183b2881.jpg)

- 叶子是 k 个候选（各归并段的当前记录）
- 每个内部结点记**两个孩子里的赢家**（较小者）
- 根就是全局最小

<!-- 备注
建树 O(k)。取走根之后，只有从那片叶子到根的这一条路径需要重算——
**O(log k)**，而不是 O(k)。
于是 k 路归并的总比较次数从 N(k-1) 降到 N log k。
-->

# 赢者树的重构

![图 9.6 图 9.5 重构后的 8 路归并赢者树](../assets/bb27070d9ac01f78.jpg)

```cpp file=code/ch09/external_sort/modern.hpp#fn:replace
void replace(std::size_t player, int value) {
    if (player >= players_.size()) {
        throw std::out_of_range("tournament player");
    }
    players_[player] = value;
    std::size_t node = leaf_base_ + player;
    tree_[node] = player;
    while (node > 1) {
        node /= 2;
        tree_[node] = detail::TournamentOps::better(players_, tree_[node * 2],
                                                    tree_[node * 2 + 1]);
    }
}

void replace(std::size_t player, int value) {
    if (player >= players_.size()) {
        throw std::out_of_range("tournament player");
    }
    players_[player] = value;
    subtree_winner_[leaf_base_ + player] = player;
    for (std::size_t node = (leaf_base_ + player) / 2; node > 0; node /= 2) {
        replay_node(node);
    }
    champion_ = subtree_winner_[1];
}
```

换掉一片叶子后，沿着它到根的路径逐层重赛。
每层要看**兄弟**是谁——所以赢者树重构时要访问兄弟结点。
下一页的败者树就是为了省掉这一步。

# 四路归并：赢家路径怎样更新

四路当前值为 `[4, 7, 2, 9]`：

```text
首轮: min(4,7)=4, min(2,9)=2, min(4,2)=2
输出: 第 2 路的 2
补入: 第 2 路变成 8，候选 [4,7,8,9]
重赛: 只重算“第 2 路叶子 → 根”的两场
结果: 新冠军为 4
```

建树 $O(k)$；每输出一条只更新一条高为 $\log k$ 的路径。

线性扫描要每次检查全部 $k$ 路，选择树只做 $O(\log k)$ 次比较。

# 败者树：省掉「看兄弟」

![图9.7 8路归并的败者树示例](../assets/93f3de38d2a0ccc4.jpg)

内部结点记的是**输家**，赢家继续往上比。

- 赢者树重构：每层要**读兄弟结点**才知道跟谁比
- 败者树重构：每层直接跟**本结点记录的输家**比

**少一次访存**。这在多路归并的内层循环里是实打实的收益。

<!-- 备注
两种树的信息量是等价的，只是把「谁输了」记在哪里不同。
败者树多一个「冠军」槽（下标 0）存全局赢家。

这是本章最容易讲糊的地方，建议对着图 9.7 和图 9.8 走一遍完整的重构过程。
实现见 code/ch09/external_sort/modern.hpp。
-->

# 代价小结

设文件 N 条记录、内存装 M 条、k 路归并：

| 环节 | 代价 |
| --- | --- |
| 生成顺串（置换选择） | 顺串平均长 $2M$，段数约 $N/2M$ |
| 归并轮数 | $\lceil\log_k(N/2M)\rceil$ |
| 每轮外存访问 | $2N$（读一遍写一遍） |
| 每步挑最小（选择树） | $O(\log k)$ |

**优化的两个方向**：置换选择减少**段数**，多路归并减少**轮数**。

# 课堂讲解卡：外排序先算 I/O

内存只放得下 M 条记录时，目标不是少比较，而是少读写磁盘页。初始顺串、归并路数和缓冲区大小共同决定总 I/O。

# 本章小结

- 外排序数的是**外存访问次数**，不是比较次数
- **顺序读写远比随机读写划算**——所以外排序全靠归并
- **置换选择**把顺串平均长度从 M 提到 2M，段数减半
- 多路归并降低轮数，但「挑最小」会变贵
- **选择树**把挑最小从 $O(k)$ 降到 $O(\log k)$
- **败者树**比赢者树少一次访存：重构时不必读兄弟
