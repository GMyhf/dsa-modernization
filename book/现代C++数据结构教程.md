## 如何使用本教程

每章正文位于本目录的独立 Markdown 文件。这样做有两个好处：阅读器能快速跳转，且每一段
C++ 都能与 `code/` 下通过测试的源码逐字同步。代码块中的 `file=` 标注就是其来源。

建议的学习顺序是第 1 至第 10 章；第 11 章给出索引技术导读；第 12 章收束内存复用与动态规划。
每章先理解抽象模型，再阅读实现，最后运行对应单元的测试。所有提取操作（例如 `pop`、
`dequeue`）都用 `std::optional` 表达正常的空状态；参数、容量或权重不合法则抛标准异常。

```bash
# 编译并运行全书的现代实现与测试
```

## 第11章 索引技术

第 11 章没有被原书列为独立 C++ 清单，因此本项目没有伪造一套“已验证实现”。这里给出干净的
概念教程，并把实现练习留给需要持久化存储的上层项目。

### 11.1 索引的目标

主文件保存完整记录；索引保存 `(key, location)` 映射。查询先查索引，再按位置读取记录。
索引的价值不在于消灭存储访问，而在于把“扫描全部记录”缩减为“读取少量索引页和目标记录页”。

线性索引把映射按 key 排序，适合二分检索。若主文件也按 key 排序，稀疏索引可以每个数据页只
存一个最小 key；若主文件无序或按多个属性查找，则需要稠密索引或辅助索引。

### 11.2 多级索引与 B/B+ 树

当一个索引页放不进内存时，再给索引建立索引，形成多级结构。磁盘访问代价远大于页内比较，
所以结点应尽可能接近一个磁盘页，使用较高分支数以降低树高。

B 树与 B+ 树都是动态平衡多路搜索树。插入时先落到叶结点，满页分裂并把分界 key 上推；删除时
先尝试向相邻兄弟借 key，不能借则合并并向上处理。B+ 树把真实记录放在叶层，叶结点按 key
链接，因此既适合点查询，也适合范围扫描。

### 11.3 倒排索引

倒排索引从属性值或词项反查记录集合：

```text
词项 / 属性值  ->  posting list（文档或记录标识及可选位置）
```

多条件查询转换为 posting list 的交、并、差。它很适合文本检索和多属性过滤，但插入、删除、
更新主记录时必须同步维护相关 posting list。主文件仍然必要，因为倒排表通常只保存标识和位置，
不保存完整记录。

### 11.4 位图、签名与红黑树

位图索引适用于低基数属性：每个属性值对应一个位串，布尔查询可由按位与、或、非快速完成；
高基数属性会造成空间膨胀，通常需要压缩。

签名文件将文档特征映射到位串，用较小的签名做候选过滤，再回到原文确认，因而可能有假阳性。
红黑树则是面向内存动态索引的折中方案：用颜色约束维持近似平衡，使查找、插入与删除都保持
O(log n)。它适合单机内存中的有序映射，不替代磁盘页导向的 B+ 树。

### 11.5 练习建议

1. 为一组变长记录实现稀疏二级线性索引，并测量一次查询的页访问数。
2. 为若干文档建立倒排表，完成 AND、OR 和短语查询。
3. 实现一个固定阶 B+ 树页模型，分别测试分裂、借位、合并和范围扫描。
4. 为低基数列实现压缩位图，比较内存占用与过滤速度。
