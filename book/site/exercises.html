#正文习题答案

  1. 读入 X,Y,Z 后三次比较即可定序：若 X<Y 交换，若 X<Z 交换，若 Y<Z 交换，此时 X≥Y≥Z，顺次输出。比较与交换都是常数次，时间 O(1)、空间 O(1)。注意「从大到小」允许相等，判断要用 < 而不是 <=，否则相等元素会白白交换。
  2. 数据结构 = 一组数据 + 它们之间的关系 + 允许的运算。例如「班级花名册」按学号排成一列，前后相邻，是线性表；「城市间的航线」两两之间可能有边，是图；「文件夹套文件夹」是树。同一批数据换一种关系去看，就是另一种数据结构，能做的运算和代价也随之变化（见 1.2.1）。
  3. 四种基本存储方式：顺序（元素连续存放，靠下标算地址，随机访问 O(1)，插删要移动）、链接（结点分散，靠指针相连，插删 O(1) 但不能随机访问，且每个结点多花指针空间）、索引（另建索引表指向记录，逻辑有序而物理无序，见 1.4 与第 11 章）、散列（由关键码直接算地址，平均 O(1)，需处理冲突，见第 10 章）。

#正文上机题参考

  1. 设 f(m,n) 是「把 m 拆成若干个不超过 n 的自然数之和」的方案数，按「用不用一个 n」分两类： $f(m,n)=f(m−n, n)+f(m, n−1).边界：f(0,n)=1（空拆法算一种）、m>0且n=0时为0、n>m时取f(m,m)。验证f(5,3)=5，与题面给的五种一致。直接递归会重复计算，改成O(mn)的二维递推即可；空间可滚动到O(m)$。

#第 2 章 线性表

#正文习题答案

  1. 有序顺序表插入 x：先二分找到第一个大于 x 的位置 k（O(log n)），再把 [k,n) 整体后移一格、写入 x（O(n)）。总代价仍是 O(n)——二分省的是比较，不是移动，这一点在顺序表上必须说清楚。实现见 code/ch02/array_list：insert 会先 ensure_capacity，扩容按翻倍，摊还 O(1)。
  2. 逐位比较 ai 与 bi，遇到第一个不等的位置就定胜负；若走到某一表的末尾仍全等，则短者小（A 是 B 的前缀时 A<B，长度相同则相等）。时间 O(min (m,n))、空间 O(1)。这正是字典序，与第 4 章字符串比较是同一套规则。
  3. 递增单链表删除所有满足 min <x< max  的结点：一次遍历，用「前驱指针 + 当前指针」把落在区间内的结点摘下并 delete；因为表是递增的，一旦当前值 ≥ max  就可以停。时间 O(n)、空间 O(1)。注意删除的是开区间，等于 min  或 max  的结点要留下。
  4. 两个递增单链表归并成一个递减表，且只用原结点：反复取两表当前较小者，用头插法接到结果表头。头插会把顺序反过来，于是取出来是递增、接上去就成了递减；一个新结点都不申请。时间 O(m+n)、额外空间 O(1)。
  5. 拆成三个循环链表：遍历原表，按 isalpha / isdigit / 其它把结点摘下来尾插到对应的表；每个表只保存尾指针 tail，尾插是 tail→next 与 tail 各改一次，O(1)。最后每个表都要闭合成环（末结点指回首结点），空表以 tail == nullptr 表示。时间 O(n)、不新建结点。循环链表的写法见 2.3.3。
  6. 顺序表删除从第 i 个起的 k 个元素：先查合法性（1≤i、i+k−1≤n、k≥0），越界抛 std::out_of_range；再把 [i+k−1,n) 的元素整体左移 k 位，最后长度减 k。移动次数 n−i−k+1，时间 O(n)。一次移动 k 位，而不是调用 k 次「删一个」——后者是 O(kn)。
  7. 递增单链表去重：相邻比较，cur->value == cur->next->value 就摘掉后一个并 delete，否则前进。因为有序，相等的一定相邻，一趟就够，O(n)。
  8. 两个递增无重复顺序表求交集：双指针，相等则写入 C 并同时前进，否则前进较小的一方。时间 O(m+n)、结果自然递增。若改用「对 A 的每个元素在 B 里二分」，代价是 O(m log n)——m 与 n 接近时不如双指针。
  9. 单链表版本同样是双指针，区别在于不能随机访问，所以只能顺着走一遍；这恰恰说明双指针法为什么在链表上仍然适用，而二分法不再适用。时间 O(m+n)。
  10. 括号配对：从左往右扫，遇到左括号入栈，遇到右括号就与栈顶比对——类型要匹配，栈空则说明右括号多了；扫完（遇到 #）时栈必须为空，否则左括号多了。时间 O(n)、空间 O(嵌套深度)。栈的实现见第 3 章，code/ch03/expression_eval 里有同一套思路的求值程序。

#正文上机题参考

  1. 单链表原地逆置的三指针写法：prev = nullptr、cur = head，每轮先记下 next = cur->next，再把 cur->next 指向 prev，然后三个指针一起前移；结束时 prev 就是新表头。 循环不变量：prev 指向已经逆置好的那一段的头，cur 指向尚未处理的那一段的头，两段合起来恰是原表的全部结点。 时间 O(n)、额外空间 O(1)（只有三个指针，与 n 无关）。 容易错的两处：忘了先保存 next 就改指针，链表当场断成两截；结束后忘了把原头结点的 next 置空，逆置完的表尾会指回去形成环。测试至少覆盖空表、单结点、两结点和一般情形——code/ch02/linked_list/test.cpp 里的边界用例可以照抄这个口径。
  2. 倒数第 m 个（题目约定 m=0 是尾结点）用双指针：fast 先走 m+1 步，若不足则 m 越界；随后 fast、slow 同步前进到 fast==nullptr，此时 slow 即答案。空表、m<0、m>=n 返回空值。一次扫描，时间 O(n)、额外空间 O(1)。
  3. Josephus 用带尾指针的循环单链表。先让 prev 指向开始报数者的前驱；每轮向前移动 m-1 次，删除 prev->next、记录其编号，再从删除位置的后继继续。n<=0 或 m<=0 拒绝；s 规范化为 ((s-1)%n+n)%n+1。模拟时间 O(nm)、结点空间 O(n)；若只要最后幸存者可用递推 J(1)=0, J(k)=(J(k-1)+m)%k。

#正文习题答案

  1. 用数组 data[n]、front（队头）和 count 表示双端队列，队尾下标为 (front+count-1)%n。队尾删除取该下标后 --count；队头插入先令 front=(front+n-1)%n，再写入并 ++count。四种操作都先判空/满，时间均为 O(1)。

[ref_DSA/homework/4字符串.md 第 3 题；ref_DSA/DSA-HW/Chapter4string.md 第 2 题；2025 秋书面作业] 级联删除所有 b 与 ac，单遍、原地、O(1) 额外空间（示例 "acbac"→""、"ababac"→"aa"）。 关键观察：已写入 S 左端的前缀本身就是一个栈，写指针 w 就是栈顶——不需要另开栈。读指针 r 从左到右： ``text w ← 0 for r ← 0 .. n-1: if S[r] == 'b': continue // b 从不写入 if S[r] == 'c' and w > 0 and S[w-1] == 'a': w ← w-1; continue // 与前一个 a 抵消 S[w] ← S[r]; w ← w+1 return w ` 为什么级联被自动处理了：b 从来没写进前缀，所以它两边的 a…c 在前缀里天然相邻；删掉一对 ac 后，$w$ 回退，前缀的新末尾若是 a，下一个 c 照样能与它抵消（如 "aacc"→""）。最终保留的前缀里不含 b，也不含相邻的 ac（写入 c` 时已检查过前一个字符），而每一步删除都是题目允许的删除，所以结果就是级联删除的不动点。r 走一遍、每步 O(1)，时间 O(n)、额外空间 O(1)。 本附录原先给的「读写栈、空间 O(n)」输出是对的（与暴力反复删除在 {a,b,c} 上长度 ≤ 9 的全部串对拍一致），但不满足题目的 O(1) 空间要求——而这正是这道题要考的：认出写指针左侧的已写区可以复用为栈。（上面的原地算法也做了同样的全量对拍。）

  1. (1) 二分插入只减少比较：第 i 个记录找位置约 log2i 次比较，总比较 O(n log n)；但插入时要把后面的记录逐个后移，移动次数与直接插入完全相同，仍是 Θ(n2)，所以只在比较代价远大于赋值时明显更快。(2) 交换式插入每前进一格是一次交换（3 次赋值），而教材的移位式每格 1 次赋值、最后再写回一次，数据移动约多 3 倍，通常更慢。实验应分别统计比较次数与赋值次数，在随机、已有序、逆序三类输入上对比，理论预测：有序输入三者都是线性，随机与逆序时二分插入比较最少、交换式移动最多。
  2. (1) 结束条件：连续的一趟奇数扫描和一趟偶数扫描都没有发生交换。只看一趟不够——奇数趟没交换时，偶数位置上的相邻逆序可能还在。(2) 每趟对一半的相邻对做比较交换，n 趟之内必然排好（奇偶交换排序的经典结论）。(3) 按上面的结束条件：已从小到大有序时，一趟奇、一趟偶都无交换即结束，共 n−1 次比较；从大到小有序时要扫满 n 趟才排好，再加两趟确认，比较次数为 n(n−1)/2+(n−1)（如 n=10 时 54 次）。平均情况同样需要 Θ(n) 趟、每趟 Θ(n) 次比较，平均时间 Θ(n2)；它的价值在于同一趟内的比较互不相关、可以并行。（脚本模拟计数。）
  3. 先扫一遍求平均值 m（O(n)），分割时把 <m 的放左边、≥m 的放右边；轴值不一定是序列元素，所以分割后没有「已就位的轴值」可以排除，两侧都要递归。必须处理一侧为空的情形：子序列全部相等时平均值就等于它们，全部落到右侧，若不特判会无限递归——此时应直接返回。平均值对均匀分布的数据划分得很均衡，但对偏斜分布（少数极大值、指数分布）划分很差，最坏仍是 Θ(n2)；平均值的累加还要防溢出（用 long long 或增量平均）。实验应在均匀、偏斜、大量重复三类数据上与原算法比较运行时间和递归深度。
  4. 英文单词的基数排序：按最大长度 n 做 LSD，从最后一个字符位往前，每位按字符分配到桶、再按桶序收集；较短的单词在缺位处视为「空字符」，空字符小于任何字母（相当于左对齐、右补最小哨兵），这样 he 排在 head 前面。区分大小写时可直接按字符编码分桶，或约定 A<a<B<b<⋯ 再映射。链式实现时桶是链队列，分配和收集只改指针，正是原书静态链基数排序的做法。不适合链式存储的算法：Shell 排序（按增量跳跃访问）、堆排序（靠下标算父子）、二分插入排序（二分要随机访问）以及按下标取中值作轴的快速排序——它们依赖 O(1) 的随机访问，换成链表后每次定位就要 O(n)。适合链式的有直接插入、直接选择、归并（链表归并不需要辅助数组）和基数排序。

#补充题参考答案

[课程第十章答案第 1 题；ref_DSA/第十章书面作业.pdf 第 1 题] 从当前指针出发按关键码方向前后移动；题目注明重复时要检索到最后一个，所以向后走时遇到相等不能立即停，要继续走到下一个结点不等于 K 为止，向前走时第一次遇到的相等结点就是最后一个。失败时不能改动 p——p 的语义是「最后一次成功检索到的结点」，失败后把它改成空或停在半路，下一次检索就失去了起点。平均检索长度取起点和目标位置的双重平均：设无重复元素、起点 i 与目标 j 各自等概率，比较次数为 |i−j|+1， $ASL=1n2∑i=1n∑j=1n(|i−j|+1)=n2−13n+1≈n3.（\sum_{i,j}|i-j|=\frac{n(n^2-1)}3。n=1,2,3,5,10暴力枚举分别得1,\frac32,\frac{17}9,\frac{13}5,\frac{43}{10}，与公式一致。）只算\frac{n^2-1}{3n}$ 是漏了「起点本身也要比较一次」。

  3. 若索引表也顺序检索，分 b 块、每块约 n/b 项，ASL 的主项约为 b/2+n/(2b)；令两项平衡得 b≈n，每块也约 n 项，总 ASL 为 Θ(n)。
  4. 集合插入重复元素是正常、可预期的集合操作，不是异常；返回 bool 可让 true 表示确实新增、false 表示原来已有，调用方无需用异常处理普通分支。本书 IntSet::insert 正是该契约。

  6. 开散列删除链结点即可，装填因子可大于 1，但每项多指针/分配开销；闭散列删除要墓碑，装填因子必须小于 1，存储连续、缓存友好但会聚集。

#原书习题答案

  1. 每块 1024/32=32 条记录，1 MB 工作内存可放 220/32=32768 条记录（1024 块）。第一遍用置换选择生成初始顺串，平均长度约为内存的 2 倍，即 65536 条记录（2 MB）。第二遍做一次多路归并：每一路至少要占一个块的输入缓冲，1 MB 内存约可同时归并 1024 路（实际要扣掉输出缓冲，略少于 1024）。于是只扫两遍能排的文件最长约为 1024×2MB=2GB，即约 6.7×107 条记录。一般地，内存 M、块长 B 时两遍可排约 2M⋅(M/B) 的数据。
  2. 排序 100 倍的记录，工作量至少是原来的 100 倍以上（外排序的读写量还随归并趟数增加），而外排序的瓶颈是磁盘 I/O：(1) CPU 速度提高：几乎不影响 I/O 时间，不能满足；(2) 磁盘 I/O 时间减半：总时间约减半，远不够 100 倍，不能满足；(3) 内存存取时间减半：对外排序影响很小，不能满足；(4) 内存增大：顺串变长（约为内存的 2 倍）、归并路数增多，归并趟数可能减少，是四者中最有效的，但单靠它也做不到 100 倍的提速，同样不能单独满足。结论：四项单独升级都不够，需要组合（例如更大内存配合更快的磁盘或多盘并行）。
  3. 三趟需 k^3>=80，最小 k=5；15 个文件含输出故 k<=14，14^2>=80，两趟取 k=9 即可。

  2. 参照 B 树：插入时叶上溢平分为两叶、把分界码复写到父结点（叶上保留），内部结点上溢时中位数上移（不在原结点保留）；删除时叶下溢先向兄弟借、借不到再与兄弟合并并删去父结点里相应的分界码，内部结点下溢的处理与 B 树相同；全程维护叶链。用 code/ch11/bplus_tree 的 BPlusTree::validate() 在每次操作后检查有序性、结点容量、叶深一致和叶链，再与 std::map 随机对拍。
  3. 中序遍历的推广：对结点 (p0,K1,p1,…,Kk,pk)，依次递归遍历 p0、输出 K1、递归遍历 p1、输出 K2……最后递归遍历 pk。由 B 树的有序性（pi−1 子树的关键码都小于 Ki，pi 子树的都大于 Ki），输出递增，每个关键码恰好输出一次，时间 O(n)；用显式栈保存（结点，下一个要处理的指针下标）即可写成非递归。
  4. B* 树要求非根结点至少 ⌈2m/3⌉ 个孩子。插入上溢时先尝试把多出的关键码经父结点匀给相邻兄弟（兄弟不满时）；兄弟也满了，就把两个满结点连同父结点中的分界码共 2m 个关键码分成三个结点，每个约 2m/3 满，向父结点增加一个分界码。删除下溢时先向兄弟借，借不到就把三个相邻结点（自己和两个兄弟）合并成两个。这样空间利用率至少约 2/3，代价是插入删除要多读一个兄弟结点。
  5. (1) 设 bh(T1)≥bh(T2)（黑高）。沿 T1 的最右路径向下，找到黑高等于 bh(T2) 的黑结点 y；以 z 为新结点、着红色，左子树为 y 为根的子树、右子树为 T2，把 z 接到 y 原来的父结点上。此时只可能出现红父红子，按插入后的修复过程向上处理即可。求黑高与下行都是 O(log N)，修复也是 O(log N)，总代价 O(log N)；bh(T1)<bh(T2) 时对称地沿 T2 的最左路径下行。(2) 不给 z 时，先从 T1 中删去最大关键码作为 z（O(log N)），再按 (1) 合并。前提是 T1 的关键码都小于 T2 的；若两棵树值域交错，就只能中序展开成两个有序表、归并后再建树，代价 O(N)。

#原书习题答案

  1. 方阵原地转置只交换 i<j 的 a[i][j] 与 a[j][i]，O(n^2)、O(1)。
  2. 双循环写对角 0、其余 1/空格后逐行打印。
  3. 每行找最小及列号，再扫描该列验证是否列最大；O(mn)。
  4. 广义表逆置用访问标记防环，递归先逆子表再反转同层 next 链。
  5. 画图题以 atom/list 标志结点，head/tail 或兄弟链表示；共享引用必须指向同一结点。
  6. Head 取表的第一个元素，Tail 取去掉第一个元素后剩下的表。L1=((((a),b),d),e)：Head(L1) =(((a),b),d)，Tail 得 (d)，再 Head 得 d，即 d= Head(Tail(Head(L1)))。L2=(a,(b,((d)),e))：Tail(L2) =((b,((d)),e))，Head 得 (b,((d)),e)，Tail 得 (((d)),e)，Head 得 ((d))，再 Head 得 (d)，再 Head 得 d，即 d= Head(Head(Head(Tail(Head(Tail(L2))))))。注意 Tail 的结果总是表，取单个元素必须最后用 Head。
  7. 深度为原子 0、空表 1（按定义），一般为 1+max(child depth)，环需 visited 防无限递归。
  8. DFS 删除匹配原子，修改前保存 next；共享结点只处理一次。
  9. 带 visited-pair 的同步比较，原子值/类型相同且子结构递归相同才相等。
  10. 单独一个请求分辨不出三种方法（只要某块够大，三种方法都能满足），但一串请求可以：前面的请求挑了哪一块，决定了后面的请求还有没有足够大的块。空闲块按地址依次为 900、1500、700，下面三组请求都经脚本模拟核对。(1) 只有首先适配能满足：150、600、950、600——首先适配把 150、600 都切在 900 上，留下 1500 给 950，最后 600 用 700；最佳适配把 150 放进 700、600 放进 900，950 用掉 1500 后最后的 600 无处可放；最差适配把 150、600 都切在 1500 上，剩 750 放不下 950。(2) 只有最佳适配能满足：100、900、1000——最佳适配把 100 放进 700，900、1000 正好用 900 和 1500；首先适配把 100 切在 900 上，900 只能用 1500，剩 600 放不下 1000；最差适配把 100、900 都切在 1500 上，剩下 900、500、700 放不下 1000。(3) 只有最差适配能满足：750、800、750——最差适配把 750 切在 1500 上留 750，800 用 900，最后 750 正好用剩下的 750；首先适配和最佳适配都把第一个 750 放进 900，800 用 1500 留 700，最后的 750 放不下。正文习题第 4 题说「能否满足分辨不出三种策略」，指的是单个请求。
  11. 把可利用空间表按块的大小从小到大排序，并且每次都从最小的块开始扫描（而不是从上次停下的位置继续）——这时第一个够大的块就是所有够大的块里最小的，首次适配就等于最佳适配。代价是分配、回收时都要维护按大小的次序，而且按地址相邻的空闲块不再在表中相邻，合并相邻空闲块要另想办法。
  12. 按原书 12.3 节，二叉 Trie 是把关键码看成二进制位串、每层按一位分左（0）右（1）。字符串先编码成位串，例如每个字母用 5 位（a=00001，b=00010，…，z=11010），词尾补全 0 作结束标记；从根开始按第 1 位、第 2 位……逐层分支，直到一棵子树里只剩一个关键码为止，该关键码作为叶挂在那里。8 个词的公共前缀决定了树形：cop、copy、cup 共享 c 的 5 位，hi、hia、his、hit、he 共享 h 的 5 位，再往下 o/u、i/e 在各自的编码第一个不同的位上分开；cop 与 copy 要一直比到 cop 的结束标记才分开。实际画图时，按字母编码逐位展开即可（字母 Trie 的每一层相当于二叉 Trie 的连续 5 层）。按字母分支的普通 Trie 则为：根下 c、h 两支；c 下 o→p（cop 结束）→y（copy）与 u→p（cup）；h 下 e（he）与 i（hi 结束）→a（hia）、s（his）、t（hit）。
  13. PAT（Patricia）Trie 在二叉 Trie 的基础上压缩掉所有只有一个孩子的结点，每个内部结点只记「下一步比较第几位」，于是 8 个关键码恰有 7 个内部结点。按字母层面看压缩效果：根先按首字母分成 c、h 两支（c 与 h 在编码上第一个不同的位处分支）；c 支直接比到第 2 个字母（o/u）分开，cup 成叶；o 支跳过 p，比较 cop 的结束标记与 copy 的 y 分开；h 支比第 2 个字母分出 he 与 hi…；hi… 再比第 3 个字母（结束标记/a/s/t）分出 hi、hia、his、hit。内部结点数 = 关键码数 −1=7 是 PAT 树的一般性质（每个内部结点恰有两个孩子）。
  14. 这里的高度按层数算（2k−1 个结点的满二叉树高为 k）。证明一个更强的命题 Q(k)：一棵高为 k 的满 AVL 树，再依次插入 2k 个比已有键都大的递增键，得到高为 k+1 的满二叉树。 从空树出发反复用 Q（Q(0)：空树插 1 个键得单结点）即得本题。先记一个事实：AVL 插入不会让树变矮（不旋转时高度不变或加 1，旋转后恢复插入前的高度），所以插入过程中子树高度单调不减。证 Q(k)（k≥1）：设树为根 r、左右子树 L、R 都是高 k−1 的满树。递增键总是插到最右路径末端。第一阶段插入前 2k−1 个键，它们都进入 R；由 Q(k−1)，R 最终成为高 k 的满树，过程中 R 的高度在 k−1 与 k 之间，r 处高度差不超过 1，不会在 r 处旋转。此时 R 的根为 r'，其左右子树 L'、R'' 都是高 k−1 的满树。第二阶段的第一个键插进 R'' 末端，R'' 变高为 k（满树加一个结点，内部不失衡），r' 处左 k−1、右 k 仍平衡，而 r 处左 k−1、右 k+1 失衡且为 RR 型，对 r 左旋一次：新根 r'，左子树为 (L,r,L')——两个高 k−1 的满树加一个根，恰是高 k 的满树——右子树为 R''。剩下的 2k−1−1 个键继续插入 R''，由 Q(k−1)（第一个键已插入，过程相同）R'' 最终成为高 k 的满树，过程中高度保持为 k，根处不再旋转。于是整棵树是左右都为高 k 满树的高 k+1 满二叉树。（脚本对 n=1..31 逐个插入核对：根依次在第 3、6、12、24 个键时换成 2、4、8、16，n=2k−1 时都是满二叉树。）
  15. 按字典序比较（注意 July < June：第三个字母 l < n）。(1) 按 Jan, Feb, Mar, Apr, May, June, July, Aug, Sep, Oct, Nov, Dec 次序插入 BST：根 Jan；Jan 的左孩子 Feb、右孩子 Mar；Feb 的左孩子 Apr，Apr 的右孩子 Aug，Aug 的右孩子 Dec；Mar 的左孩子 June、右孩子 May；June 的左孩子 July；May 的右孩子 Sep，Sep 的左孩子 Oct，Oct 的左孩子 Nov。各结点深度（根为 1）之和为 42，成功查找 ASL=42/12=3.5。(2) 按同样次序插入 AVL 树（必要时旋转），结果：根 Mar；Mar 的左孩子 Jan、右孩子 Oct；Jan 的左孩子 Aug、右孩子 June；Aug 的左孩子 Apr、右孩子 Feb，Feb 的左孩子 Dec；June 的左孩子 July；Oct 的左孩子 May、右孩子 Sep；May 的右孩子 Nov。深度之和为 38，ASL=38/12≈3.17。（脚本建树复算。）
  16. 可允许重复但必须规定等键统一去一侧或结点存计数；图中两个 12 需靠附加次关键字/计数解释。
  17. 按本书 12.4.2 节的约定（只有根的树高度为 0，t(1)=2、t(2)=4）：高度为 h 的 AVL 树最少结点数 N(h) 满足 N(0)=1、N(1)=2、N(h)=N(h−1)+N(h−2)+1，即 N(h)=F(h+3)−1（F 为 Fibonacci 数，F(1)=F(2)=1），前几项为 1、2、4、7、12、20、33；最多结点数是满二叉树的 2h+1−1。若约定只有根的树高度为 1，则把 h 换成 h−1：最少 F(h+2)−1、最多 2h−1。答题时先说明高度的口径。
