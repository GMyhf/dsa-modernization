2025 秋「数据结构与算法」期末机考（dsa.openjudge.cn/2025final）的考场说明列出四份考场可以使用的资料： 本书作者的 C++ 代码包、一份 C 语言代码包、C++ 离线手册（cppreference）和 Weiss 的英文教材。 本附录只讲与本书直接相关的第一份：DSCode_ZhangWangZhao2008_06.zip。

原书前言说：「教材中只给出了最主要的算法和代码，完整的实现方法可参考教学网站上提供的与本书配套的代码包。」 这就是那个包。它是作者实际编译运行过的工程，每章一个目录，每个算法一两个文件。

#它和书上印的不是同一份

包名里的 200806 与原书「2008 年 6 月第 1 版第 1 次印刷」是同一个月，但包里的代码和书上印的不总是一致， 而且两边各有对错：

  • 多数时候包里是对的。 原书第 3 章的顺序栈按印刷原样编译不过——数据成员 int top 与成员函数 bool top(T&) 重名； 包里那个函数叫 getTop(T*)，编译得过。第 2 章的 delete 作函数名、第 3 章背包问题的 enum rdType {0,1,2} 也是这样。
  • 也有书上对、包里错的时候。 原书算法8.5 冒泡排序的内层循环写 j > i，包里写成 j >= i，第一趟就读到 Array[-1]； 原书算法2.11 的单链表删除写对了，包里删尾结点时会把同一个结点释放两次。
  • 还有两边都错的。 算法2.9 的 setPos 用 new 出一个多余的结点起步，书上和包里逐字相同； 算法4.6、4.8 的模式匹配都按 1 起始报位置，而正文说下标从 0 起。

所以考场上拿包里的代码来用，先在本书里查一下那一条：原书 105 条清单，本书逐条登记了它在包里的位置； 每条「编译不过」或「跑起来是错的」勘误，都查过包里有没有；第 2、3、4、8 章还把包里的实现与本书的实现 在同一批输入上真跑了对拍。逐条结论见本附录后三节与书末「原书勘误」。

#用之前要知道的三件事

  1. 编码。 包里大多数文件是 GBK 编码、Windows 换行（2008 年 VC6 的默认），第 1、10、12 章另有几个带 BOM 的 UTF-8 文件。 用 UTF-8 打开 GBK 文件，中文注释会是乱码——换成 GBK 重新打开即可，代码本身不受影响。
  2. 编译器。 包是 VC6 年代写的，有些写法今天的 g++ 不再接受，最常见的是 void main()。 OpenJudge 的 C++ 用 g++ 编译，交题前按「今天的 g++ 编译得过吗」一节改掉。
  3. 容器会自己打印。 包里的栈、队列、线性表在出错时直接 cout 一句中文提示（「栈满溢出」「栈为空，不能出栈操作」）， 题目要求严格输出格式时，这些提示会让答案错。

#包里的坑

下面几处缺陷原书没有——要么原书没印那段代码，要么印对了——只在包里。考场上直接拿包里的代码交题，会在这些地方读写到数组外面或得到错的结果。

编号 位置 缺陷
P01 算法8.4（包里的 MaxHeap），ch08_Sort/HeapSort/MaxHeap.h MaxHeap 的 SiftDown 判右孩子写 j<CurrentSize，应为 j<CurrentSize-1：n 为偶数时建堆读 heapArray[n]，越界一格，那格若更大还会被换进堆、再把 temp 写出界。原书没印 MaxHeap；第 5 章 MinHeap 与代码5.11 写对了。ASan 在对拍里当场报 heap-buffer-overflow
P02 算法8.5，ch08_Sort/BubSort.cpp BubbleSort 内层循环写 j>=i：i=0 时比较 Array[0] 与 Array[-1]，越界一格；原书印的 j > i 是对的
P03 算法2.11，ch02_LinearList/alg2.6-11/lnkList.h lnkList 的 del 删尾结点时 tail = p; delete q; 之后又落进 if (q != NULL) { p->next = q->next; delete q; }——释放后使用加二次释放；原书用 else if 写对了，还多了 p == tail 的判断
P04 算法3.10，ch03_StackQueue/alg3.9-11/knap1.cpp knap 最后一行是 else knap(s, n-1);——少了 return，结果被丢弃、函数从末尾流出（未定义行为）；原书印的 else return knap(s, n-1) 是对的
P05 算法8.10（包里的驱动），ch08_Sort/BucketSort.cpp BucketSort.cpp 的 sort 包装写死 max = 80，而计时驱动 SortMain.h 生成 Random(32003)——值 ≥ 80 时 count[TempArray[i]] 越界写。只因驱动里的排序调用被注释掉（P06）才没炸
P06 第 8 章计时驱动，ch08_Sort/SortMain.h SortMain.h 的计时循环里 //sort<int>(&array[i], listsize); 被注释掉：包里 12 个排序程序跑起来只生成 1000 万个随机数、给空循环计时，随后逐对检查有序、打出成串 ERROR!!!——作者的排序从没在这个驱动里真正跑过

另有与原书同病、但不在勘误表里的：

  • P07（代码3.2）：无参构造 arrStack() 只设 top = -1，mSize 与 st 都未初始化，析构时 delete [] st 释放野指针——原书代码3.2 的无参构造同病

与原书同病的那些（印出来就错、包里也错）见书末「原书勘误」的「作者代码包里有没有」一节。
