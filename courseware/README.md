本目录存放《数据结构与算法》（张铭、王腾蛟、赵海燕，高等教育出版社 2008）
现代化重制版的**讲义（`.md`）与课件（`.pptx`）**，二者**同名成对**，
内容依据 [`../book/`](../book/) 的书稿编写。

| | 用途 | 特点 |
| --- | --- | --- |
| `*.md` 讲义 | 课后阅读、作业参考 | 完整正文、可运行代码、习题与参考答案 |
| `*.pptx` 课件 | 课堂放映 | 只保留主干、关键代码与原书插图，16:9 版面 |

> 讲义与课件是一套东西，因此放在同一目录、成对维护：改讲义时顺手核对同名课件。

**与 `book/slides/` 的关系**：那一套是从书稿自动抽取的放映稿，
覆盖全书 12 章、由 `tools/build_slides.py` 生成；本目录是**另起一套**、
按课堂节奏手写的讲义 + 课件，不复用它的任何内容。两者可以并存。

## 2 源码与再生成

课件**不是手工排版的**，而是由脚本从结构化内容生成，便于批量修改样式与逐年复用。

```
courseware/
├── DSA_CHNN_*.md        # 讲义（手写维护）
├── DSA_CHNN_*.pptx      # 课件（由下面的脚本生成）
├── deck.py              # 排版引擎：主题配色、版面构件、自适应字号
├── build_all.py         # 生成入口
├── verify.py            # 闸门：配对 / 元数据 / 资源 / 编译 / 可重生成 / 版面 / 渲染
├── content/
│   └── ch01.py          # 第 1 章课件的内容（META + SLIDES）
└── code/ch01/           # 讲义里上机题的参考实现（真编译、真运行）
```

⚠️ **不要直接编辑 `.pptx`** —— 它会被下次生成覆盖。改课件请改 `content/chNN.py`。
讲义 `.md` 是手写维护的，与 `content/` 无生成关系；两者内容需人工保持一致，
`verify.py` 只保证「源与产物一致」，保证不了「讲义与课件说的是同一件事」。

**环境**：`python-pptx`（读图片尺寸还要 `Pillow`）。这是本仓库里
**唯一**允许第三方依赖的目录 —— `tools/` 与 `code/` 仍然是纯标准库。

```bash
pip install python-pptx Pillow
```

**生成**：

```bash
cd courseware
python3 build_all.py           # 生成全部已编写的章
python3 build_all.py 01        # 只重新生成第 1 章
```

## 3 修改内容

编辑 `content/chNN.py` 中的 `SLIDES` 列表即可，无需碰排版代码。
每张幻灯片是一个元组：

| 写法 | 说明 |
| --- | --- |
| `('section', '第 1 节', '标题', '副标题?')` | 章节分隔页 |
| `('bullets', '标题', [条目, ...])` | 要点页；条目以 `- ` 开头表示次级 |
| `('code', '标题', '代码', '说明?')` | 代码页，字号按行数与最长行自动缩放 |
| `('ascii', '标题', '示意图', '说明?')` | 等宽示意图，居中 |
| `('image', '标题', '图片路径', '说明?')` | 原书扫描插图，等比缩放后居中 |
| `('table', '标题', [[表头...], [行...]], '说明?')` | 表格，列宽按内容自动分配 |
| `('two', '标题', '左标题', [...], '右标题', [...])` | 左右两栏 |
| `('key', '标题', '要点正文')` | 整页强调一句话 |

正文中可用 `**强调**`（渲染为深蓝加粗）与 `` `等宽` ``。
**代码页与示意图页原样输出**，不解析这些标记 —— 所以 C++ 的 `**` 与反引号是安全的。

`image` 页的路径相对 `courseware/` 解析，原书插图在
[`../book/assets/scan/`](../book/assets/scan/)。

## 4 质量检查

```bash
python3 verify.py            # 第 1–6 项，几秒
python3 verify.py --render   # 加第 7 项渲染检查（需 libreoffice + poppler-utils）
```

| # | 检查 | 它回答的问题 |
| --- | --- | --- |
| 1 | 配对 | 每章 `chNN.py` + `.md` + `.pptx` 齐不齐 |
| 2 | 元数据 | 讲义抬头四要素齐不齐；讲义与课件指的是不是同一章 |
| 3 | 资源 | 课件引用的插图、讲义里的相对链接，是不是都存在 |
| 4 | 代码 | `courseware/code/` 下每个 `.cpp` 在 `-Werror` 下真编译、真运行 |
| 5 | 可重生成 | `.pptx` 是不是当前 `content/` 的产物；页数与本文件的表格一致 |
| 6 | 版面标记 | 放映稿上有没有印出 `**` 或反引号；条目有没有以空白开头 |
| 7 | 渲染 | 逐页文字有没有越出版心、侵入页脚；PDF 有没有嵌入中文字体 |

第 5、6 项是这套东西最容易悄悄坏掉的地方：

- **第 5 项**防的是「改了 `content/`，忘了 `build_all.py`」——
  产物与源不一致，而两个文件都还在，肉眼看不出来。
- **第 6 项**防的是排版标记漏解析。`**` 与反引号是给引擎看的，不是内容；
  漏掉一层解析它们就原样打在投影幕上。人眼对一个小小的反引号极不敏感，
  所以这件事只能由代码保证。

排版引擎自己还有一道**构建期**的保护：代码页 / 示意图页的自适应字号一旦触底
（低于 8.5pt），`deck.py` 直接抛 `LayoutOverflow` 报错，而不是钳位后照常画。
字号是构建期就能精确算出来的量，不该留给 4 分钟的渲染检查去碰运气。

> ⚠️ 字体以放映机器为准：Windows / macOS + Microsoft PowerPoint 下
> 「微软雅黑 + Consolas」可直接使用；LibreOffice 若缺少中文字体会渲染成方框，
> 闸门第 7 项会显式报出「未嵌入中文字体」，不会把这种情况当作通过。
