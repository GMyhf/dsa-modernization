## P2｜读每一种排序方法时，同时问四件事

四个问题。

第一，它靠元素之间比较，还是靠关键码的数字结构做分配？这一条把所有排序分成两大类，而且决定了它受不受那条 n log n 下界的约束。

第二，相等的键排完之后相对次序变不变？这叫稳定性。

第三，除了原序列还要多少额外空间？

第四，最好、平均、最坏各是什么时间？注意是三个数，不是一个。

稳定不是装饰。举个例子：按成绩排序时，两名同分的学生如果仍然按原来的姓名顺序出现，后续再按姓名排才有意义。

最后说明一句：本章所有实现都是手写的，没有用标准库的 sort 顶替任何一个算法——那样等于把这一章删掉。理由在八点七点二节。

## P4｜第 1 节　8.1 排序问题的基本概念

第一节，基本概念。术语、稳定性、怎么衡量代价。

## P5｜8.1 术语先约定清楚

内排序是所有记录都能放进内存，这是本章；外排序还需要访问外存，那是第九章。

讨论排序的时候，习惯上用「记录」或者「元素」代替前七章的「结点」，用「序列」代替「线性表」。每个记录里有一个排序码域，作为排序的依据。

这里有一个容易忽略的区分：排序码不一定是关键码。关键码是唯一确定一个记录的域；如果排序码不是关键码，就可能有多个记录排序码相同，因此排序的结果可能不唯一。

正序是指序列已经符合排序要求；逆序是指把它反过来正好符合要求。

稳定，是指相同排序码的记录排序之后相对次序不变。

---

## P6｜怎么衡量代价

时间代价一般用记录的总比较次数和总移动次数来衡量。

有一条换算要记住：一次移动就是一次记录赋值，而一次交换算三次移动。这条换算在八点七点二节解释「同样是 n 平方，冒泡为什么比插入慢几十倍」的时候要用到。

影响相对运行时间的因素有：记录数量、排序码和记录的大小，还有——这一条最容易被忘记——输入记录的原始有序程度。

所以要分别考虑最佳、最差、平均三种情况。平均是这样定义的：长度为 n 的序列共有 n 的阶乘 种排列，假定每种排列等概率，所有排列的平均运行时间就是平均时间代价。

本章沿用原书的分类。

插入排序类：直接插入排序、Shell 排序。选择排序类：直接选择排序、堆排序。交换排序类：冒泡排序、快速排序。然后是归并排序。最后是分配排序：桶式排序、基数排序、索引排序。

第二节，插入排序。直接插入与 Shell。

## P9｜8.2.1 直接插入排序

直接插入排序是把第 i 个记录插入到前面已经排好序的 i 个记录中的恰当位置。

最好情况是 n，输入已有序的时候内层循环一次都不进。最坏是 n 平方，输入逆序的时候。它是稳定的，因为只与相邻元素比较，遇到相等就停下，绝不跳过相等元素。

这一页最值得记的是代价的来源。插入排序的时间，主要由记录移动到目标位置所需的步长之和决定，而步长又由序列中的「逆置数」决定。一个长度为 n 的序列平均有 n 乘 n 减一 除以四 对逆置。

于是得到一条很强的结论：任何一种只对相邻记录进行比较的排序算法，平均时间代价都是 n 平方。注意这句话说的不是某个算法，是一整类算法。

---

## P10｜8.2.2 Shell 排序

直接插入的代价几乎全花在「一次只能挪一格」上：一个很小的元素落在末尾，就得一路挪回 n 减一 次。

Shell 排序是一九五九年 D. L. Shell 提出的，它有效地利用了插入排序的两个性质：正序时是线性的，而且在短序列上很有效。

做法是：先把序列分成若干个不相邻、间距相同的子序列，各自做插入排序；然后减小间距，重复；直到间距减为一的时候，整个序列已经基本有序，最后那一趟插入排序就接近线性。

代码上和插入排序几乎一样，只是把「减一」换成了「减 gap」。

---

## P11｜Shell 排序：一步跨四格

看这个八个元素的例子。两个三十四用 34 和 34 撇 区分。

gap 等于四那一趟，把序列分成四个各含两个元素的子序列，各自排好。请看二十九：它从下标六一步搬到了下标二。再看 34 撇：从下标四一步搬到下标零。一步跨四格，这是直接插入做不到的。

gap 等于二再来一趟，gap 等于一最后一趟。最后这一趟的时候序列已经基本有序了。

但请看最终结果：34 撇 排在了 34 前面，和输入次序相反。

---

## P12｜为什么 Shell 不稳定，以及增量怎么选

Shell 排序不稳定，原因正是那个「跨越式移动」：34 和 34 撇 落在不同的子序列里，34 撇 在第一趟就越过了 34。

反过来说，稳定性恰恰依赖「只与相邻元素比较、绝不跳过相等元素」这件事。跨越换来了速度，代价就是稳定性。这个交换在数据结构里很常见。

增量序列的选择直接决定复杂度，而这是一个至今没有完全解决的问题。减半序列，也就是本书用的这个，最坏是 n 平方；Hibbard 序列，一、三、七、一直到 二的 k 次方减一，最坏是 n 的一点五次方；实测常用的 Sedgewick 序列更好。

本书取减半，是因为它最容易讲清楚「增量」这件事本身。

## P14｜8.3 选择排序

直接选择排序：每一轮从剩余部分选出最小的，与当前位置交换。

它的最好情况也是 n 平方。为什么？因为无论输入什么样，都要把剩余部分完整扫一遍才能确定最小值。它没有「提前结束」的机会。

但它换来了一个别人没有的性质：交换次数不超过 n 减一。记录很大的时候，这一条是有价值的。

它不稳定，因为交换会把相等元素跨过去。

堆排序用的是第五章的最大堆。建堆是线性的，然后 n 次取最大，每次 log n。总代价 n log n，而且最坏情况也有这个保证。它是原地排序，不要额外空间。

再强调一次第五章那个结论：那个 log n 全部来自后面 n 次取最大，建堆那一步是白送的。

---

## P15｜8.4.2 快速排序：分、治、不用合

快速排序是一九六二年 Tony Hoare 发明的，被评选为二十世纪十大算法之一，平均时间代价是 n log n。

四步。从序列中选一个记录作轴值；把其余记录分割成左右两个子序列；左边都不大于轴值、右边都不小于轴值，于是轴值正好位于它最终的位置；然后对两个子序列递归。

请注意第三步的后果：不需要明显的「合」过程。轴值已经到位，左序列的记录再也不会跑到轴值右边。这是它与归并排序最大的区别——归并必须有合并那一步。

分割是快排的全部工作量所在：它是一次线性扫描。而分得均不均匀，决定了递归有多深。每次都平分是 n log n；每次只切下一个元素，就退化成 n 平方。

---

## P16｜轴值怎么选，影响很大

轴值的选择应该尽量使序列能被划分为均匀的两半。

最糟糕的情况莫过于轴值恰好是第一个或者最后一个记录——这样分出的两个子序列中会有一个为空，分治法根本起不到作用。

所以，如果选第一个或最后一个记录当轴值，那么输入恰好正序或者恰好逆序的时候，每次分割都是最坏。

选中间点会好很多：正序或逆序时正好平分序列，实验效果非常好。实务中的快排一定要配三数取中，或者随机枢轴。

最后一条提醒：等于轴值的记录怎么处理，有多种方法，因为快排本来就不稳定。但有一条是硬要求——全相等的输入必须也能结束。处理不当会死循环，这是快排最常见的一处 bug。

## P18｜8.5 归并排序

归并排序也是分治：分成两半各自排好，再合成一个有序序列。

它和快排正好相反——快排把功夫花在「分」上，分完就不用管了；归并把功夫花在「合」上，分只是对半切一刀。

归并是稳定的，合并的时候相等元素优先取左半边的就行。最坏也是 n log n。

代价是需要 n 的辅助空间。这是它与堆排序的分水岭。

把三个 n log n 的算法放在一起看：堆排序原地但不稳定；归并稳定但费空间；快排平均最快但最坏退化。三者各占一角，没有一个全占。这就是为什么标准库要把它们拼起来用。

---

## P19｜8.6.1 桶式排序：不再比较

前面每一种排序都靠元素之间的比较决定次序，而比较排序最坏至少要 n log n 次比较——这个证明在八点七点三节。

要突破这个下界，只能不再比较。转而利用关键码本身的数字结构，直接算出每个元素该去哪儿。这类方法叫分配排序。

桶式排序是其中最简单的一种。已知所有取值落在零到 m 减一 之间时：第一步，准备 m 个计数器，扫一遍序列数出每个取值出现几次。第二步，把计数累加成「小于等于 i 的元素共有几个」。第三步，这就直接给出了每个取值在结果里的位置区间。

「先数一遍再累加」这一步的用处是：预先给每个桶留出恰好够用的一段，于是只需要一个长度为 n 的辅助数组，而不是 m 条变长的链。

---

## P20｜8.6.2 基数排序

桶式排序的问题是 m 太大的时候空间吃不消——值域有多大就要多少个计数器。

基数排序的办法是把关键码按位拆开。每一位的取值只有 r 种，十进制就是十种。低位优先的做法叫 LSD：从最低位开始，每一位做一次分配加收集，一共 d 趟。

这里有一条硬要求：第一趟之后的每一趟，都必须用稳定排序。否则前面几趟的成果会被后面的趟数打乱。这是本章「稳定性不是装饰」最硬的一个例子——不稳定的话，算法直接给出错误答案。

代价是 d 乘以 括号 n 加 r。它没有违反那条 n log n 下界，而是站在下界管辖范围之外。代价是对关键码的形态有额外要求：值域要够密，或者位数要够少。

## P22｜8.7.1 三种简单排序

三种 n 平方 的算法放在一起看，差别不在数量级，而在它们对输入形态的反应。

直接插入：最好是 n，输入已有序；平均和最坏是 n 平方；稳定。

冒泡带无交换退出：最好也是 n；平均最坏 n 平方；稳定。

直接选择：最好、平均、最坏全是 n 平方；不稳定；但交换次数不超过 n 减一。

选择排序那一行是关键。它的最好情况也是 n 平方，因为无论输入什么样都要完整扫一遍。代价换来了「交换次数最少」这个别人没有的性质。

而插入和冒泡都能在有序输入上退化到线性——前者的内层循环一次都不进，后者靠那个「本趟无交换」的标志立刻退出。

## P24｜从这两张表读出来的三件事

第一件：同为 n 平方，冒泡比插入慢二十七倍，五千八百二十二 对 二百一十四。

常数差异从哪来？冒泡每遇到一个逆序对就做一次三步交换，插入只做一次搬移。渐近记号把常数丢掉了，但常数在你实际关心的规模上是看得见的。

再说一遍那句话：Θ 告诉你 n 变大时谁会输，不告诉你在你关心的那个 n 上谁更快。

第二件：n 从一万涨到五万，是五倍。n 平方 的三个涨了大约二十五倍，也就是五的平方；n log n 的三个只涨了五到六倍。这就是量出来的数量级。

第三件，也是最反直觉的：优化快排在已经排好序的输入上，比插入排序慢了不止一百倍。原因在八点四点二讲过——本书实现取末元素作枢轴，有序输入每次划分都最坏。而那两处优化管的是栈深和常数，救不了最坏时间。

## P25｜原书量出的几条敏感性结论

原书还量出了几条对数据分布的敏感性结论，值得一并记住。

选择排序、归并排序、基数排序对数据分布不敏感。而插入、冒泡、Shell 都是正序比逆序快；在正序或者基本有序的输入上，简单算法反而是最好的。

快速排序的正序和逆序速度一样，都比随机分布要快。原因是原书的算法选取中间点作为轴值，正序或逆序时正好平分序列。而本书实现取末元素，所以在这两种输入上反而最慢。

同一个算法，选轴策略不同，对输入形态的反应可以完全相反。这一条值得记住。

堆排序逆序比正序稍微快一些，因为用的是最大堆，逆序时已经自然成堆。

顺序基数排序比链式要快；但如果记录是比较大的组合类型，应该用链式存储来减少移动。

## P26｜标准库里的排序是怎么做的

标准库的 sort 实际上是一种基于快速排序的混合算法，今天通称 introsort。

它先用快速排序，轴值三点选中；当长度小于某个阈值——原书记为二十——就停止递归，最后对整个序列做一次插入排序；同时引入一个递归计数，当递归深度超过阈值——原书记为二倍 log n——就转入堆排序。

这样最坏情况下也能达到接近 n log n：比堆排序差一些，但比纯快排好得多，而平均性能与快排差不多。

另外，stable_sort 用的是归并排序，partial_sort 用的是堆排序。

这段话正好解释了本书为什么不用标准库的 sort 顶替这一章：它是把本章三种算法拼起来的产物，读懂它的前提，恰恰是先把这三种都手写一遍。

## P27｜8.7.3 排序问题的下限

先把上限和下限这两个词说清楚。下限是解决这个问题所能达到的最佳可能效率，即使算法还没设计出来；上限是已知最快算法达到的效率。如果两者相同，那么从渐近意义上说，不可能有更有效的算法了。

先看一条谁也绕不过去的下限：任何算法的时间代价都不可能小于它的输入输出时间。算法至少要花 n 步读入 n 个数据、n 步输出结果。所以排序的时间只可能在 n 到 n log n 之间。

已经知道比较排序的上限是 n log n。那它的下限能不能降到 n？

答案是不能。任何基于比较的排序，最坏情况下至少需要 n log n 次比较。

## P28｜判定树：证明

证明用判定树，这个论证很漂亮。

把一次排序的执行过程画成一棵二叉树。每个内部结点是一次比较，问 a i 小于 a j 吗；两条边是两种结果；每片叶子是一种最终的输出排列。

于是，算法在某个输入上做了多少次比较，就等于从根走到对应叶子的路径长度。

现在数叶子。n 个互不相同的元素有 n 的阶乘 种排列，每一种都必须能被这棵树区分出来——否则算法会对两个不同的输入给出同一个答案，那就错了。所以叶子至少有 n 的阶乘 片。

再数高度。高度为 h 的二叉树最多有 二的 h 次方 片叶子。于是 二的 h 次方 大于等于 n 的阶乘，两边取对数，h 大于等于 log n 的阶乘。用 Stirling 公式，这就是 n log n。

而树的高度，正是最坏情况下的比较次数。证毕。

## P29｜这个下界只约束比较排序

最后强调一句：这个下界只约束比较排序。

桶式排序和基数排序不比较元素，它们直接用关键码的值算位置。所以它们没有违反下界，而是站在下界的管辖范围之外。

这不是钻空子。代价是对关键码的形态有额外要求：值域要够密，或者位数要够少。天下没有免费的午餐，这里买单的是「适用范围」。

排序、检索和索引历来是数据结构讨论的重点问题，三者互相支撑。

稳定性决定了能不能做多关键码排序，基数排序 LSD 完全依赖它。

三种简单排序都是 n 平方，根本原因是同一个：只对相邻记录比较和移动。想从数量级上提高，就必须摆脱这种一步步操作的思想，Shell 是这个方向上的第一步。

堆排序原地但不稳定；归并稳定但费空间；快排平均最快但最坏退化——各占一角。

比较排序的最坏下界是 n log n，用判定树证明；分配排序不受它约束。

最后：同阶不等于同速。冒泡与插入同为 n 平方，实测差二十七倍。

## P31｜习题

作业，完整题面和参考答案在同名讲义里。

手算题：对同一组数据分别走一遍六种排序，写出每一趟。注意三种排序的「第一趟」做的事情完全不同，别混。

稳定性：逐一判断本章各算法是否稳定，而且要对不稳定的给出最小反例。

原书第八题很有意思：把冒泡的内层循环边界改一下，问算法还对不对、复杂度变不变。答案是仍然正确、渐近复杂度不变，但实际比较次数翻了一倍。这道题考的正是「渐近相同、常数翻倍」。

原书第十二题：用栈代替快排的递归，问最差情况栈有多深、怎样组织递归顺序能把栈深减到最小。答案是每次先把较大的那一半压栈、先处理较小的那一半，栈深就从 n 降到 log n。

上机第一题是复现那两张实测表。报告里一定要写清编译器、优化档和机器——没有这三项，时间数字是不可复现的。
