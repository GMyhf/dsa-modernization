## P5｜4.1 字符串与线性表的两点区别

字符串是组成元素为单个字符的线性表，简称串。字符个数称为串的长度，长度为零的叫空串。

它和普通线性表有两点区别。第一，数据对象约束为字符集。第二，基本操作通常以串的整体为对象——拼接、复制、抽取子串、模式匹配，动的都是一整段，不是单个元素。

子串的定义是：如果存在一个偏移 i，使得模式的每个字符都等于目标对应位置的字符，那么模式就是目标的子串。两个约定要记住：空串是所有字符串的子串；任何串都是自身的子串。非空而且不等于自身的子串，叫真子串。

## P7｜4.1.1 字符编码

字符串的逻辑元素是字符，但内存里保存的是编码单元。这两件事必须分开。

ASCII 每个字符一个字节，低七位表示字符，最高位是零，一共一百二十八个。其中第零到三十二号和第一百二十七号，共三十四个是控制字符或通信专用字符。剩下的是通用字符：大写字母六十五到九十，小写字母九十七到一百二十二，数字四十八到五十七。

ASCII 制定于二十世纪六十年代，没有考虑多语言。于是各语言各自发展出独立的编码系统，而这些系统可能用相同的数字表示各自不同的字符。中文有国标码和大五码，日文有 S-JIS 和 JIS，韩文有 Wansung。同一个数字，在两种编码里是两个完全不同的字。

为解决互通问题产生了 UNICODE。今天最常见的落地形式是 UTF-8，用一到四个字节编码一个码点，而且与 ASCII 完全兼容。

## P8｜一条 2008 年的书还讲不到的结论

由此产生一条结论，二零零八年那本书还讲不到，但今天必须知道。

C 加加 的 char 是一个字节，不等于一个人眼看到的字符。std string 的 size 返回的是字节数，不能用来数 Unicode 字符。要数字符就得按 UTF-8 解码，或者用明确的 Unicode 库。

好在编码本身不改变字符串概念和操作的本质：查找、拼接、抽取子串，这些接口的语义与编码无关。所以本书和原书一样，以 ASCII 为主。

## P9｜4.1.2 字符的编码顺序

字符编码表遵循偏序编码规则：编码顺序与自然次序一致。零的编码加一等于一的编码，一直到九；字母也一样。

所以任意两个字符都可以直接用编码值比大小。对字母而言，这种次序就是字典编目次序。

两个串按字符顺序比较，结果是：monday 小于 sunday 小于 tuesday；一二三 小于 一二三四 小于 二三。

请注意后面那一组。这只是字符串的字典次序，跟日常理解的次序不同——星期一确实在星期二之前，但整数一百二十三比二十三大。

比较规则是：先比第一个不同的编码单元；如果一个是另一个的前缀，短的那个更小。

## P10｜这里有个 C++ 特有的坑

这一页说一个 C 加加 特有的坑，必须点破。

刚才那条结论只对 std string 成立。两个字符串字面量之间写小于号，比的是两个数组的地址，不是内容。

看编译器的警告：comparison between two arrays，两个数组之间的比较。再看运行结果：只要有一边是 std string，答案是 true true；两边都是裸字面量，答案变成 false true——第一个的答案反了。

因为地址由编译器摆放决定，这个结果没有任何意义。所以本书凡是比较字符串，一律先落到 String 或者 std string 上，再谈编码顺序。

## P12｜4.2 串的顺序存储

串一般用顺序存储，就是一块连续的字符数组。记长度有两种办法。

一种是末尾放结束标记，C 风格字符串用的就是这个，末尾一个反斜杠零。代价是求长度要扫一遍，而且串里不能含这个字节。

另一种是单独存一个长度字段。求长度是常数时间，而且串里可以含任意字节。本书的 String 用后者。

这个类同样自己管着 new 出来的缓冲区，所以三法则一条都不能少。这和第二章的顺序表、第三章的顺序栈是同一课——这已经是第三次了。同一个知识点在三章里各出现一次，不是重复，是因为它确实每次都要用。

## P13｜原书 String 类的三处硬伤

原书这个类的三处硬伤。

## P15｜4.3 模式匹配问题

模式匹配就是在文本中寻找一个给定的模式。通常文本很大，模式很短。

两个典型场景。文本编辑：模式通常是一个单词，十个字符左右，而文本从几百字到上百万字。DNA 分析：信息由 A、C、G、T 四个符号组成，基因一般几百个字符，而人类染色体的长度有三十亿之多。

匹配分精确和近似两类。本节和原书一样，只讨论精确匹配中的单选情况，不涉及通配符、正则表达式和近似匹配。

要回答的问题是：模式是否作为目标的连续子串出现，如果出现，首次出现在哪个位置。

有一句要记住：模式和目标的第一个字符都从位置零开始。下一页你会看到，原书自己的两个算法都没有遵守它。

## P16｜4.3.1 朴素算法：思路与代价

朴素算法的思路直白：把模式的首字符对齐目标的每一个位置，逐字符比较。一旦失配，就把模式向右移动一个字符位置，重新开始下一趟。

代价分情况。最佳情况，目标首位置开始的子串就是要找的，代价是模式长度。

最差情况是目标长度乘模式长度。举个例子：目标是 n 个 a，模式是 m 减一 个 a 再加一个 b。每一趟都要比到模式的最后一个字符才发现不匹配，然后右移一位重来。

这里有句话值得记住：此类情况很少出现在文本中，却经常出现在 DNA 信息和图像信息中。这正是朴素算法在生物计算里不够用的原因。

平均情况下，字符集只有两个字符的时候大约是两倍的目标长度。

---

## P17｜朴素算法的问题出在哪里

问题出在哪里？

一旦失配，无论模式的具体情况如何，都只右移一位。于是目标里的字符会被反复比较，这叫目标的回溯。

「无论模式的具体情况如何」这半句是关键。模式本身其实携带着信息，而朴素算法把这个信息完全扔掉了。

---

## P18｜一个具体的浪费

看一个具体的浪费。模式是 abacab，目标是 abacaabacc 后面还有一串。

第一趟比到下标五发现不匹配。朴素算法把模式右移一位，让模式的第零个字符和目标的第一个字符比。

但这次比较是多余的。理由有两条：上一趟已经比过目标第一个字符和模式第一个字符，而且相等；又已知模式的第一个字符不等于第零个字符，这是模式自身的性质。两条一合，模式第零个字符不等于目标第一个字符，是推得出来的，根本用不着重新比。

Knuth、Morris、Pratt 三个人的发现是：每次右移的位数是存在的，而且与目标串无关，仅依赖于模式本身。

请体会这句话的分量——它意味着这个位数可以**预先算好**，一次算完，用在任何目标上。

## P19｜4.3.2 特征向量：一个例子就清楚了

换一个例子。目标是 ababab 后面一个 d，模式是 ababd，从位置零开始比。

比到下标四失配，目标那里是 a，模式那里是 d。失配之前已经匹配上了 abab 这四个字符。

KMP 的做法是问一个问题：abab 的前缀和后缀里，最长的相同的一段是多少？

前缀有 a、ab、aba；后缀有 b、ab、bab。最长相同的一段是 ab，长度二。

这个二的意义是：abab 的末尾两个字符恰好也是它的开头两个字符。而模式的开头也是 ab。所以模式可以一次右移四减二等于二位直接对上去，而且移过去之后前两个字符不必再比，它们必然相同。

接着从模式下标二和目标下标四往下比，一路比到底。整个过程中，目标的下标从来没有往回退过。

## P20｜特征向量怎么算

把「每个位置失配时该退到哪里」对模式的每个位置预先算出来，就是特征向量，也叫 next 数组。

代码是这样。外层循环走模式的每个位置，内层那个 while 是沿已经算好的特征值往回退。

最值得看的是最后那个三目表达式。如果模式的第 i 个字符和第 k 个字符相等，就直接借用 next k，而不是用 k。为什么？因为退到 k 之后，必然还会在同一个字符上失配，那一次比较注定失败，不如一次退到位。这就是所谓的「优化版」next。

刚才那个例子跑出来是：负一、零、负一、零、二。

## P21｜4.3.3 KMP：与朴素算法只差失配那一步

有了特征向量，匹配过程和朴素算法几乎一样，只有失配那一步不同：不再把模式退回开头，而是退到 next i。

注意两个变量的注释。模式下标 i 可以退到负一；目标下标 j 只增不减。这两行注释就是整个算法的灵魂。

还要注意返回值那一行：是 j 减 m，不是 j 减 m 加一。原书这里差了一，一会儿专门说。

最后看函数签名：next 由调用方传入。这样同一个模式可以只算一次、在多个目标上复用——这正是原书强调的性质，接口把它显式表达出来了。

## P22｜为什么 KMP 是线性的

为什么 KMP 是线性的？完整的论证是这样。

关键在于目标下标 j 只增不减。循环体里 j 加加 至多执行目标长度次，与它同处一条语句的 i 加加 也不超过目标长度次。

能让 i 减少的只有 i 等于 next i 这一句，而 next i 严格小于 i，所以每执行一次 i 至少减一。一旦减到负一，下一步必然进入 i 加加、j 加加 那个分支。

因此 i 等于 next i 的执行次数，不超过 i 加加 的次数加一。整个循环体至多执行两倍目标长度加一次——与目标串长度成线性关系。

加上算 next 的模式长度那一份，KMP 整体是模式长度加目标长度。

## P26｜本章小结

小结。

字符串是数据对象限定为字符集、而且以整段为操作对象的线性表。

编码：ASCII 单字节；UTF-8 用一到四个字节兼容 ASCII。char 不等于一个人眼看到的字符，size 数的是字节。

比较：按编码单元的字典序，前缀更短者更小。要小心两个裸字面量之间的小于号，那比的是地址。

朴素匹配最坏是目标长度乘模式长度，瓶颈是目标的回溯。KMP 用模式自身的前后缀信息决定右移多少，目标下标只增不减，整体线性。特征向量只依赖模式，可以跨多个目标复用。

最后，顺序存储加自管缓冲区，三法则在本章第三次出现。
