## P5｜1.1.1 问题描述：股市的传言

问题是这样的：若干个股票经纪人之间互相传消息，谁能直接传给谁、传一次要花多久，都是已知的。问从哪一个人开始散布消息，能让所有人最快都知道。

请注意，题目要的不是出边最多的人。要的是让最后一个收到消息的人，也尽可能早收到。这是两件不同的事，后面会看到差别。

教材用五个经纪人、十条有向边作为例子。方向和权都重要：B 一到 B 五要三个单位时间，而 B 五到 B 一要五个单位时间。同一对人，两个方向不一样。

## P9｜解法拆成三步

解法分三步。

第一步，用弗洛伊德算法算出任意两人之间的最短传播时间。

第二步，对每一个候选起点，找出从它出发到每个人的最短时间里，最慢的那一项。

第三步，在这些最大值里选最小的一个，那就是答案。如果某一行还留着无穷大，说明有人永远收不到消息，这个起点不合格。

教材里的大写 D 就是代码里的 shortest 矩阵，max i 是每一行的最大值，pos 是我们代码里 best source 的返回值。下标从零开始，所以 B 三对应的返回值是二。

---

## P10｜为什么取「最慢的一项」

第二步最容易想错，单独说一下。

从 B 三出发，到 B 一是六，到 B 二是七，到 B 四是十，到 B 五是二。消息要传遍所有人，就必须等最慢的 B 四收到。所以 B 三的完成时间是十 —— 不是这几个数的和，也不是最小值，是最大值。

## P11｜把每个人都当一次起点

把每个人都当一次起点，算完就是这张表。这是弗洛伊德跑完之后的结果矩阵。

只有 B 三这一行没有无穷大，它的最慢时间是十。其余四行都至少有一个人收不到消息。所以答案是 B 三。

这类目标有个名字，叫最小化最大距离。第七章讲图的时候还会再遇到它。

## P14｜Floyd：三重循环到底在循环什么

这是弗洛伊德的三重循环。

第一行先把矩阵复制一份，所以多次调用不会改动原来的网络。

三层循环的含义不是随便循环三次。最外层的 via 是中转站：这一轮允许路径经过 via。中间一层固定起点，最内层固定终点。循环体做的事情只有一件：比较原来的从 from 到 to，和绕道经过 via，哪一个更短。

举个例子，B 二到 B 四没有直接边，但是 B 二到 B 五是八，B 五到 B 一是五，B 一到 B 四是四，加起来十七。弗洛伊德最终算出来的就是十七。

这里有一个初学者最常犯的错：把 via 挪到最内层。挪了算法就不对了，因为它依赖的是「前 k 个中转点都已经考虑完」这个不变量。

## P15｜选答案：每行取最大，再在其中取最小

算完最短路，就是选答案。

result 一开始是空的，表示还没有找到合格的起点。外层循环每次处理一行，也就是一个候选起点；内层扫描这一行取最大值，那就是这个起点的完成时间。如果它比目前最好的还小，就更新。

这里的最大值有个术语，叫离心率。任何一行只要含有无穷大，这一行的最大值也是无穷大，不会优于有限的答案。全都不可达的时候，返回空值。

整个算法的时间是顶点数的三次方，空间是顶点数的平方。

## P16｜「可能没有答案」怎么返回

说一下返回值的写法，这是本书和教材一个明显的差别。

教材那种传统写法是：返回一个 bool，再拿一个引用参数把结果带出来。问题是，答案和「有没有答案」走了两条通道。你如果忘了看返回值，读到的就是一个未初始化的变量，而编译器什么都不会说。

本书的写法是返回 optional，可以先理解成一个「可能装着下标的盒子」。取值之前必须先判断盒子空不空，所以「无解」这种情况漏不掉。

还有两条一起记住：容器和抽象数据类型内部不打印任何东西，真正的错误靠抛异常；返回值加了 nodiscard，调用者丢不掉。

## P19｜数据结构是三件事

数据结构是三件事，必须分开看：逻辑结构，说的是关系是什么；存储结构，说的是这些关系怎么落到内存里；还有定义在它们之上的运算。

后面十一章，都是在这三层之间做选择。

---

## P20｜1.2.1 逻辑结构：二元组 B = (K, R)

逻辑结构是从具体问题里抽出来的模型，写成一个二元组，K 和 R。

K 是结点的有穷集合。一个结点就是一个数据单位，类型任意 —— 可以是一个整数，也可以是一个结构体，甚至是更复杂的对象。数据结构课只关心结点之间的关系，所以通常把结点当作黑盒。

R 是定义在 K 上的一组二元关系。本书里 R 一般只含一个关系 r，这时候就记作 K 和 r。如果一个有序对属于 r，前面那个叫前驱，后面那个叫后继。没有前驱的叫开始结点，没有后继的叫终止结点。

举个例子：教学计划。每一门必修课是一个结点，「程序设计，数据结构」这个有序对，表示必须先上程序设计。

最后强调一句：逻辑结构只谈关系，不谈占几个字节。

---

## P21｜按关系的性质，逻辑结构分三类

按关系 r 的性质，逻辑结构分成三大类。

线性结构，每个结点至多一个前驱、至多一个后继。线性表、栈、队列、串都是，对应第二到第四章。

树形结构，根没有前驱，其余每个结点恰好一个前驱，但是后继的数目不限。二叉树、树、B 树，对应第五、第六、第十一章。

图结构，前驱和后继都不限，对应第七章。

这里记住两条分界线：树和图的区别，在于每个结点是不是只从属于一个直接前驱；线性和树的区别，在于每个结点是不是只有一个直接后继。

---

## P22｜1.2.2 存储结构：四种基本映射方法

同一套逻辑关系，落到内存里有四种基本方法。

顺序方法，把结点存进地址相邻的单元，逻辑顺序就是地址顺序，按下标访问是常数时间。数组就是它。它又叫紧凑存储，因为除了数据本身没有附加信息，紧凑的程度用存储密度来衡量。完全二叉树也能顺序存，孩子的下标可以用二 i 加一、二 i 加二算出来，那是第五章的内容。

链接方法，每个结点里附一个指针域，存后继的地址。增删方便，但是按位置访问不再是常数时间，只能从链头一个一个比过去。

索引方法，在结点的存储空间之外，另建一张表，把索引值映射到存储地址。它的主要作用是减少读写磁盘的数据量，第十一章会详细讲。

散列方法，是索引法的延伸：不查表，用散列函数把关键码直接算成地址。冲突怎么处理，是第十章的内容。

## P24｜为什么索引函数不是数组那样的线性函数

再看一眼刚才那张图里每一块的宽度：五块的长度各不相同。

## P25｜1.2.3 抽象数据类型 ADT

第三小节，抽象数据类型，简称 ADT。

抽象的意思是，同一个概念可以有多种实现。一个抽象数据类型，是定义了一组操作的抽象模型：数据和操作封在一起，使用方只能通过这些操作访问数据，不能直接去翻内部表示。

一般写成三元组，D、R、P。D 是数据对象，R 是数据关系，P 是基本操作。D 和 R 给出数据模型，是对数据的抽象；P 给出这个模型能做什么，是对操作的抽象。

有了它，讨论一种结构的时候可以先不管它是数组还是链表，只问两件事：它提供哪些运算，这些运算有什么约定。

整数连同加减乘除，就是一个最简单的抽象数据类型。

## P27｜本书的一处改动：不写抽象基类

这里说一处本书和教材不一样的地方。

教材习惯先写一个纯声明的抽象基类，再让具体的类去继承它。本书不这么做，原因有两条。

第一，它给不了多态。基类之所以有用，是因为可以拿基类指针指向派生对象，写一份代码同时适用于顺序表和链表。但是本书各章的容器都是模板，元素类型在编译期就定了，彼此根本不需要互相替换，这个基类从头到尾没有一处用到。

第二，它还带一个陷阱。只要基类的析构函数不是虚函数，用基类指针去 delete 一个派生对象，标准规定这是未定义行为。常见的后果是只析构了基类那一层，派生类里 new 出来的缓冲区没人释放，内存就漏了；也可能直接崩掉。

未定义行为这个词后面会反复出现。它的意思始终是「标准不再对程序的行为作任何承诺」，而不是「结果不确定但还能用」。

## P29｜1.3.1 算法的四条性质

算法有四条性质。

通用性：对任意符合输入类型的数据都成立，不是只对书上那一组样例。

有效性：由有限条能被确切执行的指令组成，每一步的结果类型可预期。

确定性：每执行一步之后，下一步怎么走有明确指示。不能含糊，也不能被锁住。

有穷性：必须在有限步内结束，不能有死循环。

第四条有个常见误解要提醒：算法由有限条指令组成，这件事本身并不能保证执行是有穷的。循环条件写错，有限条指令照样能转个没完。所以设计算法的时候，要专门盯住结束条件。

---

## P30｜1.3.2 六种算法设计方法

六种常用的算法设计方法。

穷举法，把问题空间里的对象一一列举、逐个检验。要求对象有限、有列举规则。C 加加 的 switch 就是一种穷举。

回溯法，逐一枚举候选解，走不通就退回上一步换一个。第五到第七章的深度优先搜索、第三章的背包问题，都是回溯。

分治和递归。大问题切成同形的小问题，各个击破再合并，是自顶向下的。快排、归并、二分检索都是。分治和递归如同一对孪生兄弟，经常一起出现。

贪心法，每一步按某个贪心标准取局部最优，寄望于拼出全局最优。第七章的 Prim、Kruskal、Dijkstra 都是贪心。用贪心法的核心问题只有一个：选一个真能产生最优解的度量标准。

动态规划，也把问题分解成子问题，但是子问题不相互独立，所以要用一张表把已经解出来的答案记下来，避免重复计算。第七章的弗洛伊德就是典型的动态规划。

回到一点一节：那道题要的是任意两点之间的最短路，所以选弗洛伊德，而不是对每个起点各跑一遍 Dijkstra。

## P32｜为什么不能拿秒来衡量算法

先说为什么不能拿秒来衡量算法。

同一个算法，在巨型机上跑和在个人电脑上跑差很多。反过来，一个效率较差的算法在巨型机上，也可能比效率极好的算法在个人电脑上更快。

同一台机器上，编译型语言往往比解释型快很多。教材举的例子是，用 C 写的程序，比用 LISP 写的、算法完全相同的程序快将近二十倍。

所以我们衡量的不是时间，而是输入规模和基本操作次数之间的关系。规模一般指输入量的数目，排序问题里就是待排序元素的个数。基本操作是指，完成它所需的时间与被操作的具体数值无关，比如两个整数相加。

---

## P33｜1.4.1 渐进分析：只留增长最快的那一项

渐进分析的做法是：只留增长最快的那一项。

看这个函数：n 的平方，加一百 n，加以十为底的对数 n，再加一千。n 等于一的时候，常数项一千贡献最大；n 等于十的时候，一百 n 和常数项持平；n 等于一百的时候，前两项持平；n 到了一千，n 的平方一家独大，已经是第二项的十倍。

但要提醒一句：并不是任何情况下都可以忽略常数。规模很小的时候，系数和常数项举足轻重 —— 用来排上万个数的算法，未必适合排十个数。

## P34｜大 O 表示法

大 O 表示法，是巴赫曼在一八九四年引入的。

定义是这样的：如果存在正数 c 和 N，使得对任意的 n 大于等于 N，都有 f n 小于等于 c 乘以 g n，就说 f n 是 O g n 的。

它说的是上限：f 的增长最终至多趋同于 g。换句话说，它表明这个算法最多会差到什么程度。

上限并不唯一。一个在 O n 里的函数，一定也在 O n 平方、O n 三次方里面。所以有个约定：大 O 取的是所有上限中最小的那一个。

还有几条常用性质：a 乘 n 的 k 次方是 O n 的 k 次方；常数倍不改变阶；大 O 可以传递、可以相加。另外，任何底数的对数增长率都相同，所以本书把以二为底的对数 n 简写成 log n。

## P35｜常见增长率：n 稍大就是天文数字

这是常见的几个阶，以及它们在 n 等于十六和 n 等于二百五十六的时候的实际取值。

常数是一；对数是四和八；线性是十六和二百五十六；n log n 是六十四和二千零四十八；n 的平方是二百五十六和六万五千五百三十六；二的 n 次方，n 等于十六就已经是六万五千多，n 等于二百五十六根本写不下。

换成时间感受一下：n 等于一千、时间单位取一微秒，线性是一毫秒，平方是一秒，三次方是十六分钟，而二的 n 次方大约是十的二百八十六次方年 —— 地球的年龄还不到十的十次方年。

## P37｜Ω 与 Θ：下限，以及上下限同阶

除了大 O，还有两个记号。

大欧米伽。它的定义和大 O 只差一个不等号的方向：f n 大于等于 c 乘以 g n。它说的是下限，也就是这个算法至少要花多少。大 O 取所有上限中最小的那个，欧米伽取所有下限中最大的那个。

希塔，用在上下限同阶的时候。一个函数既是 O g n，又是欧米伽 g n，就说它是希塔 g n。

举个例子：一百 n 的平方，加五 n，加五百。取 c 一等于一百、c 二等于一百零五、N 等于十，就能上下夹住它，所以它是希塔 n 的平方。说是希塔，比说是大 O 更强。

## P39｜数一数赋值操作（二）：嵌套循环

第二段是嵌套循环，依次求出所有前缀子数组的和。

## P40｜数一数赋值操作（三）：嵌套不等于平方

第三段专门用来破一个误解：嵌套不等于平方。

这段代码只对每个子数组的前五个元素求和。外层循环 n 减四次，但是内层恒定执行四次，跟 i 的大小无关，每个 i 一共八次赋值。

## P41｜1.4.2 最佳、最差与平均

一点四点二节，最佳、最差和平均情况。

以在数组里顺序检索一个 K 为例。最佳情况，K 就是第一个元素，比较一次。最差情况，K 是最后一个，比较 n 次。平均情况，如果 K 出现在每个位置的概率都是 n 分之一，平均要比较 n 加一除以二次。

但是概率不相等的时候，结论会明显改变。假设它出现在第一个位置的概率是二分之一，第二个位置是四分之一，其余位置均分，那么平均只要一，加上 n 加三除以八次，比等概率的情况快将近四倍。

所以平均情况分析并不总是可行 —— 它要求你事先知道输入的概率分布。

---

## P42｜那该看哪一种情况

那分析一个算法的时候，应该看哪一种情况？

最佳情况发生的概率太小，代表不了算法的性能，但它能告诉你这个算法在什么场合适用。

最差情况告诉你这个算法至少能做多快，这一点在实时系统里最要紧。教材举的例子是空运处理系统：一个绝大多数时候能管 n 架飞机、但是偶尔会超时的算法，是不可接受的。

对多数算法来说，最坏和平均往往只差一个常数因子。

后面每讲一个算法，我们都会分别交代三种情况。比如第八章的快速排序，平均是 n log n，但是输入已经有序的时候会退化成 n 的平方。

## P44｜1.4.3 时间和空间的折衷

一点四点三节，时间和空间的折衷。

很多算法用的是静态存储结构，规模一旦定下来，占用的空间就不变，好估，所以本书对这类算法一般只讨论时间代价。也有一些算法用动态结构，运行当中空间会数量级地涨落，那就必须单独分析。

时空折衷的意思是：为了改善时间开销，往往要以增大空间开销为代价，反过来也一样。

空间换时间的例子：黄页查电话，另建一张散列索引表，时间从线性降到常数，空间多出线性的一份。

时间换空间的例子：第六点三节把一棵树压成带右链的序列，省下了全部指针域，代价是恢复结构的时候必须重新扫一遍。

一句话：没有免费的加速。

## P45｜1.4.4 选数据结构的四条原则

一点四点四节，怎么选数据结构。四条原则。

第一，先分析问题本身，涉及哪些数据类型、数据之间是什么逻辑关系。

第二，数据结构的初步设计通常先于算法设计。结构定了，算法往往水到渠成。

第三，注意可扩展性。输入规模变了、问题演变了，这个结构还撑不撑得住。

第四，比较时空开销的优劣，具体情况具体分析。

回到本章的例子：五个顶点，要的是任意两点最短路，所以相邻矩阵加弗洛伊德是合适的。如果顶点很多、边很少、又只问单源最短路，就该换成邻接表加 Dijkstra。如果数据在外存，还要考虑一次磁盘读写比一次比较贵几个数量级 —— 那是第九章和第十一章反复出现的分界线。

## P46｜本章小结

小结一下。

用计算机求解问题，是一个问题抽象、数据抽象、算法抽象，最后编码实现的过程。
