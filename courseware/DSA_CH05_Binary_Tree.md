## 5.1 二叉树的概念

### 5.1.1 定义和基本术语

**二叉树**（binary tree）由结点的有限集合构成：这个集合**或者为空**，
或者由一个**根**（root）及两棵**互不相交**的、分别称为**左子树**和**右子树**的二叉树组成。

这是一个**递归定义**，它刻画了二叉树的固有特性 —— 子树本身也是二叉树。

> **二叉树的子树有左、右之分，其次序不能颠倒。**

![图 5.1 二叉树的 5 种基本形态](../book/assets/scan/fig-5-1.png)

图 5.1　(a) 空树；(b) 只有一个根结点；(c) 右子树为空；(d) 左子树为空；(e) 左右子树均非空。
**(c) 和 (d) 是两棵不同的二叉树** —— 同样是一个根加一个孩子，挂左边和挂右边不能混为一谈。
第 6 章的一般树没有这个区分，**这正是二叉树不是「度为 2 的树」的原因**。

术语：

- 非根结点都有且仅有一个前驱，称为**父结点**；最多两个后继，称为**左子结点**、**右子结点**；
  同父的结点互称**兄弟结点**。
- 结点的子树数目称为它的**度**。度为 0 的叫**叶结点**，其余叫**内部结点**。
- 若存在结点序列使相邻两个之间都有边，则称存在一条**路径**，边数为**路径长度**。
- 从根到某结点的路径长度称为结点的**层数**：**根为第 0 层**。

### 5.1.2 满、完全、扩充二叉树

- **满二叉树**（full）：任何结点或者是叶，或者左右子树都非空。
  深度为 $k$ 的满二叉树共有 $2^{k+1}-1$ 个结点，叶在同一层。
- **完全二叉树**（complete）：所有叶只出现在**最下两层**，
  且最下层的结点从左到右**连续排列、没有空洞**。
  > **满二叉树一定完全，完全二叉树不一定满。** 堆正是利用这个条件按层编号存进数组。
- **扩充二叉树**（extended）：把每个空子树位置补成一个**外部叶**。
  若原树有 $n$ 个内部结点，则扩充树有 $n+1$ 个外部叶，而且**一定是满二叉树**。

设内部路径长度 $I$ 为根到所有内部结点的边数之和，外部路径长度 $E$ 为根到所有外部叶的边数之和，则

$$E = I + 2n$$

这个关系是最优二叉树和 Huffman 树计算带权路径长度的基础。

### 5.1.3 主要性质

第 $i$ 层至多 $2^i$ 个结点；深度为 $k$ 的二叉树至多 $2^{k+1}-1$ 个结点。
**按层从 0 编号时，结点 $i$ 的父是 $\lfloor(i-1)/2\rfloor$，左右孩子是 $2i+1$ 与 $2i+2$** ——
第 5.5 节的堆全靠这一条。$n$ 个结点的完全二叉树高度为 $\lceil\log_2(n+1)\rceil$。

三条要反复用的：

**性质 3.** 非空二叉树的叶结点数 $n_0$ 等于度为 2 的结点数 $n_2$ 加 1：$n_0 = n_2 + 1$。

> **证明.** 设结点总数 $n$、度为 1 的结点数 $n_1$，则 $n = n_0+n_1+n_2$。
> 换个角度数边：除根之外每个结点都恰好有一条边进入，所以边数 $e = n-1$；
> 而这些边都从度为 1 或 2 的结点射出，所以 $e = n_1 + 2n_2$。
> 两式合起来即得。∎

**性质 4（满二叉树定理）.** 非空满二叉树的**树叶数目 = 分支结点数 + 1**。

> **证明.** 满二叉树里每个结点的度非 0 即 2，即 $n_1 = 0$，由性质 3 直接得到。∎

**性质 5（推论）.** 非空二叉树的**空子树数目 = 结点数 + 1**。

> **证明.** 把所有空子树都换成树叶，得到扩充二叉树 $T'$。$T'$ 是满二叉树，
> 而 $T$ 原来的每个结点在 $T'$ 里都成了分支结点。由性质 4，
> $T'$ 的树叶数 = 分支结点数 + 1 = $T$ 的结点数 + 1。
> 每片新添的树叶恰好对应 $T$ 的一棵空子树。∎

> **性质 5 不是纸面游戏**：它说明一棵 $n$ 个结点的二叉树里有 **$n+1$ 个空指针**。
> 链式存储时这些空指针占的空间和结点本身同阶 ——
> **线索二叉树、Trie 的压缩、第 12 章 PATRICIA 的动机都从这里来。**

## 5.2 二叉树的周游

### 5.2.2 深度优先周游

二叉树的逻辑结构只有三个基本单元：**根结点、左子树、右子树**。
周游一棵树就是安排这三件事的先后。记访问当前结点为 $t$、周游左子树为 $L$、周游右子树为 $R$，
六种排列里**约定「先左后右」**，剩下三种：

| 次序 | 名字 | 递归定义 |
| --- | --- | --- |
| $tLR$ | **前序**（preorder） | 访问根 → 前序周游左子树 → 前序周游右子树 |
| $LtR$ | **中序**（inorder） | 中序周游左子树 → 访问根 → 中序周游右子树 |
| $LRt$ | **后序**（postorder） | 后序周游左子树 → 后序周游右子树 → 访问根 |

![图 5.5 二叉树示例](../book/assets/scan/fig-5-5.png)

图 5.5　根 A；左子树的根 B 有孩子 D 和 E，E 有左孩子 G；右子树的根 C 有右孩子 F，F 有孩子 H 和 I。

| 周游 | 序列 |
| --- | --- |
| 前序 | `A B D E G C F H I` |
| 中序 | `D B G E A C H F I` |
| 后序 | `D G E B H I F C A` |
| 层次 | `A B C D E F G H I` |

**周游把非线性的树摊成一个线性序列**，「前驱」「后继」这类本属于线性结构的说法，
对树才有了意义 —— 但它取决于用的是哪一种周游。
结点 $E$ 在前序里的前驱是 $D$、后继是 $G$；中序里前驱是 $G$、后继是 $A$；
后序里前驱是 $G$、后继是 $B$。**同一个结点，换一种次序就换一批邻居。**

```cpp
template <typename Visitor>
static void preorder_impl(const Node* node, Visitor& visit) {
    if (node == nullptr) return;
    visit(node->value);                 // 根
    preorder_impl(node->left, visit);   // 左
    preorder_impl(node->right, visit);  // 右
}

template <typename Visitor>
static void inorder_impl(const Node* node, Visitor& visit) {
    if (node == nullptr) return;
    inorder_impl(node->left, visit);    // 左
    visit(node->value);                 // 根
    inorder_impl(node->right, visit);   // 右
}
```

三个函数的形状完全一样，只差 `visit` 那一行放在哪里。
**递归在这一章的价值就在这里：代码的形状和定义的形状能一眼对上。**

> 读的时候要把「访问」和「走进去」分清楚 ——
> `visit(node->value)` 是访问，`preorder_impl(node->left, visit)` 是走进去。
> 报错的序列多半来自把这两件事混为一谈。

#### 代价，以及哪些地方不能用递归

每个结点进出各一次，三种周游的**时间都是 $O(n)$**。
**空间是递归深度，等于树高**：平衡时约 $\log_2 n$，退化成一条「藤」时是 $n$。

本书对递归的处理是分开的：

- **周游保留递归为主实现** —— 它就是本节要教的东西，抹掉递归等于抹掉课程内容。
  迭代版作为补充并列给出。
- **析构 `make_empty()` 与深拷贝改成了迭代。** 理由是它们
  **不是教学内容，却会被隐式触发** —— 一次普通的作用域结束、一句 `auto copy = tree;`，
  **调用方根本看不见自己正在递归**。教学价值为零，风险却实打实。

改完之后，纯左链 500 万结点的析构与深拷贝都不再崩（原先分别在 100 万、50 万段错误）；
测试里有一个百万深链的用例专门守着这条，改回递归它就会报 `stack-overflow`。

#### 表达式树：周游的一个用途

三种周游次序不是三种口味，它们各自对应一种实用的表达式写法。
表达式 $A + B \times (C + D)$ 的二叉树表示里，运算符落在内部结点，运算对象落在叶结点，
**括号一个都不出现** —— 树的形状已经把运算次序记下来了。

| 周游 | 得到 | 本例 |
| --- | --- | --- |
| 前序 | **前缀**表达式（波兰式） | `+ A × B + C D` |
| 中序 | 中缀表达式（**缺括号**） | `A + B × C + D` |
| 后序 | **后缀**表达式（逆波兰式） | `A B C D + × +` |

中序那一行值得多看一眼：它和原式长得像，但**括号丢了**，
照它算出来的是 $A + B \times C + D$，已经不是原来的表达式。

> 第 3.1.4 节那个后缀表达式求值器吃的正是这棵树后序周游的结果；
> 那一节把中缀式转成后缀式的工作，换个说法就是「**建出这棵表达式树，再后序周游一遍**」。

### 5.2.3 广度优先周游

深度优先尽量往**深**走，广度优先**一层一层**走：
第 0 层 → 第 1 层从左到右 → 第 2 层……对图 5.5，结果是 `A B C D E F G H I`。

**深度优先靠栈**（写成递归时就是运行栈），**广度优先靠队列**：

```text
把根入队
while 队列非空:
    出队一个结点，访问它
    把它的左孩子（若有）入队
    把它的右孩子（若有）入队
```

这是第 3 章那句「队列是广度优先搜索的主要中间数据结构」的第一次兑现。
第 6、7 章的图搜索用的是同一套骨架，只是要多一个「访问过没有」的标记。

## 5.3 二叉树的存储结构

**链式存储**：结点含三个域 —— 数据域 `info`、左指针 `left`、右指针 `right`。
这样得到的是**二叉链表**；再加一根指向父结点的 `parent`，就是**三叉链表**。

> 二叉链表里找父结点得从根重新走一趟，三叉链表顺着 `parent` 一步就到 ——
> 多一根指针买到的就是这件事。这和第 2 章「双链表多一根 `prev`」是同一种交易。

数一数二叉链表里的空指针：$n$ 个结点恰有 $n+1$ 个空链域（性质 5），
**线索二叉树就是把它们利用起来**。

**顺序存储**：用一组地址连续的单元存结点。
⚠️ **通常情况下，只通过相应位置不足以刻画整个树形结构。**

但对**完全二叉树**例外：从根起自上而下、从左至右把结点从 $0$ 到 $n-1$ 编号，
编号 $i$ 的结点就放在数组下标 $i$ —— 这个线性序列正是**层次周游**的结果。
堆全靠这一条。

## 5.4 二叉搜索树

### 为什么需要它

- **无序线性表**：插入只需放在表末端，但检索慢；
- **有序线性表**：二分检索效率高，但插入删除需要移动大量元素。

很多应用需要一种**插入、删除和检索效率都较高**的组织方法。

**二叉搜索树**（binary search tree，BST）的性质：

- 若左子树非空，则**左子树上所有结点的值均小于**该结点的关键码；
- 若右子树非空，则**右子树上所有结点的值均大于**该结点的关键码；
- 任何结点的左右子树都是二叉搜索树；**关键码必须唯一**。

> **按中序周游整个二叉搜索树，可得到一个由小到大的有序排列。**

![图 5.11 二叉搜索树](../book/assets/scan/fig-5-11.png)

图 5.11　检索 `key` 时把它与根比较：小于就只找左子树，大于就只找右子树，
**每一步都能扔掉一整棵子树** —— 这就是它比无序线性表快的原因。

### 插入

先运用检索方法查找待插入关键码是否在树中；不允许重复。
直到走到空子树还没发现重复，就把新结点插在那个位置作为新的叶结点。

> **它不像在有序线性表中插入元素那样要移动大量数据，只需改动某个结点的空指针。**
> 代价是根到插入位置的路径长度，所以**树形比较平衡时效率相当高**。

实现上用了「**指向指针的指针**」`Node** link`：它指向「新结点该挂在哪根指针上」，
于是「挂到根」和「挂到某个孩子」写成同一句 `*link = new Node{...}`，
**空树不必另开一个分支**。

### 删除：本章最容易写错的一段

要保持性质，就**不能在树中留下一个空位置**，必须找一个结点来填。

**用左子树里最右的那个（中序前驱）顶替被删结点。**
它比左子树其余的都大、比右子树全部都小，顶上来之后「左小右大」原封不动。

> ⚠️ **前驱自己可能还有一个左孩子**，顶替之前必须先把它接走
> （`*predecessor_link = replacement->left;`）。
> 漏了这一句，树上会出现**环** —— 教学版的测试专门搭了一棵这样的树，
> 去掉那句，中序周游立刻无限递归、ASan 报栈溢出。

原书在这里给了两个算法，**本书实现的是后一个**：

- **基本方案（算法5.9）**：把 `temppointer` 的右指针指向被删结点右子树的根，
  然后用左子树的根代替被删结点。它是对的，
  但**把右子树整个下降之后，树的高度可能会增加** —— 删了一个结点，树反而更瘦长了。
- **改进方案（算法5.10）**：先在左子树中找到中序最后一个结点并**把它从树中删除**
  （它没有右子树，删除只需用它的左子树代替它），然后用它代替待删结点。
  **接上去的是同一层的邻居，高度不会凭空长高。**

插入重复键、删除不存在的键都是**可预期状态，返回 `false`**，不抛异常。

## 5.5 堆与优先队列

### 堆是什么

堆是一种**特殊的完全二叉树**：每个结点对应序列中的一个关键码，根对应 $K_0$。
**最小堆**中所有内部结点的值均不大于其左右子结点。

> ⚠️ **堆序只是局部有序** —— 一个结点与其兄弟之间**没有任何必然的联系**。
> 只有当两个结点是**父子关系**时，才能确定它们关键码的大小关系。
> 这一点和二叉搜索树完全不同，**也正是建堆能比排序更快的原因**。

既然是完全二叉树，就用**顺序存储**：下标 `i` 的孩子是 `2i+1` 和 `2i+2`。
这样**既避免了使用指针来保持结构，又能有效地执行相应操作**。

![图 5.14 最小堆对应的完全二叉树](../book/assets/scan/fig-5-14.png)

图 5.14　$K = \{12,14,15,19,20,17,18,24,22,26\}$ 对应的最小堆。根一定是最小的那个。

### 插入、删除与建堆

- **插入**：新元素加到末尾，然后沿祖先路径**自下而上**依次比较和交换 —— 这个过程称为**筛选**。
  要么升到顶端，要么遇到一个更小的父结点就停。
- **删除**：方向相反。把**最末端**的结点填进空位，再**自上而下**与较小的孩子比较交换。
  > ⚠️ `sift_down` 必须**比较左右两个孩子**，只看一个是常见错误。
- **建堆**：把关键码放进数组后并不是堆，但**仅包含叶结点的子树已经是堆** ——
  $i > \lfloor n/2 \rfloor - 1$ 时以 $K_i$ 为根的子树已是堆。
  所以从 $i = \lfloor n/2 \rfloor - 1$ 开始，**从右至左、从下往上**依次下沉。

### 建堆为什么是 $O(n)$ 而不是 $O(n\log n)$

**粗看**这是 $O(n\log n)$：`sift_down` 一次最多走一条树高，是 $O(\log n)$；
非叶结点大约 $n/2$ 个。**原书特意说这只是一个粗略的上界。**

细算要用到一件事：**下沉的代价不是 $\log n$，而是「这个结点到最底层还有多远」**。
**越靠近底层的结点越多，而它们能下沉的距离越短 —— 两者正好互相抵消。**

先把这个堆放大成一棵**满二叉树**。设堆的高度为 $h = \lfloor\log_2 n\rfloor$。
高度同为 $h$ 的满二叉树有 $2^{h+1}-1 \ge n$ 个结点，每一层都排满，
而且每个结点能下沉的距离都不比原堆里对应位置的短，
**所以在这棵满树上算出来的总代价是原堆的一个上界**。

> 这一步是必要的：一般的 $n$ 下堆的最后一层未必满，层数也要取整，
> 直接把「共 $\log n$ 层」当等式用是不严谨的。

满树的第 $i$ 层**恰有** $2^i$ 个结点，其中的结点最多下沉 $h-i$ 层，于是

$$\text{建堆代价} \le \sum_{i=0}^{h} 2^{i}(h-i) = \sum_{j=0}^{h} 2^{h-j} \cdot j = 2^{h}\sum_{j=0}^{h}\frac{j}{2^{j}} < 2^{h} \cdot 2 = 2^{h+1} \le 2n$$

用到 $\sum_{j\ge0} j/2^j = 2$，以及 $2^h \le n$。所以**建堆的时间复杂度是 $O(n)$**。

> **这个结论有实际后果**：第 8.3.2 节堆排序的总代价是 $O(n\log n)$，
> 但那个 $\log n$ **全部来自后面 $n$ 次取最小值，建堆那一步是白送的**。
> 反过来，如果一个个 `insert` 建堆 —— 每次上浮 $O(\log n)$，$n$ 次就是 $O(n\log n)$ ——
> 就把这份便宜丢掉了。

### 5.5.2 优先队列

**优先队列**支持从一个集合中**快速地查找并移出具有最大值或最小值的元素**。

应用：操作系统用它实现等候进程的**调度管理**（优先级越高值越小）；
打印机的**输出任务队列**（先打印页数少的任务）。

| 实现 | 插入 | 取最小 |
| --- | --- | --- |
| 无序线性表 | $O(1)$ | $O(n)$ |
| 有序线性表 | 要移动元素 | $O(1)$ |
| **堆** | $O(\log n)$ | 查看堆顶 $O(1)$，移除 $O(\log n)$，**建堆 $O(n)$** |

> ⚠️ **最小堆只适合查找最小值，查找任意值的效率不高** ——
> 它没有二叉搜索树那样的全序，找一个中间大小的关键码只能线性扫描。
> **这正是第 10 章要另起炉灶讲检索的原因。**

若应用要求相同优先级保持到达顺序，还要把**到达序号作为第二关键码**显式存入元素。

## 5.6 Huffman 树及其应用

同样是四个权为 6、2、3、4 的外部结点，树的形状不同，**带权外部路径长度**（WPL）就不同：

![图 5.18 具有不同带权外部路径长度的二叉树](../book/assets/scan/fig-5-18.png)

图 5.18　(a) $6{\times}2+2{\times}2+3{\times}2+4{\times}2 = 30$；
(b) $6{\times}2+2{\times}3+3{\times}3+4{\times}1 = 31$；
(c) $6{\times}1+2{\times}3+3{\times}3+4{\times}2 = 29$。
(c) 最小，它就是这组权值的 **Huffman 树** —— **权越大的叶离根越近，总长就越小**。

### 构造

$n$ 个权各自成为一棵单结点树；**每次挑出根权最小的两棵**，
合成一棵新树、新根的权是两者之和；重复 $n-1$ 次，集合里只剩一棵。
根的权等于全部叶子权之和。

> **为什么用堆**：每一轮都要「取当前最小的两棵」。
> 用数组线性扫是 $O(n)$ 一轮、总共 $O(n^2)$；用最小堆是 $O(\log n)$ 一轮、总共 $O(n\log n)$。
> 这就是 5.5 节那个数据结构在本节的兑现 —— **数据结构选对了，算法的阶就变了**。

### 5.6.2 Huffman 编码

**问题从哪来。** 要传电文 `abbaaadc`。定长编码给每个字符 2 位，总共 16 位。
想更短，就得让**出现次数多的字符用更短的码**。
比如 a=0, b=1, c=01, d=10，电文变成 10 位 —— **但这样的电文没法译码**：
收到 `011`，既可以读成 a b b，也可以读成 c b。

**症结是「前缀」。** `0` 是 `01` 的前缀，所以读到 `0` 时无法判断该停还是该再读一位。
解决办法是要求任何字符的编码都不是另一个字符编码的前缀 —— 这种编码叫**前缀码**。

**Huffman 树天然给出前缀码。** 从每个结点引向**左**孩子的边标 0、引向**右**孩子的边标 1，
从根走到某个叶子，一路的 0/1 连起来就是那个字符的编码。

> 为什么一定无前缀冲突？因为**字符只住在叶子上**，
> 而一个叶子不可能出现在另一个叶子的路径上。

以 `abbaaadc` 为例，频率是 a×4、b×2、c×1、d×1：

| 字符 | 频率 | 编码 | 位数 |
| --- | --- | --- | --- |
| a | 4 | `0` | 1 |
| b | 2 | `10` | 2 |
| c | 1 | `110` | 3 |
| d | 1 | `111` | 3 |

电文编成 **14 位**，比定长的 16 位短。

> **注意 14 正好等于这棵树的 WPL** —— 这不是巧合：
> WPL 是 $\sum(\text{权}\times\text{深度})$，而权就是出现次数、深度就是码长，
> 两者算的是同一个和。
> 所以「Huffman 树让 WPL 最小」翻译过来就是「**它让这段电文的编码总长最短**」。

**译码用的是同一棵树**：从根出发，读 0 走左、读 1 走右，走到叶子就吐出一个字符，
然后回到根接着读。前缀码保证这个过程不会有歧义。

三处边界，测试各有一条用例守着：

- **比特串走到一半就没了** → 返回空 `optional`，而不是吐出半个字符；
- **出现既不是 0 也不是 1 的字符** → 同样返回空 `optional`；
- **整棵树只有一个字符**：从根到叶的路径是空串，那样的编码根本没法传。
  本书约定给它一位 `"0"`。

> **一个反直觉的结论：如果所有字符频率相同，Huffman 一位都省不下来。**
> 8 个等权字符建出的是一棵平衡树，每个字符恰好 3 位 —— 退化成定长编码。
> **压缩的收益完全来自频率的不均匀。**

## 本章小结

- **二叉树的定义是递归的**，左右有别；5 种基本形态，(c) 与 (d) 是两棵不同的树。
- **性质 5**：$n$ 个结点的二叉树有 $n+1$ 个空指针 —— 后面几章的多个技巧都源于此。
- **三种深度优先周游**只差 `visit` 放在哪一行；时间 $O(n)$，空间等于树高。
  周游保留递归（那是课程内容），**析构与深拷贝改迭代**（会被隐式触发）。
- **二叉搜索树**：左小右大，中序周游得到有序序列；删除用**中序前驱**顶替。
- **堆**：完全二叉树 + 顺序存储 + **局部有序**；建堆 $O(n)$，取最小 $O(\log n)$。
- **Huffman 树**让 WPL 最小，等价于让电文的编码总长最短；前缀码保证译码无歧义。

### 补充证明题

**补充 1.** 判断「先序和后序遍历序列总能唯一确定二叉树」是否成立；若不成立给出**最小反例**。

> **答：不成立。** 最小反例是两个结点：根 A 加一个孩子 B。
> 挂左边和挂右边，先序都是 `A B`、后序都是 `B A`，但它们是两棵不同的树（图 5.1 的 (c) 与 (d)）。
> **根因**：先序告诉你根在哪，后序也告诉你根在哪，但**没有任何一个序列告诉你左右子树的分界**。
> 中序恰好提供了这个分界（根左边是左子树，右边是右子树），所以
> **先序 + 中序、后序 + 中序都能唯一确定，先序 + 后序不能。**

**补充 2.** 设计 $O(n)$ 算法检查数组是否为大顶堆，说明为什么只需检查每个非根结点与父结点的关系。

> **答**：对每个下标 $i \ge 1$ 检查 `a[i] <= a[(i-1)/2]`，全部成立即为大顶堆，一趟 $O(n)$。
> **为什么够**：堆的定义只约束父子关系，兄弟之间没有要求；
> 而「每个非根结点都不大于其父」正是把所有父子对都检查了一遍 —— 不多也不少。

**补充 3.** 证明含 $n$ 个结点的满二叉 Huffman 树叶子数为 $(n+1)/2$。

> **答**：满二叉树里 $n_1 = 0$，由性质 3 得 $n_0 = n_2 + 1$；
> 又 $n = n_0 + n_2 = 2n_0 - 1$，故 $n_0 = (n+1)/2$。

### 正文习题

**1.** 画出含 3 个结点的二叉树的所有不同形态。

> **答：5 种。** 按根的左右子树结点数分：(0,2)、(1,1)、(2,0)。
> (1,1) 只有 1 种；(0,2) 和 (2,0) 各有 2 种（那 2 个结点自身有两种形态）。
> 这个数正是 Catalan 数 $C_3 = 5$。

**2.** 先序 `ABCDEFG`、中序 `CBDAFEG`，画出这棵树并写出后序。

> **答**：先序首字符 A 是根；中序里 A 左边 `CBD` 是左子树、右边 `FEG` 是右子树。
> 递归下去：左子树先序 `BCD`、中序 `CBD` → 根 B，左孩子 C，右孩子 D；
> 右子树先序 `EFG`、中序 `FEG` → 根 E，左孩子 F，右孩子 G。
> **后序是 `C D B F G E A`。**

**3.** 证明：有 $n$ 个结点的二叉树，空指针域的个数是 $n+1$。

> **答**：见性质 5 的证明。也可以直接数：$n$ 个结点共 $2n$ 个指针域，
> 其中 $n-1$ 个用于指向非根结点（每个非根结点恰好被一根指针指到），
> 故空的有 $2n - (n-1) = n+1$ 个。

**4.** 完全二叉树按层编号，写出结点 $i$ 的父、左孩子、右孩子公式并证明。

> **答**：父 $\lfloor(i-1)/2\rfloor$，左孩子 $2i+1$，右孩子 $2i+2$。
> 证明用归纳：第 $k$ 层的第一个结点编号是 $2^k - 1$，该层共 $2^k$ 个；
> 第 $k$ 层第 $j$ 个（0 起）的两个孩子在第 $k+1$ 层的第 $2j$、$2j+1$ 个，代入即得。

**5.** 写出层次周游的算法，并说明为什么需要队列。

> **答**：根入队；循环出队一个、访问、把左右孩子入队。
> **为什么是队列**：层次周游要求「先到先访问」——
> 第 $i$ 层的结点都比第 $i+1$ 层先被发现，也必须先被访问，这正是 FIFO。
> 换成栈就变成了某种深度优先。

**6.** 依次插入 50, 30, 70, 20, 40, 60, 80，画出 BST；再删除 50。

> **答**：得到的是一棵满的三层树，根 50，左 30（孩子 20、40），右 70（孩子 60、80）。
> 删除根 50 时，按**改进方案**用左子树最右的结点（**40**）顶替：
> 先把 40 从原位摘下（它没有右子树，用它的左子树 —— 这里为空 —— 代替它），
> 再让 40 继承 50 的两棵子树。结果根是 40，左 30（只剩左孩子 20），右 70 不变。

**7.** 对权 2, 3, 4, 7, 8 构造 Huffman 树，计算 WPL，并给出一组前缀编码。

> **答**：合并过程 2+3=5 → 4+5=9 → 7+8=15 → 9+15=24。
> 深度：8 和 7 各 2 层，4 是 3 层，2 和 3 各 4 层。
> $\text{WPL} = 8{\times}2 + 7{\times}2 + 4{\times}3 + 3{\times}4 + 2{\times}4 = 16+14+12+12+8 = 62$。
> 一组前缀编码（左 0 右 1）：`8→10`、`7→11`、`4→01`、`2→000`、`3→001`。
> ⚠️ 编码不唯一（左右可以整体互换），但**WPL 是唯一的**。

### 原书习题选做

**原书 3.** 命题：叶结点在前序、中序、后序序列中都按相同的相对位置出现。

> **答：真。** 三种周游都遵守「先左后右」，而叶结点之间没有祖先关系，
> 它们的先后完全由「谁在更左的子树里」决定 —— 这一点三种周游是一致的。

**原书 4.** 找出结点在下列两种次序下顺序相同的所有二叉树。

> **答**：(1) 前序 = 中序 ⟺ **每个结点都没有左子树**（右斜的藤）；
> (2) 前序 = 后序 ⟺ **树中至多一个结点**；
> (3) 中序 = 后序 ⟺ **每个结点都没有右子树**（左斜的藤）。

**原书 8.** 给定 $p$、$q$、$rt$，求 $p$ 与 $q$ 最近的共同祖先。

> **答**（无父指针时）：递归。若 `rt` 为空或等于 `p` 或 `q`，返回 `rt`；
> 否则分别在左右子树里递归求解 —— 两边都非空说明 `p`、`q` 分居两侧，答案就是 `rt`；
> 只有一边非空就返回那一边。时间 $O(n)$、空间 $O(h)$。

**原书 19.** 对 $\{E, D, X, K, H, L, M, C, P\}$ 用筛选法建最小堆，数移位次数。

> **答**：$n = 9$，从下标 $\lfloor 9/2 \rfloor - 1 = 3$ 开始倒着下沉。
> 数移位时按题目提示：**一次交换算 3 次移位**（两次读、一次写的等价计数）。
> 建议做法是把每一步的数组状态写出来再数，不要凭印象 —— 这道题考的就是耐心。

## 上机题与参考实现

**表达式二叉树。** 读入一种表达式，在机内建出这棵树，再按要求输出另外两种。

- **读后缀建树**最简单：遇操作数就 `push` 一个叶结点；遇操作符就 `pop` 两个作为右、左孩子，
  合成一个新结点再 `push`。**注意先弹出的是右孩子** —— 与第 3 章后缀求值同一个坑。
- **读中缀建树**要处理优先级和括号，等价于「先转后缀，再按上面那步建树」。
- 输出前缀 / 后缀就是前序 / 后序周游；
  **输出中缀必须按优先级补括号**，否则拿回来的不是原式。

**Huffman 文件压缩。** 把编码器扩展成能压缩文件，还要再加两步：
**把码表本身也写进输出**（否则解压方不知道怎么译），
以及**处理最后不足一字节的那几位**（通常在文件头记下有效位数）。
