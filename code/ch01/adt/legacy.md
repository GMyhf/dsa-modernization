# 第1章抽象数据类型

## 原书逐条核对

- 【算法1.1】以邻接矩阵保存经纪人间的有向边，先调用 Floyd，再选每行最大最短路最小的起点。
- 【代码1.2】给出 ADT 的 C++ 模板，意图是把数据对象、关系和操作封装成可替换实现。
- 原算法以 `cout` 报告不连通并以 `-1` 传递失败；现代接口返回 `std::optional<std::size_t>`，
  使没有可传播源成为调用者可判定的正常结果。
- 现代 `RumorNetwork` 不暴露邻接矩阵，也不接受控制台输入，便于用小图对拍 Floyd 的选择结果。
- 重边保留较小权值；负边拒绝，因为本章的 Floyd 示例没有定义负环语义。

## OCR 与编译证据

原书算法块含有 C++ 无法接受的 OCR 间隔，例如 `i + +`、`G. VerticesNum( )` 和
`if (min = = INFINITY)`。最小复现：

```text
$ printf 'int main(){ int i=0; i + +; }\n' | g++ -std=c++17 -x c++ -
<stdin>:1:25: error: expected primary-expression before ';' token
```

原稿的 `int * * D;` 未分配矩阵即传给 `Floyd(G, D)`；即使 OCR 修复，输出参数的所有权也
没有说明。原算法还在循环内混用未重新声明的 `i`，并有孤立的 `1` 作为缺失花括号标记。

## 验证边界

### 关于「原书样例自相矛盾」——这个说法不成立，已撤回

本单元第一版曾断言：按印出的矩阵，B1 与 B5 的最大最短路均为 8，
因此算法应返回 B1，与正文声称的 B3 矛盾。**这个结论是错的**，原因是把
OCR 损伤当成了原书内容。Claude 复核时否掉了它（2026-08-12），依据有三：

1. **`8` 是 OCR 把 `∞` 认错的产物。** 同一张表里第 2、4 行**残留着真正的 `∞`**，
   其余位置却是 `8`——同一个符号在同一张表里两种呈现，只能是 OCR 不稳定。
   `CLAUDE.md` 的「OCR artifacts」一节从一开始就记着这条：
   *frequently garbled cells (`8` for `∞`)*。

2. **原书正文明写这些格子是 ∞**（`dsa_raw.md:571`）：

   > 从顶点 B₁、B₂、B₄、B₅ 出发到其他各顶点的最短路径中最大值均为∞，
   > 而从 B₃ 出发的最长的最短路径为10

3. **选起点用的根本不是那张表。** 算法读的是**图1.3**（Floyd 的输出矩阵），
   而图1.3 在底稿里是一张**图片**（`![](...c398712d....jpg)`），
   内容从未被 OCR 过。第一版拿图1.2 的输入矩阵去算，连矩阵都取错了。

按正文还原（`8` 处为 ∞ 即无边）重新验算：B2、B4 没有出边；B1 只到 B4(4)、B5(3)，
到不了 B3；B5 只到 B1(5)、B2(5)，到不了 B3；**只有 B3 能到达全部顶点，
最大最短路 = 10**。与正文完全一致，也与正文另一处旁证吻合——
「B₅ 到 B₄ 需经过 B₁，顶点序列 B₅B₁B₄」，5 + 4 = 9。

**原书这个样例是对的、自洽的。** 测试断言已改为 B3（下标 2）。

这条记在这里不是为了记一次错，而是为了记住红线 #1 的用处：
`dsa_raw.md` 只读、逐条采证，为的就是任何时候都能分清
「原书的错」与「OCR 的错」。这次差一点把后者当成前者印进书里。另覆盖重边、空图、
单点、非连通图、负权和越界。Floyd 的三重循环是教学保留，输入规模很大时有 O(n^3) 时间与
O(n^2) 空间成本。
