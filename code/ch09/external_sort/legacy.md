# 第9章外部排序

## 原书逐条核对

- 【算法9.1】置换选择以最小堆选择当前最小关键码，把**小于刚输出值**的新记录冻结到下一顺串。
  原书正文（`dsa_raw.md:8272`）写得很清楚：新记录 `R ≥` 刚输出值才进当前堆，否则用堆底顶替根、缩小堆。
- 【代码9.2】赢者树支持初始化、取得最终赢家和从变化选手到根的重赛。内部结点保存胜者下标。
- 【代码9.3】败者树把每轮失败者留在内部结点，另用一个冠军槽记录全局赢者。

## 现代实现曾经做错什么

2026-08-12 的第一版 `replacement_selection` **把整份输入推进一个堆再依次弹出**，
返回的是一条完全有序序列。那是堆排序，不是置换选择：

- 原书图 9.2 的输入 `50 49 35 45 30 25 15 60 16 27 1`、工作区 `M = 7`，
  第一顺串应长于 7（冻结 `16, 27, 1`，放进 `60`），而不是一条长度为 11 的总排序。
- 旧测试只断言 `{3,1,2} → {1,2,3}`，堆排序也能过，所以闸门一直绿。
- `WinnerTree` 与 `LoserTree` 是同一个类型的别名，败者树的「内部结点记败者」从未实现。

2026-08-13 已按正文重做：`replacement_selection(input, memory)` 返回若干顺串；
赢者树与败者树拆成两个类。文件 I/O 与页缓冲仍由上层负责，这里只抽算法。

## OCR 与编译证据

【代码9.2】原稿的类声明存在 `int * tree;`、`int * player;` 的裸数组所有权，析构、复制和
赋值的规则未给出。OCR 中还有 `if (n < 2) return;` 后缺失分支边界，不能逐字作为实现。

原稿【代码9.3】把成员声明识别成 `int lowExt, offset;` 与间隔化的 `B[ p/2]`；最小 OCR 片段
中的孤立 `1` 无法编译：

```text
$ printf 'int main(){ int value = 0; 1 }\n' | g++ -std=c++17 -x c++ -
<stdin>:1:30: error: expected ';' before '}' token
```

【算法9.1】印刷代码把 `else` 写成与 `if` 不对齐，OCR 把 `}` 认成 `1`，且 `last ! = 0` 被拆开：

```text
$ printf 'void f(int last){ if (last ! = 0) {} }\n' | g++ -std=c++17 -x c++ -
<stdin>:1:27: error: expected ')'
```

## 验证边界

测试覆盖原书图 9.2 的两趟顺串（第一趟长度 8 > M=7）、空/单元素、递减输入必须冻出多趟、
零内存抛异常、赢者树与败者树各自的平局/重赛/非法选手。实现没有调用
`std::sort`、`std::make_heap` 或 `std::sort_heap`。本实现不模拟磁盘块耗尽和多路文件
归并；这些外部 I/O 策略须在拥有文件句柄的上层另行实现。
