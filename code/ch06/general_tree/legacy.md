# 第6章树

## 原书逐条核对

- 【代码6.1】以孩子-兄弟表示法给出树结点，并把根保存为裸指针；复制、释放和异常路径都需要手工维护。
- 【代码6.2】树容器同时承担根创建、复制、赋值和销毁职责。原版赋值没有明确自赋值与异常安全边界。
- 【算法6.3】先根周游先访问结点，再递归处理孩子和兄弟。
- 【算法6.4】后根周游先递归处理孩子和兄弟，再访问结点。
- 【算法6.5】层次周游使用队列，空树不应解引用根指针。
- 【代码6.6】插入第一个孩子和插入下一个兄弟都必须同步维护 `parent`、`child`、`sibling` 三条链接。
- 【代码6.7】切除子树必须先把结点从父孩子链或根兄弟链脱开，随后才能销毁；否则父树保留悬垂指针。
- 【代码6.8】并查集的数组父指针以根自身为哨兵，合并同集合应是无副作用失败。结点里那个
  `int nCount; //子树元素数目` 是为**重量权衡合并规则**准备的（底稿第 5275 行：
  「令含元素少的子集的树根指向含元素多的子集的根」）。
- 【算法6.9】`find` 沿父链寻找根，并在返回时压缩路径；实现会写入父数组，故不能错误标为逻辑 `const`。
- 【算法6.10】**带双标记位先根次序树构造算法**（底稿第 5420 行）：从 `(info, ltag, rtag)`
  的先根序列重建「左子/右兄」链表。用栈记住那些 `rtag == 0`、还等着接右兄弟的结点；
  扫到 `ltag == 1`（没有孩子，子树到头）就弹一个出来接上。

## OCR 与编译证据

原稿【代码6.6】把声明识别为 `T m_ Value;`，其中的空格使声明不能通过 C++ 编译：

```text
$ printf 'int main(){ int m_ Value = 0; }\n' | g++ -std=c++17 -x c++ -
<stdin>:1:20: error: expected initializer before 'Value'
```

原稿【代码6.8】的析构函数波浪号与相邻标识符存在 OCR 粘连风险，不能直接照抄为现代 C++。

### 缺陷 4：【算法6.10】对空栈取顶

原书的构造算法在 `ltag == 1` 分支里直接写 `pointer = aStack.top(); aStack.pop();`，
**没有判空**。标志位不自洽的输入（例如两个结点都声称「没有孩子、没有兄弟」）会让它
对空栈取顶，那是未定义行为。用 libstdc++ 复现：

```text
$ g++ -std=c++17 -O1 -g -fsanitize=address,undefined -fno-sanitize-recover=all probe.cpp
$ ./a.out
/usr/include/c++/13/bits/stl_iterator.h:1158:45: runtime error:
    applying non-zero offset 18446744073709551615 to null pointer
```

（上面这段正是把现代实现里的判空去掉之后跑出来的，见本单元变异自检。）
现代实现改为抛 `std::invalid_argument`，并另加一条「末结点仍声称有孩子」的收尾检查。

### 一处曾经写错的归属，记在这里

本文件此前把【算法6.10】记成「按秩合并把较矮树挂到较高树下」——**那不是算法6.10**。
底稿第 5420 行写得清楚，算法6.10 是带双标记位先根次序树构造算法；而且当时
`modern.hpp` 里根本没有实现它，台账却把它算进了「已覆盖」。
2026-08-16 由课程课件（`ref_数据结构与算法A 2021秋/第6章 树.ppt`）对照发现并补实现。
【算法6.3】、【算法6.4】、克隆和递归销毁都保留递归教学写法；极深退化树存在 Stack Overflow Risk。

## 现代化取舍与验证

`GeneralTree` 仍用内部 `Node*` 表达孩子-兄弟关系，但由容器独占并以析构、复制构造、复制赋值、移动构造和移动赋值覆盖所有权转移。`delete_subtree` 对森林的非首根也沿根兄弟链寻找，避免对空 `parent` 解引用。测试覆盖三种周游、兄弟根的首尾删除、深复制、自赋值、移动、空指针拒绝、清空、路径压缩、重量权衡合并和越界，以及【算法6.10】的序列还原、父指针接法与三种不自洽输入。

**合并规则按原书口径，不用按秩**：按秩比树高、按重量比元素个数，两者在同一组等价对上会长出不同形状的树。实测（本单元变异自检）：把实现换成按秩之后，「规模 3 的集合与规模 2 的集合合并，根应是前者」这条断言当场变红。课程第 6 章习题 8 要求「使用重量权衡合并规则与路径压缩」并画出父指针数组，按秩会让读者对不上答案。并列时的口径（值大的根挂到值小的根下）也取自该题原话。

本机 AddressSanitizer 初始化在 `sanitizer_malloc_mac.inc:189` 退出，故本批只完成 Release 运行；内存和 UB 检查未得到 ASan 覆盖，析构、克隆失败回滚、局部子树切除是最脆弱的三条析构路径。
