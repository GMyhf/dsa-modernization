# 第6章树

## 原书逐条核对

- 【代码6.1】以孩子-兄弟表示法给出树结点，并把根保存为裸指针；复制、释放和异常路径都需要手工维护。
- 【代码6.2】树容器同时承担根创建、复制、赋值和销毁职责。原版赋值没有明确自赋值与异常安全边界。
- 【算法6.3】先根周游先访问结点，再递归处理孩子和兄弟。
- 【算法6.4】后根周游先递归处理孩子和兄弟，再访问结点。
- 【算法6.5】层次周游使用队列，空树不应解引用根指针。
- 【代码6.6】插入第一个孩子和插入下一个兄弟都必须同步维护 `parent`、`child`、`sibling` 三条链接。
- 【代码6.7】切除子树必须先把结点从父孩子链或根兄弟链脱开，随后才能销毁；否则父树保留悬垂指针。
- 【代码6.8】并查集的数组父指针以根自身为哨兵，合并同集合应是无副作用失败。
- 【算法6.9】`find` 沿父链寻找根，并在返回时压缩路径；实现会写入父数组，故不能错误标为逻辑 `const`。
- 【算法6.10】按秩合并把较矮树挂到较高树下，秩相同才增加新根的秩。

## OCR 与编译证据

原稿【代码6.6】把声明识别为 `T m_ Value;`，其中的空格使声明不能通过 C++ 编译：

```text
$ printf 'int main(){ int m_ Value = 0; }\n' | g++ -std=c++17 -x c++ -
<stdin>:1:20: error: expected initializer before 'Value'
```

原稿【代码6.8】的析构函数波浪号与相邻标识符存在 OCR 粘连风险，不能直接照抄为现代 C++。
【算法6.3】、【算法6.4】、克隆和递归销毁都保留递归教学写法；极深退化树存在 Stack Overflow Risk。

## 现代化取舍与验证

`GeneralTree` 仍用内部 `Node*` 表达孩子-兄弟关系，但由容器独占并以析构、复制构造、复制赋值、移动构造和移动赋值覆盖所有权转移。`delete_subtree` 对森林的非首根也沿根兄弟链寻找，避免对空 `parent` 解引用。测试覆盖三种周游、兄弟根的首尾删除、深复制、自赋值、移动、空指针拒绝、清空、路径压缩、按秩合并和越界。

本机 AddressSanitizer 初始化在 `sanitizer_malloc_mac.inc:189` 退出，故本批只完成 Release 运行；内存和 UB 检查未得到 ASan 覆盖，析构、克隆失败回滚、局部子树切除是最脆弱的三条析构路径。
