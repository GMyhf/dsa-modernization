# 原书写法 → 问题 → 现代写法：代码7.4 用邻接表存储图

原文范围 `dsa_raw.md:6001-6102`。

## 这个单元为什么单独存在

**代码7.4 原先被 `code/ch07/graph` 认领着，但那个单元只实现了邻接矩阵。** 它的 `legacy.md`
写的是「代码7.3/7.4 的矩阵和邻接表语义由 `add_edge` 的有向/无向选择承载」——这句话不成立：
代码7.4 是**存储结构**，和有向/无向没有关系。台账因此把一条根本没实现的清单记成了「已现代化」，
正是 D-007 要堵的「结构合规、内容为空」。

本轮把代码7.4 的认领移到这里，并真的实现出来。`code/ch07/graph` 的 listings 相应减一，
105 的等式不变。

## 原书可复核问题

**先分清哪些是 OCR 损伤、哪些是原书的。** 底稿里 `}` 被认成 `1`、`*` 被写成 `\*`、
`temp − > next` 这类空格分裂，都按 CLAUDE.md 的规定当作 OCR 修掉，**不计入原书缺陷**。
下面四条里，前两条无法从底稿断定是排版还是原书，如实标注；后两条与排版无关。

1. **`struct listUnit` 没有右花括号**（可能是 OCR）。按印刷原样：

   ```text
   $ g++ -std=c++17 -fsyntax-only listunit.cpp
   error: expected ‘}’ at end of input
   note: to match this ‘{’
   ```

2. **`class Graphl: public Graph` 后面直接跟 `private:`，缺 `{`**（可能是 OCR）：

   ```text
   $ g++ -std=c++17 -fsyntax-only graphl.cpp
   error: expected ‘{’ before ‘private’
   error: expected unqualified-id before ‘private’
   ```

3. **整份清单里没有任何析构函数，邻接表一路泄漏。** 这条与排版无关：
   `Graphl` 的构造函数写了 `graList = new LList<listUnit>[numVertex]`，
   而清单 6001–6102 行内**唯一**的 `delete` 出现在「从边表中删除一个结点」那一句，
   既没有 `~Graphl`、也没有 `~LList`、`~Link`。于是每建一个图对象，
   整个边表数组连同所有边结点都收不回来。第 2 章的链表已经把「谁来释放」讲过一遍，
   这里又退回去了。

4. **`Link` 的第二个构造函数不初始化 `element`。**

   ```cpp
   Link(Link* nextval = NULL) { next = nextval; }   // element 一个字都没写
   ```

   `LList` 的构造函数正是用它建头结点（`head = new Link<Elem>()`）。于是头结点的
   `element.vertex` / `element.weight` 是未初始化的。**实测 `-Wall -Wextra` 给出 0 条警告**，
   而读出来是不是垃圾值取决于分配器当时给了哪块内存——**不稳定复现，正是它难查的原因**。
   这与第 3 章 `arrStack` 未初始化 `mSize` 是同一类问题。

## 现代实现

- **每个顶点一条边表**（`std::vector<Edge>`），只存实际存在的边。原书用的是链式边结点；
  本章要教的是**存储方式的取舍**（$V^2$ 对 $V+E$），不是链式结点怎么串——那是第 2 章的内容，
  已经讲过，不必再演一遍。这条写进了 `unit.json` 的 `d001_exceptions`。
- **加边覆盖而非并存**：重复加同一条 `from→to` 时覆盖权值，与邻接矩阵同语义。
  这是为了让两种表示法能**逐项对拍**；代价是每次加边 O(deg from)，如实写在接口注释里。
- **Dijkstra 与 Prim 换成最小堆**：邻接表 + 堆是 $O((V+E)\log V)$，
  而矩阵版每轮扫全部顶点找最近点是 $O(V^2)$。稀疏图上这才是该用的组合。
- **`scan_steps()` / `storage_cells()` 是教学接口**，把复杂度差别变成可断言的数字，
  而不是停留在「邻接表更省」这句话上。

## 验证边界

- **156 项断言**，`-Werror` + ASan/UBSan 与 `-O2` 双档通过。
- **与邻接矩阵逐项对拍**：DFS / BFS 序列、拓扑序、Dijkstra 距离向量逐项相等；
  外加 **30 轮随机图**对拍（固定种子 20260814，失败可复现）。
  MST 只断言**总权相同**——最小生成树可能不唯一，断言具体边集会是假强度。
- **对拍要求加边次序按 `to` 升序**，否则邻接表的遍历次序与矩阵的「从 0 扫到 V−1」不同，
  DFS/BFS 的访问顺序会不一样（**两者都对**，只是不可逐项比）。测试里对此有注释说明。
- 存储与代价的差别是**量出来的**：1000 个顶点的链，BFS 只检查 999 条边，
  而矩阵版必须扫 $V^2 = 10^6$ 格。
- **不在范围内**：没有实现十字链表、邻接多重表；没有删边接口；
  `weight(u,v)` 是 $O(\deg u)$ 的线性查找——这正是邻接表相对矩阵**吃亏**的地方，
  如实保留，不用哈希表掩盖掉。
- `dfs` 仍是递归实现，与矩阵版一致；深度正比于最长路径，病态长链上有栈风险，
  与第 5 章递归周游同源，本单元没有实测数字。
