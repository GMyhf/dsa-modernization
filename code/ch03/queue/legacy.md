# 第3章队列

## 原书逐条核对

- 【代码3.13】顺序队列以数组、前端和后端下标表示 FIFO；原版的出队通过出参和 `bool` 表示。
- 【代码3.14】循环队列用牺牲一个槽位区分空和满：`front == rear` 为空，后端下一格等于前端为满。
- 【代码3.15】链式队列维护 `front` / `rear` 指针；最后一个结点出队时两者都必须置空。
- 现代 `ArrayQueue` 保留原书循环数组策略，容量为 n 时实际申请 n+1 个槽位，代价是少一个可用槽。
- 空队列是预期状态，`dequeue()` 返回 `std::optional<T>`；插入满队列返回 `false`。
- `LinkedQueue` 补齐析构、深复制、copy-and-swap、自赋值和移动，避免默认浅复制造成双重释放。

## OCR 与编译证据

原书代码3.13 的接口文字把参数写成指针，函数实现却把它当普通对象操作；相同形式若直接编译，
解引用与成员访问不匹配：

```text
$ printf 'struct Q { bool dequeue(int* out) { out = 1; return true; } };\n' | g++ -std=c++17 -x c++ -
<stdin>:1:45: error: invalid conversion from 'int' to 'int*' [-fpermissive]
```

代码3.14 的 OCR 在模运算附近出现 `rear + 1) % maxSize` 缺左括号、`rear = (rear + 1) %`
的断行；修复排版后保留其牺牲一个槽位的算法逻辑。代码3.15 的原始类有析构和裸结点指针，
却没有复制构造或复制赋值；默认复制会共享链结点，两个析构函数随后释放同一条链。

原书容器方法直接 `cout` 输出“队列为空”，使数据结构与交互 I/O 绑定；现代版本返回状态，
由调用方决定展示方式。`int` 下标在超大容量和负值转换时也不适合作为现代数组索引，改用
`std::size_t`。

## 验证边界

测试覆盖空/满、牺牲槽位、满时长度不变、FIFO、排空、前后下标各连续绕环至少九次、数组队列
深复制和自赋值、链式队列深复制/独立变异、清空及移动。macOS ASan 空探针仍在
`sanitizer_malloc_mac.inc:189` 退出，故本机只有 Release 结果；链结点析构和复制异常路径待
可用 sanitizer 环境补跑。
