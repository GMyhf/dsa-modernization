# 原书写法 → 问题 → 现代写法：链式栈

覆盖清单：**代码3.4**（栈的链式实现）。原文见 `dsa_raw.md:1935`。

## 一、缺陷清单与证据

### 缺陷 1（致命）：`Link<T>* top` 与 `bool top(T&)` 重名

与代码3.2 的 `arrStack` 是**同一处错误**（那里是 `int top`）。整个类编译不过：

```console
$ g++ -std=c++17 -c l1.cpp
l1.cpp:12:85: error: ‘bool lnkStack<T>::top(T&)’ conflicts with a previous declaration
```

同一本书在两个存储结构的实现里犯了同一个命名错误，**两处都没有被编译器验证过**。
D-001 第 4 条把「消除成员变量与成员函数重名」列为红线，起因正是这一类。

### 缺陷 2（未定义行为）：有析构却没有拷贝构造/拷贝赋值

`~lnkStack(){ clear(); }` 会逐个 `delete` 结点，而编译器生成的浅拷贝让两个栈
共享同一串结点。这是本书第**五**次遇到同一个错误
（顺序栈、顺序表、链表、字符串、链式栈）。
变异验证：把现代实现的拷贝构造改回共享指针，ASan 报 `heap-use-after-free`。

### 缺陷 3：构造函数的 `defSize` 参数从未被使用

```cpp
lnkStack(int defSize){ top = NULL; size = 0; }
```

链式栈**不需要预设容量**——这正是它相对顺序栈的核心差别。
这个参数是从 `arrStack(int size)` 照抄过来的，形式上还在，语义上是空的；
而且因为没有默认构造函数，用户被迫为一个无意义的参数编个数出来。

### 缺陷 4：容器里 `cout`

`pop`/`top` 失败时打印中文提示。与前几章同一个毛病。

### 缺陷 5：`bool pop(T& item)` 双通道返回、`int size` 有符号

与全书其余部分一致的接口问题，按 D-001 §3c 改为 `std::optional<T>`。

## 二、刻意保留的东西

- 结点仍由**裸指针**串联、手工 `new`/`delete`：这是本节的教学内容；
- 压栈仍然只是"接一个新结点"，**没有"栈满"这回事**——
  这正是与顺序栈对照的落点，`test_no_capacity_limit` 用 20 万次压栈钉住它。

## 三、一处刻意的实现选择：`clear()` 与析构都是迭代的

链式结构最自然的写法是递归释放，但深链会爆栈——第 5 章有实测数字
（`collab/UNVERIFIED-RISKS.md` 第一节）。这里用 `while` 逐个摘除，
20 万结点的测试就是为这条兜底。拷贝构造同理，用尾插而非递归。
