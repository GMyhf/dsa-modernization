# 原书写法 → 问题 → 现代写法：背包问题

覆盖清单：**算法3.10**（递归算法）、**算法3.11**（非递归实现）、
**算法3.12**（非递归实现的优化版）。原文见 `dsa_raw.md:2395`、`2441`、`2522`。

> 这一组是 3.1.5 节的压轴：把一个**有两条递归规则**的算法，
> 机械地改写成显式栈驱动的循环。本文件是证据，每条都附编译器输出。

## 一、缺陷清单与证据

### 缺陷 1（致命）：`enum rdType {0,1,2};` —— 枚举值不能是整数字面量

```console
$ g++ -std=c++17 -c k1.cpp
k1.cpp:1:14: error: expected identifier before numeric constant
    1 | enum rdType {0,1,2};
      |              ^
```

枚举成员必须是标识符。原书想表达的应该是三个具名常量
（本书写成 `enum class Stage { Enter, AfterRule1, AfterRule2 }`）。

### 缺陷 2（致命）：`public class knapNode { ... }` —— 这是 Java 语法

```console
$ g++ -std=c++17 -c k2.cpp
k2.cpp:1:1: error: expected unqualified-id before ‘public’
    1 | public class knapNode {
      | ^~~~~~
```

C++ 里 `public` 是类内的访问说明符，不能修饰类声明本身。
这处写法在原书出现**两次**（算法3.11 之前的栈结点声明、算法3.12 之前的优化版声明）。

### 缺陷 3（致命）：算法3.12 同时把 `stack.top` 当数据成员和成员函数用

```cpp
t = stack.top;          // 当成 int 数据成员：取栈顶下标
stack.top(&tmp);        // 当成成员函数：读栈顶元素
```

同一个名字在同一个函数里被当成两种东西，**任何一种解释下都编译不过**。
而且这恰恰**依赖**代码3.2 / 代码3.4 那个 `top` 重名缺陷——
如果那两个类能编译，这里才有可能"两种用法同时存在"。
一处错误撑起了另一处错误，本书里再没有比这更清楚的「从未编译过」的证据。

### 缺陷 4：`w[]` 是一个从未声明的全局数组

算法3.10 直接用 `w[n-1]`，算法3.11/3.12 用 `w[tmp.n-1]`、`w[n0-1-t]`，
而**全书没有任何一处声明过 `w`**。同理，算法3.11/3.12 用到的
`tmp`、`x`、`stack` 也都是正文里用散文引入的全局变量。
后果是这些函数不可重入、不能并发、也无法独立测试。
本书把物品重量作为参数传入。

### 缺陷 5：解通过 `cout` 打印，而不是返回

算法3.10 在选中某件物品时 `cout << w[n-1]`，算法3.11/3.12 同理。
调用方**拿不到解**，只能在终端上看到一串数字；正确性也就无从检验。
本书返回选中物品的下标集合，测试因此可以独立验算：
把返回的下标对应的重量加起来，必须恰好等于承重。

### 缺陷 6：OCR 无法掩盖的语法残缺

`if (tmp.s < 0) || (tmp.s > 0 && tmp.n < 1) {`（括号位置不成立）、
`while (tmp.s >= 0) & (tmp.s <= 0 || n0 > t) {`（同上，且 `&` 应为 `&&`）、
`w[nO - 1 - t]`（字母 O 与数字 0）。这些大概率是 OCR 损伤，
但**在一份从未编译过的代码里，无法把它们与真错误区分开**——
这本身就是"代码必须经过编译器"的最好论据。

## 二、刻意保留的东西

- **两条递归规则与两个递归出口一字未改**：
  出口 1（承重为 0 → 有解）、出口 2（承重为负，或承重为正但已无物品）；
  规则 1（选第 n-1 件）、规则 2（不选第 n-1 件）。
- **"返回地址"机制保留**：原书用 `goto label0/1/2/3` 表示"执行到哪一步"，
  本书写成栈帧里的 `stage` 字段，**语义一一对应**。
  不用 goto 的理由是硬的：goto 跳进跳出会让编译器无法保证局部对象的
  构造与析构配对，在有 RAII 的 C++ 里不能这么写。
- **算法3.12 的两点优化照单实现**：结果单元提到栈外、参数 n 由栈深推出，
  栈帧从四个域缩到两个。这是本节真正的"优化"——不是更快，
  而是**每层要记的东西更少**。

## 三、写这个单元时我自己踩的坑

第一版显式栈实现，我把"返回地址"塞进 `rd` 的位标志里（`rd | 4`、`rd & 8`），
结果**死循环，撞上闸门 120 秒超时**。改写成与原书 label 一一对应的
`enum class Stage` 之后一次通过。

记在这里是因为它印证了原书这一节的难度：**手工模拟递归确实容易写错**，
而原书那份用 goto 的版本从未被编译器验证过。
