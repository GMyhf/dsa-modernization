# 原书写法 → 问题 → 现代写法：后缀表达式求值

覆盖清单：**算法3.5**（后缀表达式的求值）。原文见 `dsa_raw.md:2134`。

## 一、缺陷清单与证据

### 缺陷 1：`GetTwoOperands` 失败时栈已被破坏——**但要害在别处**

原书写法是：

```cpp
bool Calculator::GetTwoOperands(double& opd1, double& opd2) {
    if (s.isEmpty()) { cerr << "Missing operand!" << endl; return false; }
    s.pop(&opd1);                                   // 右操作数：已经弹掉了
    if (s.isEmpty()) { cerr << "Missing operand!" << endl; return false; }
    s.pop(&opd2);
    return true;
}
```

第二次检查失败时，**第一个操作数已经被弹出且丢弃**，栈就此少了一个元素。

**但真正让这件事变成 bug 的，是调用方的行为**：`Compute` 拿到 `false` 之后
`s.clear()` 然后**继续读下一个记号**；`Run()` 的循环照跑不误。
于是一个残缺的表达式会让后续计算在一个被破坏的栈上进行。

这一点值得说清楚，因为它改变了"怎样才算修好"：
**本书的实现出错即抛异常、整次求值作废，栈根本没有机会被下一步用到**——
这才是修法。`pop_two` 里"先查够不够再弹"只是让报错更早更准，不是关键。

> 写这份文档时验证过：把现代实现改回"先弹一个再查"，
> 全部断言**依然通过**——因为在抛异常即作废的设计里，栈被破坏与否观测不到。
> 于是补了 `test_evaluations_are_independent`：钉住"上一次失败不给下一次留残留"
> 这条**真正可测**的性质。

### 缺陷 2：算法与终端焊死

`Run()` 直接 `cin >> c` 读、`cout << res` 写，`GetTwoOperands` 直接 `cerr` 报错。
后果是这个算法**没法写测试、没法在库里复用、没法处理来自别处的表达式**。
本书改为接受 `std::string_view`、返回 `double`、出错抛异常。

### 缺陷 3：`s.pop(&opd1)` 传指针，与本书自己的栈 ADT 对不上

代码3.1 声明的是 `bool pop(T& item)`（引用）。这是本书第**三**处同类不一致
（另两处：算法3.9 的 `s.pop(&tmp)`、本处两次）。

### 缺陷 4：`Stack<double> s;` 又实例化了那个假抽象基类

见 `../array_stack/legacy.md` 缺陷 5。

### 缺陷 5：除零判断——原书正文自己说了它是错的，代码照旧

正文写：

> 在实际编写程序时，浮点数是否为0不能直接与0进行相等比较，
> 而是要通过某个很小的阈值来判断，例如采用 if(abs(operand1) < 1E-7)

**但印出来的代码仍然是 `if (operand1 == 0.0)`。** 书知道更好的写法，却没有印它。

不过原书正文那条建议本身也值得推敲：**除以 1e-300 是合法的**，
结果是一个极大的有限值或 `inf`，把它当成错误是另一个决定，不是"更正确"。
本书只拦精确的 `0.0`，并把这个取舍写在代码注释里；
`test_divide_by_zero` 里有一条断言专门钉住"除以 1e-300 得到极大值而非报错"。

## 二、刻意保留的东西

- 求值主线一字未改：**遇操作数压栈，遇操作符弹两个算完压回**；
- 用的仍是本章自己的 `ArrayStack<double>`，不是 `std::stack`；
- 仍然只处理后缀表达式，不引入中缀转换——那是原书没讲的内容。
