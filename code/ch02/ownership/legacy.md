# 所有权工具的选择判据（第 2 章补充单元）

## 这个单元为什么存在

D-001 §2 规定「存储管理本身是课的地方，用裸指针加显式五法则」。这条规定常被读成
「这本书不用智能指针」——**不对**：`code/ch11/bplus_tree` 和 `code/ch12/trie` 的孩子结点
就是 `std::unique_ptr`。真正的判据是「所有权是不是这一节要教的东西」，以及**换过去会不会
出事**。

本单元把后半句变成可测的数字。它不认领任何原书清单（原书没有讨论智能指针，2008 年
`unique_ptr` 还没进标准），靠 `beyond_book` 说明来历。

## 实测：`unique_ptr` 串成的链，析构是递归的

`RecursiveNode` 里一个 `std::unique_ptr<RecursiveNode> next`，看起来最省事：没有 `delete`，
没有析构函数，五法则一条都不用写。但 `~RecursiveNode` 要析构 `next`，`next` 的析构又要析构
它的 `next`——链有多长，栈就压多深。

```text
$ ulimit -s
8192                          # 8 MB 栈

$ g++ -std=c++17 -O0 -g -I code/ch02/ownership depth.cpp -o /tmp/dp
$ /tmp/dp 100000
Segmentation fault (core dumped)     # shell 报告退出码 139
```

二分找到的阈值：

| 构建档 | 最大安全结点数 | 崩溃于 |
| --- | --- | --- |
| `-O0 -g` | ≈ 57,625 | 58,601 |
| `-O2` | ≈ 523,329 | 524,306 |

**两档差了九倍。** 这才是最难受的地方：同一份代码，debug 下五万多个结点就崩，release 下
五十多万才崩。学生在 debug 里调出段错误，切到 release 又复现不了；或者反过来，测试环境
一直好好的，换个优化级别就炸。递归深度这种东西不该由优化级别决定。

## 对照：自己管所有权，析构走循环

`IterativeChain` 多写了一个析构、一个 `clear()` 和完整的五法则。换来的是**栈深度与链长无关**：

```text
$ g++ -std=c++17 -O0 -g -I code/ch02/ownership depth_iter.cpp -o /tmp/dpi
$ /tmp/dpi 5000000
建好 5000000 个结点，开始析构
$ echo $?
0
```

五百万个结点，`-O0`，一次段错误都没有。`code/ch02/linked_list` 的 `clear()` 就是这个写法，
不是风格偏好，是这个结构能不能处理大数据的分界线。

## 判据表

| 结构形态 | 该用什么 | 理由 |
| --- | --- | --- |
| 链（结点串成一条线） | 裸指针 + 迭代释放 | `unique_ptr` 的析构是递归的，见上表 |
| 树（孩子唯一所有权，深度 $O(\log n)$） | `unique_ptr` | 释放本来就递归，但深度是对数级；`code/ch11/bplus_tree`、`code/ch12/trie` 用的就是它 |
| 一整块缓冲区 | 裸 `T*` + 五法则 | 换成 `unique_ptr<T[]>` 只省掉一句 `delete[]`；它只能移动，拷贝构造仍须手写，五法则并没有消失。本书用裸指针，因为第 3 章要教的正是扩容与 `delete[]` |
| 共享（一个结点多个父） | 手写引用计数 | `unique_ptr` 语义上不成立；`shared_ptr` 可以，但 12.2 要教的正是「谁来回收」，见 `code/ch12/gen_list` |

## 验证边界

- 15 项断言，`-Werror` + ASan/UBSan 与 `-O2` 双档通过。
- **测试里不测 `RecursiveChain` 的崩溃规模**——段错误没法写成断言，写进去只会让闸门变红。
  崩溃是上面那两条命令的事，数字随平台和栈上限变，复现方法比数字本身重要。
- 上表的阈值是**本机 8 MB 栈**下的测量值。换栈上限（`ulimit -s`）、换编译器、换平台，
  数字都会变；不变的是「递归释放的深度正比于链长」这个性质。
- `IterativeChain` 的拷贝先收集再逆序建链，为的是拷贝路径同样不递归；代价是多一趟遍历和
  一个临时 `vector`。真实实现可以边走边接，这里选了更容易读的写法。
- 本单元只讨论**单线程**的所有权。`shared_ptr` 的原子计数开销、`weak_ptr` 破环，都不在范围内。
