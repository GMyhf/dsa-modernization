# 12.2.4 无用单元回收：标记–清除

## 原书给了什么

原书 12.2.4 只有文字：「标记–清除从一组根（栈上的指针、全局变量）出发走遍所有还能碰到的
对象并打上标记，然后扫一遍堆，没标记的统统回收。」**没有清单**，本单元是新增实现。

它和 12.2.1 广义表的引用计数互为对照：那里明说「引用计数收不回环」，这里演示标记–清除
为什么收得回。两个单元合起来才把 12.2 的存储管理讲完整。

## 第一版的模型太薄，记在这里

第一版（`af11567`）每个结点只有**一条**出边（`Node* edge`），`collect()` 只接受**一个**根。
那是一条带 GC 标记的链表，不是对象图——而原书原话是「从一**组**根出发走遍所有还能碰到的
对象」。用它演示不出这几件事：

- 一个对象被多处引用、却都够不着根（引用计数为 3 照样该回收）；
- 两个根共享同一个子图，撤掉其中一个根之后哪些成了垃圾；
- 标记阶段遇到环怎么才不会转不出来。

现在的模型：出边是 `std::vector<Node*>`，`collect()` 接受根集，标记阶段用**显式栈**。

## 为什么标记不用递归

GC 恰恰是在内存吃紧的时候跑的，那时最不该再去吃调用栈。这与 D-001 §2b 是同一个判据。
测试里有 20 万个对象的深链，递归标记必然压穿栈，显式栈则不受影响。

## 可复现的证据

```text
$ cd code/ch12/storage_recovery
$ g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -O1 -g \
      -fsanitize=address,undefined -fno-sanitize-recover=all test.cpp -o /tmp/sr
$ /tmp/sr
StorageRecovery: 25 项断言，0 失败
```

**变异自检**（三处，都见红）：

| 把实现改成哪种错法 | 后果 |
| --- | --- |
| 标记时先入栈后置标记 | 遇到环转不出来，测试挂死跑不完 |
| 清除时不复位标记 | 3 条红：第二轮回收把该留的当成已标记 |
| `collect()` 只认第一个根 | 3 条红：共享子图与多根场景全错 |

## 验证边界

- 25 项断言，`-Werror` + ASan/UBSan 与 `-O2` 双档通过。
- 覆盖：不可达对象回收、**无根环整个回收**（引用计数做不到的那件事）、有根环全部保留、
  「被三处引用但够不着根」照样回收、两个根共享子图、根集为空则全清、20 万深链与 5 万宽图。
- **这是教学模型，不是运行时垃圾回收器**。对象图由调用方显式搭出来：没有栈扫描、
  没有写屏障、没有分代、不做移动整理，也**不区分「这是指针」和「这只是个看起来像地址的
  整数」**——而那恰恰是真实 GC 最难的部分。原书正文也是这么说的，本单元不冒充更多。
- 没有实现原书 12.2.3 的首次/最佳/最坏适应与边界标记合并；那一节仍是概念导读。
