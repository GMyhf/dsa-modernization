# 12.1.3 稀疏矩阵与十字链表

## 原书给了什么

原书 12.1.3 只有文字：三元组线性表，或者十字链表——「每个非零元同时挂在行链表和列链表上，
便于按行、按列遍历」。**没有 `【算法】`/`【代码】` 清单**（第 12 章的清单只有算法12.1、
算法12.2）。参考资料里那份 `SourceCodes/Chap12_AdvDS/AdvList/SparseMatrix` 也用不了：

```text
$ g++ -std=c++17 -fsyntax-only Example.cpp
SMatrix.h:3:10: fatal error: afxtempl.h: No such file or directory
```

`afxtempl.h` 是 MFC 的头文件，非 Windows 平台根本编不了。所以本单元从零写。

## 第一版走错了路，记在这里

本单元的第一版（`af11567`）把列链做成了**派生索引**：行链用 `unique_ptr` 串起来，
每次 `set()` 之后调用 `rebuild_columns()` 把全部列链重建一遍。它能通过当时那三条断言，
但有两个问题：

1. **教学上是错的。** 十字链表的定义就是「每个非零元同时在两条链上，两条链局部维护」。
   全表重建等于把列链降级成一个每次都重算的索引，读者会学到错误的东西。
2. **代价是 O(n²)。** 实测建表耗时随非零元数平方增长：

   | 非零元数 | 耗时 |
   | --- | --- |
   | 2000 | 0.00 秒 |
   | 4000 | 0.02 秒 |
   | 8000 | 0.11 秒 |

3. **`unique_ptr` 串行链，析构是递归的。** 这正是 D-001 §2b 判据表里「链」那一行明确
   排除的用法。实测（8 MB 栈）：

   ```text
   $ g++ -std=c++17 -O0 -g   # 一行 60000 个非零元
   Segmentation fault (core dumped)      # 退出码 139
   ```

   `-O2` 下同样规模能过（尾调用被优化掉），`-O0` 下崩——又是那个「debug 崩、release 过」
   的老问题。

现在这一版：行链和列链都在插入时**局部**接上（只走该行、该列各一段），删除时从两条链上
各摘一次；结点所有权归容器，析构沿行链**迭代**释放。

## 可复现的证据

```text
$ cd code/ch12/sparse_matrix
$ g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -O1 -g \
      -fsanitize=address,undefined -fno-sanitize-recover=all test.cpp -o /tmp/sm
$ /tmp/sm
SparseMatrix: 37 项断言，0 失败
```

**变异自检**：

| 把实现改成哪种错法 | 后果 |
| --- | --- |
| 插入时不接列链 | 段错误，退出码 139 |
| 删除时只摘行链、不摘列链 | `ERROR: AddressSanitizer: heap-use-after-free` |

## 验证边界

- 37 项断言，`-Werror` + ASan/UBSan 与 `-O2` 双档通过。
- **与普通二维数组对拍**：30×30 上做 4000 次随机写，逐元比对，再按行、按列各扫一遍——
  行链和列链必须指向同一批结点。
- 「按列扫只走该列」是**量出来的**：200×200 的对角线矩阵加两个非零元，扫第 7 列
  走过 3 个结点，而不是全表 202 个。
- 一行 20 万个非零元的用例守着「析构走循环」这条。**按降序插入**，因为升序插入每次都要
  走完整条行链，是 O(n²)——那是单链表的固有代价，不是这里要测的东西。
- **不在范围内**：没有加法/乘法/转置；没有拷贝构造（只能移动）；
  `get(i,j)` 是 O(该行非零元数) 的线性查找，这正是十字链表相对二维数组**吃亏**的地方，
  如实保留，不用哈希表掩盖。
- 结点只存后继不存前驱，所以删除时列链的前驱要现找，代价 O(该列非零元数)。
