# 动态分配证据

原书 12.2.3 只讨论首次适应、最佳适应、最坏适应和边界标记合并。
本单元用固定容量的块目录模拟连续堆，分配时按策略选择空闲块，必要时分裂，释放时合并相邻空闲块。

```text
$ python3 tools/check_code.py code/ch12/memory_allocator --allow-degraded
BoundaryAllocator: 12 checks, 0 failures
```

实现不劫持全局 `new`，不承诺线程安全或真实系统堆性能；目标是让选择、分裂和合并可运行验证。
每个块记录起始偏移、大小、前驱和后继，前后链接就是边界标记的教学化等价物。
首次适应遇到第一个可用块立即停止，最佳/最坏适应分别比较最小/最大可用块。
分裂只在剩余空间非零且元数据容量允许时发生，释放后先与后继、再与前驱合并。
测试对三种策略各执行同一组分配、重复释放和相邻合并操作。
空请求返回空值，重复释放返回 false，分配不足时不修改已有块。
本单元模拟的是连续堆布局，不提供真实地址、对齐和并发保证。
Sanitizer 在当前 macOS 环境的空探针失败，以上结果为 Release-O2 验证。
碎片策略的差异由块大小选择顺序体现，不依赖具体系统分配器。
边界合并测试最终恢复 100 字节空闲容量，证明释放没有丢失块。
该证据只覆盖单线程顺序操作，复杂调度仍属于章节练习的扩展范围。
实现中的偏移量从 0 开始，便于把块分裂结果和边界标记逐项打印核对。
测试没有把“总空闲字节数”误当成“存在连续可用块”，两者在碎片化时可以不同。
