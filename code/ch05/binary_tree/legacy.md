## 可复现或可审计的问题

1. **OCR 造成代码不可编译**：代码5.1的子树参数 `* 1`、代码5.2/5.8 的 `∼`、全角分号、
   孤立 `1` 和缺花括号均会被现代书稿的 R2 拦截。它们被标为 OCR 损伤，不冒充原书设计结论。
   可复核：`python3 tools/check_doc.py book/ch05-binary-tree.md` 对同步后的书稿通过；原始
   片段保留在只读 `dsa_raw.md:3704-4105`，不以修复后的代码覆盖 OCR 证据。
2. **复制控制缺失**：代码5.2只有析构 `DeleteBinaryTree(root)`，未展示复制构造和拷贝赋值。
   默认浅拷贝会让两棵树后序删除同一子树。现代实现 Rule of Five；`clone` 中途失败会回收
   已建半树，`test_partial_clone_is_cleaned` 用寿命计数守住。
3. **`CreateTree` 的别名危险**：原书把两棵参数树的根直接挂到新根后置空；若传入同一棵树
   两次或传入自身，所有权会重叠。现代接口只接收两个 rvalue 子树，表达“转移所有权”。
4. **容器内 I/O 与出参接口**：原书周游把 `Visit` 固定为输出样式，父结点返回裸指针。
   现代周游接受 visitor；空树自然不访问；BST 删除不存在键按 D-001 §3c 返回 `false`。
5. **递归栈溢出风险（已拍板保留）**：算法5.3及后序销毁在极深/病态树上受调用栈限制，
   可能 Stack Overflow。D-001 §3d 要求保留递归作为教学主实现，风险在实现注释和本节明确。
   算法5.4–5.6 的手写显式栈实现仅作为补充接口，不改变此教学主线。

## 最脆弱的析构路径（供 Claude 的 sanitizer 专项变异）

1. `BinaryTree::make_empty()` 的左右子树后序释放：漏删任一分支会泄漏，先删根会悬垂。
2. `BinaryTree::clone()` 的左子树已复制、右子树构造抛异常：catch 必须回收半树。
3. `BinarySearchTree::remove()` 的前驱摘除/根替换：replacement 的左链接必须先脱离原父，
   再继承被删结点子树，且被删结点只能 delete 一次。
