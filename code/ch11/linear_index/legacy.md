# 11.1 线性索引 / 11.2 静态多分树（索引部分）

## 原书给了什么

**第 11 章一条清单都没有**——`tools/ledger.py` 从 `dsa_raw.md` 解析的 105 条
`【算法】`/`【代码】`里，第 11 章为 0。参考资料 `ref_数据结构与算法A 2021秋/SourceCodes`
里也没有 `Chap11` 目录。所以本单元从零写，listings 为空，由 `beyond_book` 说明来历。

原书本节确立的取舍，实现逐条落到可执行的断言上：

| 原书结论 | 对应的可执行事实 |
| --- | --- |
| 稠密索引每条记录一项，**主文件可以无序** | `IndexKind::Dense` 装入乱序记录仍可查；`entries() == 记录数` |
| 稀疏索引每个数据页一项，**要求主文件有序** | 乱序输入抛 `std::invalid_argument`；`entries() == 数据页数` |
| 稀疏更省空间 | `sparse.index_pages() < dense.index_pages()` |
| 一层放不下就做多级 | 索引项逐层收敛到一页，`levels()` 报层数 |
| **关键指标是页访问次数，不是比较次数** | `page_reads()`；顶层常驻内存不计 |

## 一条容易被忽略的差别

稠密索引查不到时**一个数据页都不用读**（索引里没有就是真没有）；稀疏索引只能定位到页，
**查不到也必须先把那一页读上来**。测试把这条差别写成了两条断言：

```text
11.1 稠密索引查不到时一个数据页都不读     page_reads() == 0
11.1 稀疏索引查不到也得先读那一页         page_reads() == 1
```

## 可复现的证据

```text
$ cd code/ch11/linear_index
$ g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -O1 -g \
      -fsanitize=address,undefined -fno-sanitize-recover=all test.cpp -o /tmp/li
$ /tmp/li
LinearIndex: 39 项断言，0 失败
```

**变异自检**：把稠密索引改成「未命中也去读数据页」（`++reads_` 提到 key 比较之前），
本节最核心的那条差别立刻变红：

```text
  FAIL: 11.1 稠密索引查不到时一个数据页都不读
LinearIndex: 39 项断言，1 失败
```

## 验证边界

- 39 项断言，`-Werror` + ASan/UBSan 与 `-O2` 双档通过。
- 500 条记录 × 两种索引，逐条查回原值，外加「小于最小 key」「大于最大 key」
  「落在两条记录之间」三种未命中。
- 页内定位用的是线性扫描而不是二分：本节要教的是**页访问次数**，页内比较次数不是重点；
  真实实现会在页内二分。这是教学清晰度优先的取舍，不是疏忽。
- 这是**内存里的**页模拟，没有真实磁盘 I/O、页缓存或并发；`page_reads()` 按
  「访问一页 = 一次访外」计。
- 不支持删除和增量维护：静态索引「一次建好、很少改」，动态维护是 11.4 B+ 树的事，
  见 `code/ch11/bplus_tree`。
