# 11.3 倒排索引

## 原书给了什么

第 11 章没有任何清单（见 `code/ch11/linear_index/legacy.md` 的同一段说明），
本单元从零写，listings 为空。

原书本节的三句话，全部变成可执行的：

- 倒排把「从记录到属性」翻成「从属性值到记录集合」。
- 与查询 = 有序表求交，或 = 求并，非 = 求差。
- 全文检索用同一结构，词项映射到「哪些文档、出现在哪些位置」；短语查询靠位置相邻过滤。

书上的例子（计算机系 → `[0310,0330,0341]`，英语专长 → `[0310,0421]`，
「计算机系且擅长英语」= `[0310]`）就是测试里的第一组断言，逐字对齐。

## 现代实现的取舍

- **交并差手写归并，不调 `std::set_intersection`。** 有序表求交的 `O(n+m)` 归并正是本节
  要教的算法；换成一行库调用，这一节就没了（D-001 第 2 条）。
- **词项字典用 `std::map`**。词典本身是第 10 章（检索）的内容，本节的教学对象是倒排表上的
  集合运算，所以字典结构作为基础设施使用，并在 `unit.json` 的 `d001_exceptions` 里写明。
- **文档号必须严格递增**。倒排表按文档号有序是所有集合运算的前提，违反直接抛异常，
  而不是默默接受一个会让求交出错的输入。
- **位置信息与文档号并列存放**，短语查询先用与查询把候选缩小，再逐个位置验证相邻。

## 可复现的证据

```text
$ cd code/ch11/inverted_index
$ g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -O1 -g \
      -fsanitize=address,undefined -fno-sanitize-recover=all test.cpp -o /tmp/iv
$ /tmp/iv

```

**变异自检**：把 `has_position()` 改成永远返回 `true`——短语查询就退化成普通的与查询，
位置信息形同虚设。四条断言同时变红：

```text

  FAIL: 11.3 短语有方向
  FAIL: 11.3 四词短语
  FAIL: 11.3 顺序不对的短语
```

## 验证边界

- 47 项断言，`-Werror` + ASan/UBSan 与 `-O2` 双档通过。
- 200 篇文档 × 3 个词项与 `std::set` 对拍：倒排表本身、以及全部 9 种两两与查询。
- 短语查询专门测了「两个词都在但不相邻」的文档（2 号），这是只靠与查询无法排除的情形。
- **不在范围内**：没有做倒排表的压缩（差值编码、可变字节）、没有词频/打分排序、
  没有增量删除与合并——原书本节明确说「每次插入删除都要同步维护相关列表」，
  那部分维护代价这里只讨论、不实现。
