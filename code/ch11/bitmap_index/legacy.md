# 11.5 位图、签名

## 原书给了什么

第 11 章没有任何清单（见 `code/ch11/linear_index/legacy.md`），本单元从零写，listings 为空。
原书本节的三个结论逐条对应到断言：

| 原书结论 | 可执行事实 |
| --- | --- |
| 位图适合取值很少的属性 | 每个取值一条位串，`words() = 取值数 × ⌈n/64⌉` |
| 查询变成机器字上的按位运算，一次处理几十上百条记录 | 200 条记录的取反只做 **4 次字运算** |
| 取值一多位图会变宽，需要压缩 | 字级游程压缩；稀疏位图 16 字 → 4 字 |
| 签名可能假阳性，**不能有假阴性** | 两组语料各自断言「无假阴性」，并给出真实出现的假阳性 |

## 两处如实呈现、不粉饰的地方

1. **压缩不是万能的。** 交替模式的稠密位图经游程压缩后**反而更大**，测试直接断言
   `run_length_encode(alternating).size() > alternating.size()`。位图压缩只对大片重复有效。
2. **假阳性要真的演示出来。** 文档词少时签名不挤，可以一个假阳性都没有；词一多签名饱和，
   假阳性就出现了。两种情形各写了一个用例，而不是只留下「可能会有」这句话。

## 一个容易漏的实现细节

记录数不是 64 的整数倍时，最后一个机器字里**超出记录数的那些位**在取反后会变成 1，
于是冒出根本不存在的记录号。`mask_tail()` 专门清掉它们，测试用 5 条记录和 64 条记录
两个边界各盯一次。

## 可复现的证据

```text
$ cd code/ch11/bitmap_index
$ g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror -O1 -g \
      -fsanitize=address,undefined -fno-sanitize-recover=all test.cpp -o /tmp/bm
$ /tmp/bm
BitmapIndex: 30 项断言，0 失败
```

**变异自检**：删掉 `mask_tail(bits)` 那一行——取反后最后一个机器字里超出记录数的位变成 1，
于是冒出根本不存在的记录号：

```text
  FAIL: 11.5 取反的记录数
  FAIL: 11.5 取反等于另一个取值
  FAIL: 11.5 取反不会冒出不存在的记录
BitmapIndex: 30 项断言，3 失败
```

## 验证边界

- 30 项断言，`-Werror` + ASan/UBSan 与 `-O2` 双档通过。
- `to_records()` 故意不用 `__builtin_ctzll`：正文代码要能在 GCC / Clang / MSVC 上都编过
  （D-001 第 1 条），代价是逐位扫描比内建指令慢。这是**可移植性优先于常数因子**的取舍。
- 签名用固定的 FNV 变体散列，同一个词在任何一次运行里都落到同样的位，测试因此可复现；
  它不是密码学散列，也没有做原书提到的分块签名、逐层签名。
- 没有实现字对齐混合编码（WAH/EWAH）那类真正用在生产里的位图压缩，只做了最朴素的字级游程。
- 红黑树在本节只作对照讨论，不提供实现——内存里的有序映射不是本章的教学对象。
