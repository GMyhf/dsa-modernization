## 实现遵守的约定

`book/ch11-index.md` 11.4 已经写明本章约定与原书 11.4.2 的差别，实现严格按本章这一套：

| | 本章（本单元实现） | 原书 11.4.2 |
| --- | --- | --- |
| `order` 的含义 | 一个结点最多几个孩子 | 同 |
| 叶的关键码容量 | 最多 `order - 1` | ⌈m/2⌉ ~ m |
| 分界码取值 | **右子树的最小关键码** | 最大关键码复写 |
| 叶分裂 | 分界码**复写**，叶上仍保留 | 同 |
| 内部结点分裂 | 中位数**上移**，原结点不保留 | 同 |

`validate()` 把这套约定写成可执行的不变量：所有叶同层、结点不超上限、除根外不低于下限、
每个分界码等于其右子树的最小关键码、叶链整体升序且总数等于 `size()`。

## 开发过程中真实踩到的缺陷

删除路径第一版是错的，**随机测试 + `validate()` 抓到的**，不是看出来的：

```text
erase 50: [20,50] / [10] [20] [60]   valid=0
```

根的分界码留下了 `50`，可这个关键码刚被删掉，`60` 才是右子树的最小关键码。原因是
`merge()` 会把父结点的分界码搬进合并后的孩子里，而那个分界码可能正是刚删掉的关键码。
修法：借位/合并之后，对被动过的孩子按「分界码 = 右子树最小关键码」重算一遍。
没有 `validate()` 和随机对拍，这棵树看起来完全正常——点查询甚至还能查对。

## 验证边界

- 9075 项断言，`-Werror` + ASan/UBSan 与 `-O2` 双档通过。其中 3 个阶数（3/4/6）× 3000 步
  随机插删，每步与 `std::set` 对拍，结束后跑 `validate()` 和全量叶链扫描。
- **变异自检**（三处，都见红）：

  | 把实现改回哪种错法 | 后果 |
  | --- | --- |
  | 叶分裂的分界码取左叶末位 | 书上例子的三条树形断言全红 |
  | 合并时不接叶链（删掉 `left->next = right->next`） | `ERROR: AddressSanitizer: heap-use-after-free`，退出码 1 |
  | 借位/合并后不重算分界码 | `validate()` 全红（就是上面那个真实缺陷） |

- **不在范围内**：这是**内存里的**页模拟，不做真正的磁盘 I/O、页缓存或并发控制；
  `page_reads()`/`page_writes()` 是教学计数器，按「访问一个结点 = 访问一页」计，
  不等于真实文件系统的读写次数。
- `refresh_separators()` 在每次删除时沿路重算分界码，为的是把约定写得直白；
  真实实现会只在必要时更新。这是**教学清晰度优先于常数因子**的取舍。
- 插入、删除、`validate()` 都对树高递归，树高是 $O(\log_m n)$，不构成栈风险。
- 没有实现 B 树（记录在内部结点的那种）；11.4 的对照靠文字，不靠第二份实现。
