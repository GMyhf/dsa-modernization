## 实现遵守的约定

2026-11-20（T-095）起按**原书 11.4.2 的定义⑤**实现，与正文、习题答案、期末复习题库同一口径。
此前（2026-08 至 T-095）用的是另一套常见约定，改动对照如下：

| | 原书定义⑤（现在的实现） | T-095 之前的实现 |
| --- | --- | --- |
| `order` 的含义 | 一个结点最多几个孩子 | 同 |
| 叶的关键码容量 | ⌈m/2⌉ ~ m（混合型另给叶阶 L：⌈L/2⌉ ~ L） | ⌈(m−1)/2⌉ ~ m−1 |
| 内部结点 | k 个孩子 **k 个**关键码 | k 个孩子 k−1 个分界码 |
| 路标取值 | 对应子树**最大码的复写** | 右子树的最小码 |
| 检索 | 第一个不小于待查码的路标；比全部都大走最右 | 第一个大于待查码的分界码左边 |
| 分裂 | 叶和内部结点同一个动作：放进第 m+1 项分成两半，两半的最大码都复写到父结点 | 叶复写右叶最小码；内部结点中位数上移 |
| 新最大码 | 沿最右路径改最后一个路标 | 不需要 |
| 删除后不下溢 | 上层路标不动（只是上界） | 每次沿路重算分界码 |
| 读写盘计数 | 一次操作内同一页只算一次读、一次写，释放的页不写 | 每次访问累加 |

`validate()` 把定义写成可执行的不变量：所有叶同层；结点不超上限、除根外不低于下限、
根若是内部结点至少两个孩子；内部结点关键码数等于孩子数，第 i 个关键码不小于第 i 棵子树的
全部关键码、小于第 i+1 棵子树的全部关键码；叶链整体升序且总数等于 `size()`。

## 开发过程中真实踩到的缺陷（T-095 之前的实现）

删除路径第一版是错的，**随机测试 + `validate()` 抓到的**，不是看出来的：

```text
erase 50: [20,50] / [10] [20] [60]   valid=0
```

根的分界码留下了 `50`，可这个关键码刚被删掉，`60` 才是右子树的最小关键码。原因是
`merge()` 会把父结点的分界码搬进合并后的孩子里，而那个分界码可能正是刚删掉的关键码。
修法：借位/合并之后，对被动过的孩子按「分界码 = 右子树最小关键码」重算一遍。
没有 `validate()` 和随机对拍，这棵树看起来完全正常——点查询甚至还能查对。

按定义⑤重写后这个坑不复存在：路标只是上界，刚删掉的码留在上层当路标仍然合法（原书 11.4.2：
「不必对应一个真实存在的键」），`validate()` 检查的也是上下界而不是「等于最小码」。

## 验证边界

- 634 项断言，g++/clang++ 的 `-Werror` + ASan/UBSan 与 `-O2` 四档通过。其中 4 个阶数（3/4/5/6）× 3000 步
  随机插删，每步与 `std::set` 对拍、每步之后跑 `validate()`，结束时再做全量叶链扫描。
- **变异自检**（T-095，全部见红）：

  | 把实现改成哪种错法 | 后果 |
  | --- | --- |
  | 建层时路标取子树最小码 | 按图 11.9 装树时 `validate()` 拒绝，`std::invalid_argument` 未捕获，退出码 134 |
  | 合并时不接叶链（删掉 `left->next = right->next`） | `ERROR: AddressSanitizer: heap-use-after-free` |
  | 新最大码不改最右路径的路标 | 期末 11-17 树形与 `validate()`、「最右路径」断言红 |
  | 分裂时左半取 ⌊(m+1)/2⌋ | 「4 阶叶放进第 5 个：分成 3 + 2」红 |
  | 借左兄弟后不改两兄弟之间的路标 | 图 11.11 树形与 `validate()` 红 |
  | 不先看左兄弟 | 图 11.11 树形红（d 没有右兄弟，跳过左兄弟 c 就直接与 c 合并，借位变成了合并） |
  | 合并时被并掉的页仍计写 | 「被并掉的那一页即使刚改过也不写回」红 |
  | 删根时旧根仍计写 | 「旧根与右邻释放，不写」红 |

- **不在范围内**：这是**内存里的**页模拟，不做真正的磁盘 I/O、页缓存或并发控制；
  `page_reads()`/`page_writes()` 是教学计数器，按「访问一个结点 = 访问一页」计，
  不等于真实文件系统的读写次数。`find`/`range` 每访问一页就计一次读；插入删除按一次操作内的不同页计。
- 插入、删除、`validate()` 都对树高递归，树高是 $O(\log_m n)$，不构成栈风险。
- 没有实现 B 树（记录在内部结点的那种）；11.4 的对照靠文字，不靠第二份实现。
