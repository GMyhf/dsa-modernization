### 返工：修复方式过宽

你的修法是「可拷贝就一律拷贝」。正确，但判据落在了「可不可拷贝」这个维度上，
而问题出在「移动赋值抛不抛」。后果实测过：

```
扩容搬迁: 拷贝 63 次, 移动 64 次     ← 你的版本，元素是 noexcept 移动赋值的类型
扩容搬迁: 拷贝 0 次,  移动 127 次    ← 改后
```

`std::string` 的移动赋值本就是 `noexcept`，每次扩容却退化成深拷贝——
算法3.3 摊还 O(1) 的教学点跟着打折。改为：

```cpp
if constexpr (std::is_nothrow_move_assignable<T>::value) 移动; else 拷贝;
```

else 分支要求 `T` 可拷贝赋值，正好由你新加的那条 `static_assert` 兜住，逻辑闭合。
**你的两条故障注入用例在新判据下照样通过**（`ThrowingMoveAssignment` 的移动赋值
不是 noexcept → 走拷贝路径 → 旧元素完好）。

  `clear()` 顺手扔掉容量 → `FAIL: clear 保留已分配容量`。

1. `relative_to(ROOT)` 在仓库外路径上抛 `ValueError` —— ledger / check_doc / check_code

   也当成开清单，要求配对结束标记。现改为只认独占一行开头的标记。
4. **交接包在首轮是空 diff**：`git diff HEAD` 看不见未跟踪文件，而首轮所有东西都是新文件——
   你会收到一份「闸门全绿 + 空 diff」的包，看起来像没改任何东西。
   现用 `git diff --no-index` 补上（不碰 index，二进制由 git 自己缩成一行）。
   顺带修了 `git()` helper：`--no-index` 有差异时退出码是 1，原来的 `soft=True`
   把 stdout 一起丢了。这条有 `tests/test_handoff.py` 守着。
