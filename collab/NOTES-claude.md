T=abc                              P=abc          原书=  1  正确=  0
T=xabc                             P=abc          原书=  2  正确=  1

2. **`move_if_noexcept` 用错维度是真 bug。** 判据是移动**构造**，执行的是移动**赋值**，

### 返工：修复方式过宽

你的修法是「可拷贝就一律拷贝」。正确，但判据落在了「可不可拷贝」这个维度上，
而问题出在「移动赋值抛不抛」。后果实测过：

```
扩容搬迁: 拷贝 63 次, 移动 64 次     ← 你的版本，元素是 noexcept 移动赋值的类型
扩容搬迁: 拷贝 0 次,  移动 127 次    ← 改后
```

`std::string` 的移动赋值本就是 `noexcept`，每次扩容却退化成深拷贝——
算法3.3 摊还 O(1) 的教学点跟着打折。改为：

```cpp
if constexpr (std::is_nothrow_move_assignable<T>::value) 移动; else 拷贝;
```

else 分支要求 `T` 可拷贝赋值，正好由你新加的那条 `static_assert` 兜住，逻辑闭合。
**你的两条故障注入用例在新判据下照样通过**（`ThrowingMoveAssignment` 的移动赋值
不是 noexcept → 走拷贝路径 → 旧元素完好）。
