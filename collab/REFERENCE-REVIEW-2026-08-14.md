# 参考书对照审查：新书修正与优化建议

对照材料：

- 《数据结构与算法》（张铭、王腾蛟、赵海燕，高等教育出版社，2008）。该书的内容提要明确覆盖基本数据结构、排序、索引、检索和高级数据结构，并以 ADT、存储方法比较和复杂度分析组织全书。
- `fcpp-flash.pdf`《C++基础能力手册》。目录第 4--6 章明确覆盖 RAII/所有权、异常、泛型与概念、迭代器、STL、区间和视图。

## 结论

新书的课程骨架基本成立：第 1--12 章覆盖了张铭教材的主要主题，代码也已经以 C++17、RAII、`optional`、异常和可执行测试重写。当前最需要做的是“边界和承诺说清楚”，而不是再无条件扩充算法数量。

## 必须修正（P0）

### 1. 删除第 1 章重复句

`book/ch01-adt.md` 在问题设计段落连续两次出现“下面是完整可运行的程序”。这不是算法错误，但会让排版和校对显得不稳定。保留一次即可。

### 2. 修正教程对 C++ 版本的定位

教程在总目录中承诺 C++17，而 `fcpp-flash.pdf` 第 6 章已经把 STL、迭代器、区间和视图作为现代 C++ 的连续知识链；第 5 章还包括概念约束、可变参数模板和折叠表达式。当前书稿大量使用 `vector`/迭代器思想，但没有一个“本书不使用 C++20/23 ranges 和 concepts”的明确决策。

建议在 `book/现代C++数据结构教程.md` 的“如何使用”或“阅读约定”增加兼容性声明：

> 主体代码固定为 C++17，以保证 GCC/Clang/MSVC 的可用性；C++20 concepts、ranges/views 作为“现代化延伸”单独标注，不把它们作为正文前置条件。

这样既不破坏当前构建闸门，也回应了 `fcpp-flash` 的现代语言基线。

### 3. 明确“源码实现”与“概念导读”的边界

`book/ch12-advanced.md` 的多维数组、广义表、Trie、Patricia 树主要是文字和图示，只有可利用空间表与最优 BST 有可运行实现；`book/ch06-tree.md` 也说明部分存储法不另写实现。张铭教材强调“不同存储方法及相关算法比较”，所以当前目录容易让读者误以为每个小节都有同等代码覆盖。

建议每章开头增加统一标记：`实现并测试`、`概念导读`、`练习实现` 三类。对未实现的 Trie、Patricia、十字链表等，给出一个最小接口/伪代码练习，或在目录中明确“本书不提供实现”。

## 建议优化（P1）

### 4. 增加现代 C++ 前置知识映射表

`fcpp-flash` 的第 4.2 节把 RAII、所有权和异常放在数据结构之前；新书则在各章分散解释五法则、移动语义、异常安全和 `optional`。分散讲法符合边做边学，但读者缺少总览。

建议在总目录后增加一张短表：

| 本教程用到的能力 | 首次出现 | 参考入口 |
| --- | --- | --- |
| RAII/析构/五法则 | 第2章顺序表 | `fcpp-flash` 4.2 |
| 移动语义/完美转发 | 第2、5章 | `fcpp-flash` 4.1、5.1 |
| 异常与强异常保证 | 第2、5、10章 | `fcpp-flash` 4.3 |
| 迭代器/STL 算法 | 第8、10章 | `fcpp-flash` 6.1 |
| concepts/ranges | 延伸阅读 | C++20/23 |

### 5. 把复杂度“结论”改成“条件化结论”

第 8 章已经给出快排平均/最坏复杂度、比较排序下界；第 7 章也给出 Dijkstra/Floyd 的选型表。但应统一补充前提：图的稠密/稀疏表示、堆实现、比较模型、输入是否已经有序，以及快排枢轴策略。否则读者会把 `O(n log n)` 当成无条件性能承诺。

### 6. 为测试闸门补一条“教学覆盖”清单

当前 `check_doc.py` 和 `check_code.py` 证明代码可编译、测试路径通过；本次实际运行仍因 macOS sanitizer 自检失败而是降级档，不能证明全部内存与 UB 路径。建议在每章末尾增加“本章已验证/未验证”两行，特别标出递归深度、未实现结构和平台差异。

## 不建议现在做的事

- 不要为了追赶 `fcpp-flash` 而把全书切换到 C++20/23；这会改变构建前提，且不是张铭教材现代化的必要条件。
- 不要把标准库 `std::sort`、`std::unordered_map` 直接替换手写算法；第 8、10 章的教学目标正是比较算法与冲突处理。
- 不要把 `dsa_raw.md` 当作可编辑正文；它仍应只用于追溯原书和 OCR 证据。
