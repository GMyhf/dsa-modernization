## D-025 · 2026-08-18 · 人已拍板：Python 进书的边界与证据链（T-041 ~ T-046）

**背景**：`../2026spring-cs201`（数算B 2026 春，Python 授课）与本书内容互补——

### 1. 边界：Python 只进「讲算法」的章，不进「讲存储管理」的章

判据与 D-001 §2 同构。D-001 说「把 `ArrayStack` 做成 `std::stack` 的薄封装等于把这一节删掉」；
Python 更快：顺序栈写成 `list`、链表写成 `list`、字符串类写成 `str`，
**三法则、五法则、强异常保证、对齐义务（D-024）在 Python 里根本没有对应物**。
那不是「换一种语言讲同一课」，是把课删了再换个语言重讲别的。

所以本书的两侧按书稿导读**已经划好**的那条线分：

| | 讲什么 | 实现 |
| --- | --- | --- |
| 存储侧 | 存储布局、所有权、拷贝/移动语义、异常安全 | **只有 C++**，正文写明「这里为什么不给 Python」 |
| 算法侧 | 算法本身的正确性与代价 | **C++ + Python 双实现** |

存储侧：2.2 顺序表、2.3 单链表/双链表、3.1 顺序栈/链式栈、3.2 队列、4.2 字符串类、

### 2b. 名单按「删掉哪一节课」逐条列，不按模块整个封（2026-08-18 同日补充条款，人已拍板）

§2 那份表里最初写的是「禁 `collections`」。**人当天驳回**：该封的是
`OrderedDict`、`Counter` 这些**确实绕过某一节课**的名字，不是整个模块。

先按判据逐个查了一遍，结论**三个名字三种处理**：

| 名字 | 会删掉本书哪一节 | 处理 |
| --- | --- | --- |
| `deque` | 3.2 队列、循环队列与双端队列（`book/ch03-stack.md` 有全部三项） | **封** |
| `Counter` | 8.6.1 桶式排序的计数数组；5.6 Huffman 的频次统计 | **封** |
| `OrderedDict` | **查不到**。本书没有「保持插入序的散列表」这一节 | **不封** |
| `defaultdict` / `namedtuple` | 不对应任何一节，是正当管道 | **不封** |

`OrderedDict` 那一行值得单独说：**Python 3.7 起普通 `dict` 本身就保持插入序**，
封 `OrderedDict` 而放行 `dict` 是做样子——真要守那一节课，该封的是 `dict`。
名单里放一个封了也没用的名字，比不封更坏，因为它让名单看起来比实际严。

**封整个模块的代价也记下来**：第 7 章图算法的 Python 版一上来就得为 `defaultdict`
写豁免。豁免写多了，名单就从判据退化成手续——每个人都学会了「先写一句理由再照旧」。

**位置敏感与否要分开**。`deque`/`Counter` 出现即算（`from collections import deque`、
`collections.deque`、`alias = deque` 三种写法都要拦）；`sort` 只在**被调用时**算——
形参或局部变量叫 `sort` 完全正当，违规的是 `values.sort()`。

**顺带发现一个更大的洞，一并堵上**：`dict` 与 `set` 确实会删掉第 10 章的课
（算法10.9–10.12 闭散列表、代码10.4 与算法10.5–10.7 集合），但它们是内建名、
在别处又是不可替代的管道，**全局封不现实**。所以给单元一个自己加码的口子：
`unit.json` 的 `d025_forbidden` 列出「**本单元**因为讲这一节而额外禁用的名字」，
同样必须写理由。第 10 章做 Python 版（T-043）时用它。

> 这一条是本决策的一次**收紧方向的细化**，不推翻 §2 的任何结论：
> 判据仍然是「一行删掉一整章的调用不许出现在实现里」，变的只是名单的粒度。

## D-024 · 2026-08-18 · Claude 记录：分配存储 ≠ 构造对象（`ArrayStack` 工程版换存储层，T-004）

**背景**：D-001 第 2 条说「存储管理**本身**就是 ch3 这一节的课，所以用裸指针 + 显式五法则，
不用 `unique_ptr`」。但实现一直停在 `new T[capacity]`——那一行把「申请存储」和
「构造对象」捆在一起，于是这一节其实**只讲了一半**。T-004 从 2026-08-12 起就挂在 Backlog。

**先量再改**（数字全部可复跑，命令与输出在 `code/ch03/array_stack/legacy.md` 缺陷 12/13）：

| | `new T[n]` | 裸存储 + placement new |
| --- | --- | --- |
| 预留容量 1000、一次 push 都没有 | 构造 **1000** 个对象 | **0** 个 |
| `T` 必须可默认构造 | **是**（static_assert 拦下） | 否 |
| 满栈 1000 时活着的元素 | **1024**（含 24 个没用过的空槽） | 1000 |
| `clear()` 之后仍活着 | **1024** 个、占 200 KB | **0** |
| 再 push 3 个之后的死元素 | **1021** 个 | 0 |

**决定**：`modern.hpp`（工程版）把存储层拆成四件事——分配存储 / 构造对象 / 析构对象 /
归还存储。`teaching.hpp`（教学版）**保持 `new T[n]` 不变**：3.1.2 要讲的是
「顺序栈就是一块连续数组」，一行拿到数组正是它该有的样子。两版的差别写进 3.1.2a，
这正是 D-012 教学版分层的用途。

**这次改动新引入一份义务，写在明处**（legacy.md 缺陷 14）：`new T[n]` 替你保证元素对齐，
`::operator new(bytes)` 不管。所以 `allocate()` 必须显式传 `std::align_val_t{alignof(T)}`。
去掉那个参数，`alignas(64)` 的元素当场越界（ASan heap-buffer-overflow；`-O2` 直接段错误）。
**裸存储换来的自由，对应的就是这份义务**——这句话本身就是这一节的教学点。

**一道挂了六天的旧题因此消失**：2026-08-12 的交接里挂着一个疑问——
「`std::move_if_noexcept` 在**赋值**而非构造语境下是否还有意义」，当时只能手写
「看移动赋值抛不抛」的判据（D-005 / legacy.md 缺陷 11，红队 T-002 就是从那个缝打进来的）。
换成裸存储后搬迁执行的**就是移动构造**，`move_if_noexcept` 问的正是那个问题。
答案是：**它本来就只适用于构造语境，当时的容器用错了语境**——
根源不是工具选错，而是容器把对象构造和存储分配捆在了一起。

**测试基础设施跟着挪**：`support/fault_injection.hpp` 里 `Fragile` 打的是拷贝**赋值**，
而搬迁现在走拷贝**构造**，注入点不挪的话用例会**安静地不再触发**。新增三个探针：
`ThrowingCopyConstruction`、`ThrowingMoveConstruction`、`CountedConstruction`。
`AllocationFailure` 靠重载 `T::operator new[]`，对全局 `::operator new` 无效，
本单元改为在 test.cpp 里替换全局的对齐版 operator new（转调普通 `::operator new`
再自己对齐；两个替换标 `noinline`，避开 gcc 把标准语义套到合法替换上的误判——
**没有用 `#pragma` 关诊断**，关掉的是整条规则，不内联只挡这一处）。

**变异自检 6/6**：`clear` 退回只归零（ASan 报 1584 字节泄漏）、`pop` 不析构槽位、
`allocate` 丢掉对齐（heap-buffer-overflow / SIGSEGV）、搬迁改用无条件 `std::move`、
析构函数不析构元素（84 字节泄漏）、构造时把槽位全建出来——六种全部当场报红。
断言 62 → **74**。

## D-023 · 2026-08-18 · Claude 记录：课件覆盖只能显式登记，不能做成匹配器（新增 R16）

页标题在一章之内唯一（274 页、12 章，实测无重名），而且改标题时报红正是我们要的提醒。
这一条本身有自测守着（`test_slide_page_titles_are_unique_within_a_chapter`）。

## D-022 · 2026-08-18 · Claude 记录：点名本书接口，机器要能查得到（新增 R15）

**背景**：T-037 复查在一份 **10 步全绿**的书稿里手工抓出 4 个**根本不存在**的接口名：
`MinHeap::pop_min`（实为 `remove_min`）、`HuffmanTree::code`（实为 `code_of`）、
`DisjointSet::connected`（实为 `same`）、`WinnerTree::winner_value`（实为 `winner_index`）。
四个都长得像真的。R3 保证 ```cpp 块与 `code/` 逐字一致，**但散文里点名的接口不受任何约束**——
学生照着抄，编译器才告诉他这个名字不存在。

**决定**：新增 **R15**——书稿与 `legacy.md` 的**行内代码**里写成 `类名::成员`
（或 `命名空间::名字`）的限定名，必须解析到 `code/` 里真实的类成员/枚举值/命名空间成员。
`std::` 跳过；`test.cpp::某用例` 这种「文件::用例」写法按前面带 `.` 排除。

**成员从类体最外层取，不是「这个词在文件里出现过」。** 这条是变异自检逼出来的，
而且逼了两次：第一版按「词出现在声明该类的文件里」判，把 `HuffmanTree::code_of`
改回错误的 `HuffmanTree::code` **闸门没红**——`encode()` 体内有一行局部变量
`auto code = code_of(c);`。收紧到「声明该类的文件」不够，必须收紧到「该类类体的最外层」。
判据松一格，真缺陷就从那一格漏过去。

**配套一次性规范化**：附录里「实际接口是 …」这类断言句原本大量写裸名
（`使用 X 的 a、b、c`——顿号后面的接口共用前面的类名），四个缺陷全躲在这种写法里。
已把这些断言句改写成限定形式，R15 管辖的限定名从 38 处涨到 **96 处**。
以后书稿点名本书接口一律写限定形式。

**明确不做的那一半**，免得 R15 被当成比它更强的东西：

- **裸写的 `push`、`erase` 不在判据内。** 章节内部上下文已经点明了类，
  硬要求限定形式会让正文难读。
- **「反引号里的裸标识符必须在 `code/` 里出现过」这条实测过，否决了**：附录里 57 处命中，
  只有 1 处是真缺陷（`connected`），其余是题面字符串（`ABCDEFGHIJKL`、`cdac`、`arc`）、
  路径（`ref_DSA`）和伪变量（`S1`、`cur`、`row_ptr`）。**1:56 的信噪比是个假阳性机器**，
  和 2026-08-17 否决「正文小节→课件页匹配器」是同一条理由（见 `ARTIFACT-FRESHNESS` 追记）。

## D-001 · 2026-08-12 · 人已拍板：DSA 教材 C++ 现代化风格公约（T-006）

改造数据结构教材的核心矛盾：**全用 STL（如 `std::stack`）就失去了手写数据结构的
教学意义；全用旧 C++ 又会给学生灌输危险的内存习惯。** 以下四条为红线。

### 1. 语言标准：C++17

所有单元默认 `-std=c++17`。理由：GCC/Clang/MSVC 支持完善，且 `std::optional`、
`std::string_view` 足以支撑安全、无副作用的数据结构接口。

`unit.json` 的 `standard` 字段仍可按单元覆盖，但**偏离 C++17 要在 `legacy.md` 里
写明理由**，并在交接记录里点出来。

> **取代记录**：本条取代 2026-08-12 早些时候 Claude 提议的「C++20 + concept」。
> 原提议的动机是用 concept 替掉原书那个「非纯虚、非虚析构」的假抽象基类 `Stack<T>`；
> 在 C++17 下这一角色由 **`static_assert` + `<type_traits>`** 承担——同样是编译期检查、
> 同样不付虚表代价，报错信息也在实例化处，只是不能像 concept 那样参与重载决议。
> 落地见 `code/ch03/array_stack/modern.hpp` 顶部的三条 `static_assert`。

### 2. STL 使用边界（核心权衡）

- **禁用（教学核心）**：不得用 `std::vector` / `std::stack` / `std::list` / `std::map`
  等容器**直接替代**该章节要讲的手写实现。把 `ArrayStack` 做成 `std::stack` 的薄封装
  等于把这一节删掉。
- **允许（现代基础设施）**：
  - 类型与辅助：`std::size_t`（替换 `int` 表示长度/下标）、`std::swap`、
    `std::initializer_list`、`<type_traits>`、`<utility>`。
  - 接口返回值：推荐 `std::optional<T>`，替换原书「返回 `bool` + 出参」的双通道设计。
  - 内存管理：**演示手写指针/动态数组时，显式编写 Rule of Five**；
    不涉及指针教学的上下文，优先 `std::unique_ptr` 管理底层数组。

> **第 3 章顺序栈按前者办**：存储结构本身就是这一节的教学内容，所以用裸 `T* data_`
> 加显式五法则。这是有意的——用 `unique_ptr` 时五法则基本是仪式（编译器生成的就够用），
> 用裸指针它才是承重的，学生才看得见「为什么必须写这五个」。
> 代价一并明写：扩容要手写 `try/catch` 清理新缓冲区，而 RAII 版本不用。

### 2b. 智能指针的判据是结构形态（2026-08-14 补充条款，人已拍板）

§2 那条「演示手写指针时显式写五法则」曾被读成「这本书不用智能指针」。**不是。**
`code/ch11/bplus_tree` 与 `code/ch12/trie` 的孩子结点就是 `std::unique_ptr`。
判据是**结构形态**，不是个人偏好：

| 结构形态 | 该用什么 | 理由 |
| --- | --- | --- |
| 链（结点串成一条线） | 裸指针 + 迭代释放 | `unique_ptr` 的析构是递归的，深度正比于链长 |
| 树（孩子唯一所有权） | `unique_ptr` | 释放同样递归，但深度 $O(\log n)$ |
| 一整块缓冲区 | 裸 `T*` + 五法则 | 换 `unique_ptr<T[]>` 只省一句 `delete[]`，五法则并没有消失 |
| 共享（一个结点多个父） | 手写引用计数 | `unique_ptr` 语义上不成立；`shared_ptr` 会删掉 12.2 的教学点，且收不回环 |

**链那一行有实测支撑，不是审美判断。** 本机 8 MB 栈，`code/ch02/ownership` 的
`RecursiveChain`（`unique_ptr<Node> next`）：

| 构建档 | 最大安全结点数 | 崩溃于 |
| --- | --- | --- |
| `-O0 -g` | ≈ 57,625 | 58,601 |
| `-O2` | ≈ 523,329 | 524,306 |

同规模下迭代释放的 `IterativeChain` 在 `-O0` 跑到 500 万结点无恙。
**两档差九倍**是最关键的一点：debug 崩、release 过，递归深度由优化级别决定，
这种不确定性不该出现在教材实现里。

**这条决定同时定下写法**：判据表进书稿（2.3.2a 一节），复现命令与完整数字进
`code/ch02/ownership/legacy.md`。以后再有人问「为什么不全用智能指针」，
指这一节，不重新讨论。

### 3. 错误处理与 I/O（彻底清除 `cout`）

- **红线**：数据结构类内部**严禁**出现 `std::cout` / `std::cerr`。原书「溢出时
  `cout << "栈满溢出"`」这类写法必须彻底清除，由 `test.cpp` 重定向流并断言其为空来守住。
- **可预期的空状态**（`pop()` / `top()` 在空容器上）：返回 `std::optional<T>`，
  空时 `std::nullopt`。不是错误，不抛异常。
- **非法参数 / 越界 / 容量溢出**：抛标准异常——`std::out_of_range`（下标越界）、
  `std::overflow_error`（容量翻倍溢出）、`std::invalid_argument`（参数非法）。

### 3b. 只读访问：`optional` 与裸指针各司其职（2026-08-12 补充条款，人已拍板）

「读栈顶」这件事有两种正当需求，公约同时提供两个接口，**不要合并**：

| 接口 | 返回 | 用在什么时候 | 代价 |
| --- | --- | --- | --- |
| `std::optional<T> top() const` | **副本** | 要把值带走、存起来、跨越后续修改 | 拷贝一次；`T` 必须可拷贝 |
| `const T* peek() const noexcept` | **指针**，空栈为 `nullptr` | 只看一眼、零拷贝；move-only 元素唯一可用的观望方式 | **指针在下一次 push / pop / clear 后失效** |

写下这条的理由：`optional<T>` 的安全是靠拷贝换来的，对 `std::unique_ptr` 这类
move-only 元素直接不可用；而裸指针零拷贝，代价是生命周期由调用方负责。
两种代价都真实存在，**藏起任何一种都是把选择权从读者手里拿走**。
失效契约必须写进接口注释与书稿正文，不能靠使用者猜。

落地：`code/ch03/array_stack/modern.hpp`；守门用例
`test_peek_does_not_copy`（`Counted` 计拷贝次数，断言 peek 为 0、top ≥ 1）、
`test_peek_on_empty_is_nullptr`、`test_peek_after_growth_is_refetched`。

### 3c. 提取与按键删除的统一口径（2026-08-12 补充条款，人已拍板，T-010）

- `pop()`、`dequeue()` 等**提取**操作：返回 `std::optional<T>`。空容器是可预期状态，
  返回 `std::nullopt`，不抛异常。
- `remove(key)`、BST 删除等**按键删除**操作：返回 `bool`。删到键返回 `true`，键不存在
  返回 `false`；这是一项幂等、可预期的轻量级失败，不是逻辑错误。

这条取代此前「线性表按位置 remove 返回 T 并在越界时抛异常」被误解为通用删除口径的风险。
按**位置**访问/插入/删除的非法下标仍是 `std::out_of_range`；本条只统一提取和按键删除。
原因是 C++17 的 `optional` 直接表达预期缺失，避免教学代码充满与算法无关的 try/catch，
也不以 `assert` 或未定义行为处理空状态。

### 3d. 递归周游的教学边界（2026-08-12 补充条款，人已拍板）

二叉树的递归前序/中序/后序周游保留为主实现：递归结构正是该节要教的语义，不强制改为
显式栈。实现注释与 `legacy.md` 必须标明：极深或病态树的递归深度受进程调用栈限制，存在
栈溢出风险。漂亮的迭代版可作为补充，不能替换主教学实现。

**2026-08-12 人补充要求：把「没能跑 ASan」的风险点像写遗嘱一样交代清楚。**
落地为 `collab/UNVERIFIED-RISKS.md`，其中第一节给出实测数字（Linux/gcc 13.3/8MB 栈）：
递归析构与周游在 50 万深度通过、100 万 SIGSEGV；Debug+ASan 档周游 50 万即
stack-overflow。**关键在于出事时的可诊断性**——ASan 档会打印
`AddressSanitizer: stack-overflow` 加完整递归回溯并指到具体行号，

### 4. 命名与 API 风格

- 类名 `PascalCase`；函数与变量 `snake_case` 或 `camelCase`（单元内保持一致）；
  私有数据成员后缀下划线（`capacity_`、`data_`）。
- **彻底消除成员变量与成员函数重名**——原书 `int top` 与 `bool top(T&)` 的冲突

  `top()` 留给成员函数。
- 查询函数标 `[[nodiscard]]` 与 `noexcept`（当且仅当真的不抛）。

## D-005 · 2026-08-12 · 红队 T-002 结论：搬迁判据与容器对 `T` 的约束

**结论**：容器扩容搬迁元素时，判据必须落在**实际执行的操作**上，不是惯用法。
本项目的规则：移动赋值 `noexcept` → 移动；否则 → 拷贝。
由此产生一条对元素类型的真实约束，写成 `static_assert`：
不可拷贝赋值的 `T` 必须 `is_nothrow_move_assignable`。

**来由**：Codex 红队用「移动构造 noexcept、移动赋值抛」的类型打穿了第一版实现
（`std::move_if_noexcept` 看的是移动构造）。Claude 复核时发现第一版修复
「可拷贝就拷贝」过宽，`std::string` 这类元素被迫深拷贝，摊还 O(1) 打折。
两版的差别只有一条数拷贝次数的用例能分辨——**该用例已补，判据由它守着**。

**代价明写**：move-only 且移动赋值可抛的类型，本容器直接拒收（编译期）。
提供基本保证而非强保证是另一条路，本项目选了前者：教学容器的行为要好解释。

## D-010 · 2026-08-14 · Claude 记录：R3 的逃生口——```text 块

**背景**：`b87dc81` 那次重构把 `book/ch02-linear-list.md` 里两个
` ```cpp file=…#anchor ` 块改成了 ` ```text `。R3 只看 ` ```cpp ` 块，于是这两段从此不受
「印出来的字节 == 编译过的字节」这条契约管辖；同一个提交又重排了源码，书上那份没跟着变——

| 用途 | 例子 | R8 |
| --- | --- | --- |

### 2026-08-17 补充：反向的沉默是子串匹配自带的（Codex 复查提出）

上面「它拦不住什么」那一段说的是**同一提交内降级 + 改源码**。Codex 指出这不是个别情形，
而是判据形态的必然：R8 问的是「这段 text **是不是**逐字出自 `code/`」，
只要有一个字符不一样就不命中——而「书稿和源码漂开了」的定义恰恰是「不一样」。
**R8 结构上就只能拦住漂移发生前的那一刻，拦不住已经漂开的。**

**两条路，选后者**：

| 方案 | 判 | 为什么 |
| --- | --- | --- |
| 放宽成相似度阈值（编辑距离 / token 重合率） | 否 | 原书引文与本书实现本来就高度相似——原书那段正是本书这段的前身。阈值调到能命中漂移，就必然把大量合法的原书引文一起判红；调到不误报，就回到逐字匹配。噪声换不来覆盖 |
| 禁「长的、形似 C++ 函数」的 text 块 | **采纳** | 判据从「像不像我们的源码」换成「**长得像不像一段实现**」，与源码内容脱钩，也就不受漂移影响 |

**Codex 的处方**：` ```text ` 块若达到「函数定义」的形态（返回类型/名字 + 参数表 + 花括号函数体，
且超过现有的长度门槛），一律要求改成 ` ```cpp file=…#锚点 `；确实要引用原书那种编不过的
listing，走显式豁免标记，理由写在块上。这样漏网的路径只剩「有人主动打豁免标记」，
那是提交里看得见的一行，不是沉默。

**2026-08-18 已实施（T-026）**。豁免语法定为
` ```text original-listing="具体理由" `：理由为空或只写裸标记都报红。规则扫描书稿与
`code/**/legacy.md`；超过 60 个规范化字符、能解析出名字、参数表和花括号函数体的 text 块，
即使与当前源码已完全不同也会报红。普查基线只需豁免两处原书引文；编译器输出改标
`console`，`{ ... }` 省略号式语法讲解与只有控制语句的 trace 不算函数实现。

数据结构代码。……看不懂『工业级、工程级』的数据结构代码。」

### 问题不是代码写错了，是呈现的对象错了

对着 `book/ch03-stack.md` §3.1 与 `code/ch03/array_stack/modern.hpp` 逐条比对，
六条症状都指向同一件事——**书稿写的是给容器作者看的工程稿**：

1. **正文从来不完整地印一个类**。§3.1 只印 5 个锚点切片
   （`#class-head`/`#rule-of-five`/`#pop`/`#grow`/`#push`），读者拼不出一个能编译的文件。
2. **顺序反了**：3.1.2 的次序是「存储与所有权（五法则 + copy-and-swap）→ pop → 扩容
   → `move_if_noexcept` 陷阱 → push」。学生读到 `push` 之前已经啃了四页异常安全。
3. **工程细节印在教学代码块中间**：`#grow` 那 39 行里夹着
   `if constexpr (std::is_nothrow_move_assignable<T>)`、`try/catch`，
   以及 8 行解释红队 T-002 的注释。
4. **注解噪声**：`array_stack` 里 5 条 `static_assert`、13 处 `noexcept`、5 处 `[[nodiscard]]`。
5. **辅助函数的认知负担**：`top_index_`、`kInitialCapacity`、`check_index(index, who)`、
   `make_gap(pos)`、独立的 `swap()`。
6. **`demo.cpp` 从来没被编译过**。R3 只保证它和文件逐字一致，闸门里没有任何一步编译它
   （`grep demo tools/*.py` 只有一处无关命中）。教学版最依赖「抄下来就能跑」。

### 决定：加一层，不是删一层

每个容器单元增加 `teaching.hpp`——**完整、独立、能编译、书稿整块印出来**的最简实现。

| 维度 | `teaching.hpp`（正文主线） | `modern.hpp`（进阶选读） |
| --- | --- | --- |
| 印法 | 整个文件印出来，可直接抄走编译 | 仍按锚点切片印 |
| 资源管理 | **三法则**：析构 + 拷贝构造 + 拷贝赋值 | 五法则 + copy-and-swap |
| 扩容 | `new` → 拷贝循环 → `delete[]`，约 10 行 | `try/catch` + `if constexpr(is_nothrow_move_assignable)` |
| 注解 | 不写 `static_assert` / `[[nodiscard]]` / `noexcept` / `if constexpr` | 全套（D-001 §4 原样有效） |
| 命名空间 | 无（`ArrayStack<int> s;` 直接用） | `namespace dsa` |
| 空状态 | `std::optional`（**两版一致**，D-001 §3 红线不打折） | 同 |
| 容器内 I/O | **禁**（D-001 §3 红线不打折） | 同 |
| 用 STL 容器替代手写实现 | **禁**（D-001 §2 红线不打折） | 同 |

**「三法则 → 五法则」是这套分层的支点。** 教学版省掉移动构造与移动赋值，
代码**在正常路径上仍然正确**（退化成拷贝，只是慢），却一次砍掉了 copy-and-swap、
`std::move`、`noexcept` 三个概念。

> **2026-08-17 Codex 复查更正**：本条原文写的是「仍然完全正确」，**这句话太满**。
> 教学版的正确性边界是：**分配与 `T` 的拷贝都不抛异常**。一旦 `T` 的拷贝抛出，
> 几处手写裸指针的实现会漏内存——`ch03/array_stack` 扩容中的 `fresh`、

> 建到一半的子树。用一个「第 N 次拷贝必抛」的元素类型实测，
> LeakSanitizer 报 **88 字节 / 5 处分配**。
>
> **决定：保留教学实现，改口径。** 理由是补失败清理要在教学代码里加 `try/catch`，
> 而那恰恰是「进阶（选读）」要讲的强异常保证——提前塞进来就把分层的意义抵消了。
> 书稿前言与各章进阶节的开头已改成「在分配和 `T` 的拷贝都不抛异常时是正确的」，
> 并写明抛出时会漏在哪。**不再声称教学版普遍通过 ASan。**

**教学版不许照抄「网上那种教学版」。** 人给的样例里那个 `ArrayStack` 有析构函数却没有

## D-015 · 2026-08-17 · Codex 定案：算法6.10 拒绝不自洽序列，**不为标准答案放宽**

**背景**：修完 P0 之后，`from_dual_tag` 拒绝的输入比原书多三类——空栈取顶、
末结点声称有孩子、末结点声称有兄弟。原书对这三类都是未定义行为，所以「拒绝」本身
不构成与原书分歧；我交出去的问题是另一个：**万一课程习题的标准答案里正好有这样的序列呢**，
那时该放宽实现去迁就答案吗。

**Codex 的裁定：不放宽。** 四条依据：

1. 课程课件的定义就是 `ltag == 1` 表示无孩子、`rtag == 1` 表示无兄弟；
2. 先根序列的最后一个结点后面已无结点，故**必然** `ltag == 1 且 rtag == 1`；
3. 课程配套源码处理末结点时直接把 `child`、`sibling` 置空，**根本不读末结点的标志位**——
   也就是说它对末结点标记的取值不设防，不能反过来当作「这些取值合法」的证据；
4. 扫描过程中「有兄弟」入栈与「子树结束」出栈必须一一配对，空栈出栈说明序列违反了
   这个结构关系。

结论：这三类输入**不对应任何完整森林的编码**，不是合法边界。若标准答案里出现其一，
应判为标记笔误或序列截断，而不是让实现把它合法化。抛 `std::invalid_argument`
比原书的未定义行为更准确。

**为什么值得立一条**：这类「实现比原书严」的地方，最容易在下一轮被人以「跟标准答案对不上」
为由放宽，而放宽的代价是把一个能当场指出输入错误的检查换成一棵默默建错的树。
判据和依据写在这里，下次要动它得先推翻这四条。

书稿 6.3.2 已把依据 1、4 讲给读者（初学者常想「能修就修」），
证据链在 `code/ch06/general_tree/legacy.md` 缺陷 4。

和**机器判不了的**（数学本身对不对、图画的是不是那回事）。这个切法是对的，
本条把边界钉下来，免得下一轮又有人以为闸门在替他核对数学。

**为什么现在做**：修 P2（建堆 $O(n)$ 推导）时顺手发现，`book/ch12-advanced.md:33`
那个多维数组偏移公式**从写下来那天起就没渲染过**——它跨了三行，而渲染器只认
「同一行 `$$` 开头、同一行 `$$` 结尾」，于是整段以原始 LaTeX 印在页面上。
没人发现，因为**没人看渲染后的那一页**，而闸门当时不看公式。
同一次普查还查出 `\Bigl` / `\Bigr` 这类命令渲染器不认识，同样会漏成原始文本。

**决定**：新增 **R9**，两条判据，都只问「印出来是不是人能读的东西」：

1. `$$…$$` 必须在同一行内闭合——跨行的当场报红；
2. 公式里出现渲染器不认识的 LaTeX 命令，报红。第 2 条**直接向 `build_site.render_math`
   要词表**，而不是在 `check_doc.py` 里抄一份——两份词表迟早会各走各的，
   而一旦走开，检查器说「认识」、渲染器说「不认识」，红就报不出来了。

代码块里的 `$$`（命令行提示、伪代码）不算公式。`tests/test_check_doc.py::TestR9Formulas`
5 条自测，变异自检 3/3 全抓（关掉跨行检查 / 关掉未知命令 / 让代码块里的 `$$` 也算公式）。

**守不到的，写明**：R9 只证明公式**能渲染**，不证明它**是对的**。
建堆那个推导修之前也是渲染正常的——错在数学，不在排版。同理，图号存在不等于图画对了：
2026-08-16 那张图 1.4 三处画错，任何机器检查都不会响，是人对着「逻辑有序、物理无序」
的定义看出来的。**数学与图的正确性仍然是人工复核项**，这一点不打算用工具去糊。

## D-004 · 2026-08-12 · Claude 记录：闸门跑两种构建，缺一不可

把这个现象本身写成了断言）。只跑一种构建会漏。
